# ONE 按需编排、分步执行（2026-10-25）

## 目标和边界

同一个用户任务包含内部步骤：找资料 → 写成稿 → 保存 → 制作网页。调度模型在原有分派调用中提交计划，不额外购买一次规划调用；程序按真实成果推进，不在每一步之后再让调度模型判断一次。短回答和单一功能保留短路径。功能内部已有固定流程（含新手引导）、本机执行及其保护不被拆散。

这里的“一步”是有用的工作阶段，不是只能搜索一次、只能发一个 API 请求。资料不足可以明确提出补充/调整剩余计划；不能以少调用为由省掉必要检索或裁剪交付正文。第一版不引入新的工作流服务或另一个任务队列。

## 执行合同

- 调度计划只包含步骤、目标、依赖、已发现的功能/执行器编号。所属空间、用户、操作编号、模型配置、凭证和保存位置由服务端绑定。
- 执行前校验整份计划的工具、模型、功能发布版本、资料授权及保存位置；缺少必需能力时先沟通，不启动付费执行。
- 一个任务默认逐步执行；依赖真实输出而非“调用已发出”。已知失败只阻塞依赖步骤，独立安全步骤可以继续。
- 先持久化步骤开始，再执行；每次转换使用同一操作和版本的比较更新。重启/重复事件只能查原结果，不盲目重发模型或外部写入。
- Notion 写入及回读分开：延迟回读继续使用现有有限、只读核对；核对成功后恢复原任务的下一步，不重新生成正文、不重复保存。
- 用户补充仍沿用同一任务和已绑定页面。停止、撤权、未知外部写入和本机保护不是可忽略的暂停。

## 上下文

每一步只接收完整目标与约束、本步指令、显式依赖的真实成果、选中的历史以及本步工具。默认历史为零，确有需要才显式增加（最多 20 条）。稳定规则只有一份；不加载全部功能说明，也不把所有历史工具输出重复塞入模型。工具/知识内容作为参考资料，不变成系统指令。

正文和明确要求不静默截短。知识候选本地排序、严格去重时保留来源/日期/完整性，并明示未纳入内容；局部召回不变成查全证明。原始记录保留在现有任务检查点，不另建知识同步库。

## 兼容和上线

新调度模式接入可选 workflow 参数；可确定的检索/写作/保存串联可由服务端补齐保守计划。多功能顺序不明确必须由调度给出计划，不凭名称猜顺序。旧运行中任务不迁移或重跑，新计划不自动接管旧未知写入。前端只增加任务内可展开步骤，不增加逐步“开始”按钮。

## 验收（完成后补实测结果）

1. 合成真实交付链：检索 → 模型 → Notion 保存/回读 → 网页文件，核对步骤顺序、正文、文件和主对话汇报。
2. 延迟回读、重复事件、重启、用户补充、必要资料不足、独立步骤、停止/撤权、跨空间隔离。
3. 同组输入的旧/新对照：模型调用次数、工具次数、请求输入字节和真实成果；字节缩减不冒充实际费用比例。
4. 全量测试、TypeScript、生产构建、diff check；上线后核对版本、健康和独立合成任务。不得重跑原专栏/手艺人任务或修改价格余额。
