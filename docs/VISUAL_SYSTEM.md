# ONE 视觉系统 · 常驻工作台与注意力

## 核心概念

ONE 的主视觉不是一个静止图标，而是一个“在场的眼睛”：外部圆角方形代表 ONE 工作空间，白色眼形代表感知与连接，中间的 `1` 同时是竖瞳和品牌首要识别符号。

关键词：在场、注视、好奇、克制、可信、有一点猫科动物的机灵。

## 标志体系

- **标准标志**：正方形黑底、白色圆眼、黑色竖瞳。用于 favicon、登录、应用入口和正式品牌露出。
- **字标**：猫眼替代 `one` 中的 `o`，其余字母使用小写 `ne`。只在品牌名称和少量栏目名中替换，不机械替换正文中的所有字母 `o`，避免破坏可读性和辅助技术朗读。
- **竖瞳 `1`**：作为回答、步骤、章节和关键内容的起始符号。它应短促、明确，不能退化成普通装饰线。
- **小尺寸**：低于 20px 时减少细节，保留黑方、白眼、竖瞳三层关系；不增加阴影和描边。
- **安全区**：标志四周至少保留标志宽度的 1/4。禁止拉伸、旋转整个标志、改变瞳孔为圆点或在眼内放文字。

## 色彩与材质

- Ink `#24251F`：品牌黑、主按钮、正文。
- Paper `#F3F3ED`：页面暖白底色。
- Surface `#FDFDF9`：工作区与输入面。
- Line `#DDDFD4`：分隔与边界。
- Muted `#76786C`：辅助信息。
- 彩色只表达系统状态：绿色为已连接，黄色为等待或警告，红色为失败或撤销。品牌本身保持黑白。
- 表面使用轻微暖灰和细边界，取消满屏纹理与大面积阴影；不使用高饱和蓝紫渐变作为品牌背景。

## 动效语言

当前实现采用 React + SVG + CSS，首页与常驻助手共用 `OneCompanionEye`。视线和眼皮由轻量的临界阻尼弹簧更新，不引入动画运行时；休息时停止逐帧计算，并尊重 `prefers-reduced-motion`。

| 交互 | 眼形 | 视线与节奏 | 使用场景 |
| --- | --- | --- | --- |
| 静候 | 自然全开、接近标准圆眼 | 偶尔向一侧看，停留后回中；不规则眨眼 | 首页与常驻助手 |
| 指针靠近 | 保留饱满眼白 | 只在附近小幅注视，平滑减速；远离后回中 | 精细鼠标指针 |
| 悬停或键盘聚焦 | 下眼缘略微上扬，显得亲近 | 眼皮柔和变化，竖瞳保持原形 | 与 ONE 打招呼 |
| 点击或键盘激活 | 一次慢眨眼后自然睁开 | 约 730ms 的温和回应，不反复急眨 | 轻量互动 |
| 思考、好奇、完成或异常 | 在近全开基础上轻微调整开合 | 不用夸张变形、僵硬往返或怒视表达业务状态 | 实际任务状态反馈 |

“活感”来自注视、停顿与回应，而不是持续运动。黑色圆角外框不自动漂浮；中间略带弧度的竖瞳沿用原标志路径，只小幅平移，不拉长、挤压或改成其他形状。眨眼通过眼白开合与裁切实现，不能把竖瞳也压扁。默认不再使用 A2 半眯眼，也不把 A3 扁眼作为持续思考姿态。

自主侧看约每 3.4–7.6 秒尝试一次，观察后停留约 0.95–1.7 秒再回中；遇到用户正在互动时让出注意力。普通眨眼间隔约 4.8–8.6 秒。附近指针的注视范围有限，使用临界阻尼减速，避免随整屏鼠标机械摇摆。鼠标悬停与键盘聚焦采用同一套友好眼皮反馈；触屏不模拟鼠标追踪，点击仍可回应。

后台标签页暂停自主动作与逐帧更新。开启“减少动态效果”时关闭自动眨眼、扫视和弹簧动画，保留静态的聚焦与点击反馈。异常的主要说明来自清楚的文字和可执行操作，不让猫眼看起来在责备用户。

### 接管态

自动化不是一个独立页面，而是当前工作台的第二种状态。用户点击闪电后，页面布局、消息位置和滚动上下文保持不变，仅以点击点为圆心扩散至黑底白字；执行结束时从开始位置恢复明亮态，手动停止则从停止按钮位置恢复。不支持 View Transition 或开启“减少动态效果”时，退化为即时主题切换。

执行状态在当前事情内使用独立、默认折叠的进度条目：标题与最新进度先出现，停止入口在运行时始终可用。展开才显示当前步骤、结果与过程记录，不再在每条消息下面重复铺开执行卡片。继续执行时优先展示本轮进度，不能把保留的上次结果当作本轮已经完成。点击任务动态或提醒时，应打开被点选的准确执行任务；历史任务不能被同会话中较新的任务悄悄替代。

### 连续工作台

采用“常驻 ONE + 当前事情 + 任务动态”的连续工作台。首页的 ONE 和输入区在首次发送时移至右侧，之后不会再退回传统全屏聊天。左侧承载消息、结果、知识来源、设置及管理；右侧始终保留助手与输入口。手机采用上方结果、下方紧凑助手的纵向结构。

输入口明确显示“继续聊 · 事情名称”或“新事情”。交代新事情不必关闭眼前的结果，各任务的未发送文字与附件独立保留；异步上传和失败恢复必须回到原任务，不能污染当前草稿。独立聊天可同时等待回复，后台完成不会抢走正在查看的事情。全局任务动态使用现有、工作区隔离的执行接口和事件流，导航时不会丢失本机执行状态。

执行期间，普通发送仍然是聊天，不会悄悄改写正在执行的指令。只有任务停止后，显式选择“继续操作电脑”才把补充内容送到执行接口。当前客户端在已知有本机任务运行时禁用其他闪电，保持单项执行体验；这不是跨浏览器/设备的服务端调度锁，不宣称已实现全局排队。

页面使用暖纸色与细边界，收起背景纹理、玻璃浮层和巨大数据卡片。登录、知识、设置和管理共享字号、间距、控件和反色变量。辅助页面按左侧实际容器宽度重排，不使用整屏宽度来猜测表单列数。

### 一次关注一件事

前景只强调当前事情：紧凑标题、明确的活动标记、最近一轮的用户输入与 ONE 回复。之前的对话保留在可展开的历史中，不删除内容，也不把整段旧信息持续铺满屏幕。执行进度另行折叠，用户可以按需要展开、收起，或放大当前事情；放大不是离开助手，输入口仍保留。

手机展开任务列表时，暂时收起助手头像、旁白和重复回执，把有限空间留给任务选择和发送区；选择后恢复。任务列表内部滚动，不把全部历史摊开，也不将发送按钮挤出屏幕。

其他事情收进任务动态，默认只显示“另外几件正在进行”与小型未读计数。展开后按“进行中”和“结果与最近”分组，每个会话只出现一行，活动状态优先于旧结果。微弱脉动与文字共同标记正在工作，颜色不承担唯一含义。打开某件事时使用短促的进入与展开动效，把注意力引到被选内容，不启动另一个抢眼的全屏动画。

新回复、完成、失败与停止通过一条小型回执提示，最多显示约 8 秒；有多项更新时保留任务动态中的未读标记，不叠满提示卡片。结果到达不切换当前事情、不抢输入焦点。初次加载历史记录保持安静，不能把过去已经完成的任务重新当成刚刚完成。后台标签页不自动标记已读，打开对应事情或主动处理提醒后再消除未读。此处是当前页面会话内的 UI 提醒，不代表跨设备、持久化通知中心或操作系统主动通知能力。

生成反馈由猫眼、任务活动标记和俏皮的颜文字旁白共同承担。颜文字 Loading 是品牌特色，不能因为追求“高级感”删除。画面克制，口吻认真、可爱、有一点小心思；幽默表达脑内旁白，不虚构检索成功、完成比例或即将完成。每条停留 7.2 秒，后台标签页暂停换词，回到新一轮等待时从第一条开始。需要处理错误、确认或停止时，优先给出清楚准确的操作信息。

首页收起巨大用户名标题、重复的品牌口号、英文编号和厚重提示卡。主视觉以猫眼引导到一句“我在，慢慢说。”，输入框是唯一主要操作面，三个示例使用轻量文字入口；手机上三个入口全部可见。键盘快捷键从输入提示里移到桌面辅助行，减少输入区的信息噪音。

### 后续动画载体

- **CSS/SVG（当前首选）**：适合导航、回答标记、按钮反馈和简单情绪，维护成本最低。
- **Rive（第二阶段首选）**：适合需要状态机、鼠标追踪、情绪混合和更夸张角色表演的首页大眼睛。设计文件可由 UI 状态直接驱动。
- **Lottie**：适合你提供的定稿片段或一次性过场；不适合连续注视和实时状态切换。
- **视频/GIF**：不作为产品 UI 主实现，仅用于品牌传播或无法实时交互的展示位。

## 产品落点

1. 顶部品牌入口：猫眼替换字母 `o`，保持常驻的低频眨眼。
2. 首页：大号猫眼以近圆形全开眼白承担“在场感”，自主侧看后停顿，附近指针触发小幅注视，悬停轻微上扬眼皮，点击温和慢眨；竖瞳原形保持不变。
3. AI 回答：使用轻量 ONE 作者标记，猫眼集中在常驻助手和执行反馈中，避免页面反复堆叠 Logo。
4. 登录、favicon 与 ONE Key macOS App：使用标准标志，形成从浏览器标签、桌面图标到应用内的一致识别。
5. 成功与错误反馈：优先改变眼形和动作，再辅以状态色；不靠更换完全不同的图标表达。
6. 空状态、授权等待、搜索中、任务完成：复用同一个角色组件的状态，而不是散落不同插画。
7. 首页快捷入口：保留中文意图和轻量方向箭头，以留白和细分隔线组织，避免重复放置猫眼、通用图标与英文编号。
8. 本机执行：闪电代表把任务交给 ONE；全页反色表达执行状态，当前事情内的折叠进度条目与活动标记说明它仍在同一上下文中工作，不重复堆放猫眼卡片。
9. 首次发送：输入区与 ONE 在原页面内重新组织空间并永久保留，不使用定时过场、空白等待页或生硬路由跳转。
10. 多件事情：前景保留一个，其他事项以可折叠列表和小型提醒出现；完成不抢焦点，点选才展开结果。

## 下一轮建议

- 同一台电脑跨浏览器的资源互斥、排队、持久化或系统级主动提醒属于后续调度能力，需要单独设计服务端状态，不能用当前页面的完成回执假装存在。
- 为知识连接流程加入“发现—注视—确认”的三段眼神反馈。
- 给发送按钮加入按下时的瞳孔收缩，以及生成完成时的 pleased 回弹。
- 只有需要更复杂的角色表演时再评估 Rive；目前的矢量注视、眼皮变化和点击回应已由代码实现，不为替换载体增加动作噪音。
- 补齐深色模式反相规范、营销图形和社交头像安全区。
