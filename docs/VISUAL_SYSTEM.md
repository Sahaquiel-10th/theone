# ONE 视觉系统 V0.1

## 核心概念

ONE 的主视觉不是一个静止图标，而是一个“在场的眼睛”：外部圆角方形代表 ONE 工作空间，白色眼形代表感知与连接，中间的 `1` 同时是竖瞳和品牌首要识别符号。

关键词：在场、注视、好奇、克制、可信、有一点猫科动物的机灵。

## 标志体系

- **标准标志**：正方形黑底、白色圆眼、黑色竖瞳。用于 favicon、登录、应用入口和正式品牌露出。
- **字标**：猫眼替代 `one` 中的 `o`，其余字母使用小写 `ne`。只在品牌名称和少量栏目名中替换，不机械替换正文中的所有字母 `o`，避免破坏可读性和辅助技术朗读。
- **竖瞳 `1`**：作为回答、步骤、章节和关键内容的起始符号。它应短促、明确，不能退化成普通装饰线。
- **小尺寸**：低于 20px 时减少细节，保留黑方、白眼、竖瞳三层关系；不增加阴影和描边。
- **安全区**：标志四周至少保留标志宽度的 1/4。禁止拉伸、旋转整个标志、改变瞳孔为圆点或在眼内放文字。

## 色彩与材质

- Ink `#171714`：品牌黑、主按钮、竖瞳。
- Paper `#F5F3EE`：页面暖白底色。
- Surface `#FFFEFA`：卡片与输入面。
- Line `#DEDBD3`：分隔与边界。
- Muted `#807B72`：辅助信息。
- 彩色只表达系统状态：绿色为已连接，黄色为等待或警告，红色为失败或撤销。品牌本身保持黑白。
- 表面使用轻微暖灰、纸张颗粒和柔和漫反射阴影；不使用高饱和蓝紫渐变作为品牌背景。

## 动效语言

当前实现采用 React + CSS：无额外运行时、矢量清晰、加载成本低，并自动尊重 `prefers-reduced-motion`。

| 状态 | 眼形 | 瞳孔 | 使用场景 |
| --- | --- | --- | --- |
| idle | 自然全开，偶发双眨 | 缓慢扫视后回中 | 首页、品牌入口 |
| attentive | 轻微收窄 | 更快地寻找并注视 | 回答标记、悬停 |
| thinking | 上眼皮压低 | 左右往返 | 检索、生成中 |
| pleased | 下缘上扬、眼形变弯 | 居中 | 成功、任务完成 |
| cozy | 上下眼皮包住眼白，舒服地眯眼 | 慢速侧看 | 首页静候、放松状态 |
| curious | 眼形轻微歪斜 | 先侧看再回中 | 用户正在输入、发现线索 |
| surprised | 眼白明显放大 | 瞳孔拉长并居中 | 新发现、意外结果 |
| angry | 上眼皮向中心下凹 | 短促左右压迫式扫视 | 明确失败或阻断，不用于责备用户 |

动效遵循“预备—动作—停顿”的角色动画节奏。标志本体不自动漂浮；常态保持 A2 舒服睁眼，以不规则扫视和眨眼为主。首页大眼睛悬停时不再改变眼形，只让竖瞳小幅、克制地跟随指针；点击触发一次短促眨眼。A3 用于思考，A5 只用于真正的错误或阻断状态，避免为了有趣而牺牲标志本身的美感。

### 接管态

自动化不是一个独立页面，而是当前对话的第二种状态。用户点击闪电后，页面布局、消息位置和滚动上下文全部保持不变，仅以点击点为圆心扩散至黑底白字；执行结束时从开始位置恢复明亮态，手动停止则从停止按钮位置恢复。执行过程贴在原消息下方自然生长，默认只显示对用户有意义的步骤，技术上下文收进“执行细节”。不支持 View Transition 或开启“减少动态效果”时，退化为即时主题切换。

### 连续工作台

首条消息发送后不立即切换成传统聊天页。输入内容先留在左侧成为任务卡，ONE 在右侧醒来并进入 thinking；随后任务卡、助理状态和输入框通过共享元素过渡收拢进正式对话。生成中的反馈继续由同一只眼睛承担，避免通用 loading、表情字符和技术状态文案打断角色感。移动端保持相同叙事，但改为“助理在上、任务在下”的单列结构。页面入口切换只使用短促的位移与淡入，大幅动效仍只留给接管态。

### 后续动画载体

- **CSS/SVG（当前首选）**：适合导航、回答标记、按钮反馈和简单情绪，维护成本最低。
- **Rive（第二阶段首选）**：适合需要状态机、鼠标追踪、情绪混合和更夸张角色表演的首页大眼睛。设计文件可由 UI 状态直接驱动。
- **Lottie**：适合你提供的定稿片段或一次性过场；不适合连续注视和实时状态切换。
- **视频/GIF**：不作为产品 UI 主实现，仅用于品牌传播或无法实时交互的展示位。

## 产品落点

1. 顶部品牌入口：猫眼替换字母 `o`，保持常驻的低频眨眼。
2. 首页：大号猫眼承担产品“在场感”，空闲使用 A2 扫视，悬停由竖瞳追随指针，点击快速眨眼，生成时进入 thinking。
3. AI 回答：每条回答以小猫眼/竖瞳起头，建立“这是 ONE 的声音”。
4. 登录、favicon 与 ONE Key macOS App：使用标准标志，形成从浏览器标签、桌面图标到应用内的一致识别。
5. 成功与错误反馈：优先改变眼形和动作，再辅以状态色；不靠更换完全不同的图标表达。
6. 空状态、授权等待、搜索中、任务完成：复用同一个角色组件的状态，而不是散落不同插画。
7. 首页快捷入口：不重复放置猫眼或通用线性图标，采用编号、英文动作词、中文意图和方向箭头组成编辑式入口，让品牌通过版式而不是图标堆叠建立识别。
8. 本机执行：闪电代表把任务交给 ONE；全页反色代表 ONE 已接管，原消息下方的猫眼和进度流代表它仍在同一上下文中工作。
9. 首次发送：输入区与 ONE 在原页面内重新组织空间；至少展示一次明确的“接住任务”反馈，再进入对话，不使用空白等待页或生硬路由跳转。

## 下一轮建议

- 为知识连接流程加入“发现—注视—确认”的三段眼神反馈。
- 给发送按钮加入按下时的瞳孔收缩，以及生成完成时的 pleased 回弹。
- 用 Rive 做首页 hero 的高表现力版本：视线跟随指针、上下眼皮独立控制、惊讶/困惑/开心的状态混合。
- 补齐深色模式反相规范、营销图形和社交头像安全区。
