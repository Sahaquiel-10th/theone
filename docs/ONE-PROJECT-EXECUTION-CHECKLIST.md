# ONE 开发与内测执行清单

> 更新：2026-09-14。生产 MVP 基线已存在；本轮内测修复仍是本地待发布版本，**尚未推送、部署或更新 U 盘**。
> 唯一首版目标：ONE Key 登录 → 一次授权个人知识来源 → 实时召回 → AI 上下文问答。
> 本文取代早期把“未激活认领码、短信/微信、受信任电脑”列为当前流程的清单。详细交付与验收见 [三人内测交付清单](ONE-BETA-READINESS.md)。

## 1. 不变的产品结论

- ONE 是跟随用户的个人 AI 工作入口，不是围绕某一家知识平台的笔记编辑器。
- 得到大脑是首个 Knowledge Connector；当前也保留已批准的 Notion 官方 MCP 只读连接。新增其他平台另行确认。
- V0.1 按需召回，不全量同步第三方笔记，不建设 ONE 自有知识库、向量库或自动记忆。
- 用户没有知识平台账号或会员时由运营人工协助；授权由用户在官方页面完成，不共享客户账号、不要求用户复制开发者 Key。
- 模型采购 Key 由运营配置，采购成本与每用户零售电力账本分开；普通用户默认直接问答，模型选择收在设置中。
- 首批内测人工开户、预绑定 Key。手机号/微信认领、未激活认领码及受信任电脑免 Key 模式不阻塞本轮。
- 当前严格模式要求 Key 在正在使用的电脑上。页面可保留已显示内容，新的私人读取、知识调用、耗电行为和管理操作必须先证明 Key 在场。

## 2. 内测标准旅程

1. 超管人工创建独立普通账号、Workspace 和电力账户，赠送明确体验额度。
2. 为该用户签发独立序列号和凭证，灌装 Mac/Windows 入口；外壳标签对应账号与序列号。不得把超管凭证复制给朋友。
3. 用户在一台电脑首次插 Key、双击对应入口；启动器完成绑定当前电脑安装身份的登录，浏览器进入自己的账号。
4. 首次引导填写称呼，连接知识来源或选择暂时跳过；进度跟随账号，称呼以后可在设置修改。
5. 已连接用户提出个人资料特有的问题，ONE 实时召回、回答，显示命中/未命中/未连接/部分失败/失败及可展开来源。
6. 附件可在同一对话后续追问中继续作为上下文；超出数量或文本预算时明确提示，不承诺完整文档都进入模型。
7. 拔 Key 后新请求在召回、模型和电力预占之前被拒绝；同一电脑重新插入或休眠恢复后，驻留程序恢复连接，原页面可继续请求。电脑重启后仍需双击一次。
8. 同一枚 Key 移至电脑 B 后，电脑 A 的旧页面必须仍被拒绝；B 的在线状态不能替 A 解锁。移回 A 后再验证恢复。
9. 网络响应丢失先查原提交结果；不能因重复点击、重新插 Key 或刷新产生重复回答和扣费。同一对话另有消息处理时提示等待。
10. 超管按用户展开用量、使用时间和有效使用情况；只查看用户明确同意分享的反馈说明，不查看他人的对话和知识原文。

其中第 7、8 项是本轮发布阻断项，Mac 和 Windows 都必须实机验证，不能只凭构建或协议模拟通过。

## 5. 接下来严格按此顺序

1. 完成本地收尾验证，冻结一个明确发布版本；准备两个系统的新启动器和升级说明。
2. 安排维护窗口、暂停新的内测发送，检查现有数据库备份并核对未决模型用量。
3. 从已核对的本轮版本更新服务器 `/usr/local/sbin/theone-deploy`。Git 更新仓库本身不会更新该已安装脚本；未更新前，新只读迁移门禁并不生效。
4. 数据库管理员应用 `002`，运行 `deploy/check-mysql-schema.mjs`。门禁只读，不自动迁移、不改业务状态、不开放 DDL 权限。
5. 发布服务端/Web，再更新 Key 启动器并首次重新登录。老启动器不能只靠刷新网页兼容；这次是协调升级，不是无感滚动兼容发布。
6. 先超管两机验收关键安全路径，再逐个交付普通用户 Key，完成 3 人独立资料/账单隔离测试。
7. 看每人是否完成真实任务、是否跨日回来、用了多少电力和明确分享的反馈，再决定下一轮；不凭 Token 数量断言产品替代成功。

发布和回滚细则以交付清单为准。回滚保留追加表和真实业务数据，不 DROP 表、不拿旧备份覆盖线上新数据；回滚期间暂停内测提交并核对未决账目。

## 6. 本轮不做与长期任务

- 新 Codex 接口、Mac/Windows Local Agent 能力统一、完整命令沙箱：暂缓；已有路径的权限漏洞仍须修复。
- 附件原件与密钥完整异地备份、恢复演练和主动告警：暂缓，不误称已有数据库备份能完整恢复产品。
- 未激活批量认领码、短信/微信登录、首次设备端生成密钥、用户自定义 Key 名称、受信任电脑免 Key：后续产品任务。
- Developer ID、公证和 Windows Authenticode：发行任务，不是接入 Claude Code；扩大分发前单独完成并实测系统安全提示。
- 在线支付自动入账、复杂财务/运维平台：后续；本轮保留充值申请和人工处理。
- 全量知识同步、私有 COS 附件存储、ONE 自有知识副本：V2；Source/Memory/View、观点演化与“人不操作文档”：更后续。
- 多进程/多机器部署：先实现数据库级原子扣款、锁与短期协议共享状态，再谈横向扩容。现在保持 ONE 单应用进程。

## 7. 不可突破的红线

- 不共享第三方账号模拟多租户，不让 Provider 失败跨 Workspace 兜底。
- 不把模型/知识凭据返回浏览器、写入 URL 或日志；USB 只存设备原型凭证。
- 不把普通 U 盘安装身份和文件私钥宣传为不可复制硬件认证。
- 没有当前电脑 Key，不读取新私人内容，不召回知识，不发起耗电或管理操作。
- 不展示其他用户私人对话/附件/知识原文给超管；用户自愿分享的反馈不扩展成默认内容审计。
- 新数据路径必须有用户/Workspace 隔离测试，数据库迁移只追加。
- 不改变中转站或同服务器其他项目来实现 ONE 的功能。
