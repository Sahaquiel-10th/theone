# 缓存用量与计费核实

## 核实依据

2026-09-19 只读检查本机 `s-中转站` 项目：`src/billing.js` 的 `normalizeUsage` 读取缓存读取、写入总量、5 分钟写入、1 小时写入；`src/proxy.js` 将这些字段保存到 usage_logs，并在非流式响应中返回上游 payload。没有修改中转站代码、配置或账单。

这确认了代码支持及透传路径，不代表所有供应商、所有调用都有非零缓存，也没有把模拟测试当成生产账单。ONE 旧版仅保留输入输出，无法从旧 ONE 账单恢复已丢弃的缓存明细；历史纠错须以中转站原账单另行对账，不自动追扣或退款。

## 计费口径

- OpenAI 的 prompt_tokens（以及带 input_tokens_details 的 input_tokens）包含缓存读取，先减去 cached_tokens 得到普通输入。
- Anthropic 的 input_tokens 为普通输入，cache_read_input_tokens 与 cache_creation_input_tokens 独立。全部输入 = 普通输入 + 缓存读取 + 缓存写入。
- 写入总量包含 5 分钟和 1 小时明细。费用 = 普通输入价 × 普通输入 + 输出价 × 输出 + 读取价 × 读取 + 基础写入价 ×（写入总量 − 1 小时写入）+ 1 小时价 × 1 小时写入，再统一换算微电力。
- 仅报告写入总量而不分有效期的部分按后台明确标注的基础写入价收费，不推断为 1 小时。不主动改变请求缓存设置或承诺命中缓存。
- OpenAI 形状中混入非零缓存写入时语义不明确，进入待核对，不猜测重复扣除。非法、冲突、负数、总量不一致的缓存字段不用于结算。
- 缓存读取通常较便宜；缓存写入可以高于普通输入。5 分钟与 1 小时分别配置，不能把缓存一律理解为折扣输入。

## 价格与账单

超管在原定价弹窗展开「缓存读取与写入价格」，启用后分别填写官方价与实际采购价的读取、基础写入、1 小时写入单价（美元 / 百万 Token）。官方价乘用户消费倍率，采购价保持独立。发布版本、生效时间、通知沿用现有流程。

新调用保存 cacheUsage、用户缓存价格快照与采购缓存价格快照。用户只看自己的用量及零售价，采购快照只供超管。账单、当前价格、价格通知展示缓存分项，原来的输入字段在新缓存账单中明确表示「普通输入」。

预占采用普通输入和缓存输入价格中最高的价格作为输入上界。真实结算按独立分项计算，实扣不超过预占，差额仍依原机制记录。

有缓存用量但没有缓存价格快照时保留待核对及预占，禁止回退普通输入价；超管先免扣释放旧调用，再为后续调用发布正确价格。发布新价不能改写旧调用的快照。

未改变已有余额和历史结算，不需数据库迁移或更新 U 盘。上线后须为实际支持缓存的在用模型发布缓存价格，不能把某张官方截图的单价套给所有模型。

## 验证

测试覆盖 OpenAI 包含式缓存、Anthropic 独立缓存、混合 5 分钟/1 小时、仅写入总量、非法用量、快照锁定、重复结算、跨账号/空间拒绝、缺价待核对、预约生效及采购成本不公开。
