# 对话附件升级计划

## 目标与边界

- 每条消息最多添加 5 个附件，单文件最高 200 MiB；图片另设模型输入保护上限。
- 附件仅属于上传者及当前对话。换电脑继续使用同一账号时可以读取，不进入跨对话知识库。
- 分片落盘，单进程排队解析，记录解析状态。失败明确告知，允许重试。
- 保存完整可解析文字到私有文件，数据库只存元数据，不再静默截断前 3 万字符。
- 定向问题检索相关片段；全文任务分段处理并按实际模型调用计费。不能把抽样结果说成全文结论或表格精确汇总。
- 所有模型调用保持 ONE Key 校验、用量记录和工作区隔离。

## 实施顺序

1. 分片上传与磁盘容量、并发、孤儿文件保护。
2. 解析进程、全文文件、状态查询与重试。
3. 对话内检索与全文任务处理。
4. 上传进度、解析状态及错误提示。
5. 隔离、长文本、失败恢复测试，类型检查、构建与上线验证。

## 格式边界

首批保持 PDF、DOCX、PPTX、XLS/XLSX、CSV、TXT、Markdown、JSON 及现有图片格式。PDF/PPT 中图片里的文字不等于已解析文字；扫描件 OCR、旧版 DOC/PPT、音视频需要独立实现和验收，不以“支持附件”暗示支持全部内容。

## 已实现规则与配置

- 上传固定每片 4 MiB，浏览器顺序发送并更新百分比；失败先查询服务端进度再重试，不盲目追加。沿用现有 10 MiB Nginx 限制，无需修改其他站点。
- 每账号同时处理 5 个文件、原件总量 5 GiB；创建任务保留至少 2 GiB 磁盘余量，写分片至少保留 1 GiB。图片单张 20 MiB，每次模型输入图片合计 25 MiB。
- 解析全局串行，单独 Node 进程，V8 堆上限 256 MiB、最长 120 秒；这不是操作系统 RSS 硬配额，ONE 的 systemd 1 GiB 总上限仍然有效。复杂文件可能被拒绝并显示原因。
- Office 包最多 5000 项，总解压体积 512 MiB、XML 结构 60 MiB；可解析文本最多 1200 万字符。超过安全限额明确失败，不保存假装完整的截断结果。
- 私有原件旁保存 `.segments` 文件，每段 4000 字符；检索时携带前段末尾 128 字符以覆盖边界。MySQL 保存状态、计数和路径，不保存大段正文。
- 检索采用中英文关键词匹配，优先命中的文件名，默认注入预算 24000 字符（`ATTACHMENT_CONTEXT_CHARS`）。这是轻量对话检索，不是向量语义索引；未命中不能证明全文无相关内容。
- 明确总结任务在超过预算时遍历全文分段归纳，再归并摘要；单次全文总结上限 72 万解析字符，超出时请指定章节/问题分批处理。分段调用使用原模型、Key 校验和正式计费，用量标记 `attachment_summary`。发送 HTTP 202 后网页查询原操作，不自动重发模型调用。
- 精确全表计算尚未新增计算引擎；模型不能将检索样本或分段摘要冒充全表统计结果。
- 新上传文件完整保存解析文本。旧附件仍兼容原有已存文字，过去已截断的内容不会自动恢复，需要重新上传原件。
- 未完成上传 24 小时后清理；解析中任务随服务重启重新排队；删除附件/对话同时删除原件及分段文件。已完成但未发送的附件暂不自动清理，计入配额。
- 这次不改变 Launcher/Bridge，无需重灌 U 盘，旧网页刷新后使用新上传协议。

## 运维注意

原件和 `.segments` 位于 `UPLOAD_DIR`（生产默认 `/srv/theone/shared/data/uploads`），不可公开挂载为静态目录。数据库备份不包含文件内容，现有文件备份边界没有扩大。分段文件可由原件重新解析生成。后续迁移必须同时迁移数据库和私有原件。

## 验证

包含真实 HTTP 上传、Key 拔出拦截、跨账号状态/下载/写入/重试/删除拒绝、重启后附件追问、全文任务异步结果查询与逐次计费测试。另有尾部内容检索、完整文本恢复、错误重试、解析队列恢复、ZIP 膨胀保护测试。

大文件压力测试仅本地显式运行，避免每次生产部署占用额外资源：

```sh
ONE_ATTACHMENT_STRESS=1 node --import tsx --test server/attachmentPipeline.test.ts
```

已用 110 MiB 媒体型 PPTX 验证分片写入和独立解析进程；这不保证任意 200 MiB 的复杂表格、扫描 PDF 都可成功识别。
