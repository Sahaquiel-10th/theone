# ONE：桥梁式能力架构检查

## 产品目标

用户只说目标。ONE 负责在已授权范围里找合适能力、组合执行、保留成果、说明卡点及下一步。价值不在多摆模型/工具按钮，而在连接和交付可靠。平台接入、任务安排、具体执行、成果返回分别有自己的契约，不能用“已排队”“工具返回”代替用户目标完成。

## 本轮实现

1. 统一发现元数据：执行 AI 和官方功能可填写行业、场景、别名、不适用说明；保留已有用途和执行要求，配置发布后才影响新轮次。
2. 渐进式目录：首轮保留基础能力、显式选定功能和相关候选，后续通过只读 function 查找当前授权能力。分页、有界输入、稳定排序；行业是偏好而非硬分组，不查询知识正文、不产生功能执行费用。当前为本地关键词匹配，不声称实现了向量语义搜索。
3. 固定流程能力：个人使用说明登记为 version 1 的官方配方，从资料完成/设置重做事件调用。内部继续运行已验收的策划、插画、流程图与网页实现，共享原任务、预算与恢复机制；不引入额外的调度模型调用。配方在统一后台显示，不开放任意脚本流程编辑器。
4. 精确权限：每次目录查找重新从当前成员、发布和连接状态计算；执行时再次检查。描述、标签、MCP 工具自述和发现结果均不能授予权限。旧任务和已有付费请求不换合同；现有价格、免费次数、模型绑定和发布范围不自动修改。

## 对照现有项目后的取舍

| 关注点 | 项目已有机制 | 本轮处理/后续边界 |
|---|---|---|
| 找什么 | 执行 AI、内置能力、功能已有统一卡片 | 增加发现信息和只读发现 function；不是让模型猜函数编号 |
| 怎么做 | function calling、固定功能、代码工具、Connector | 灵活外层 + 确定内层共存，不要求每个固定步骤再调一次 AI |
| 怎样算完成 | 任务回执、附件、阶段检查、外部写入核验 | 保留真实结果判定；目录命中不代表供应商可用 |
| 失败怎么接着做 | 私有步骤检查点、完成成果复用、未知写入防重放 | 保留同一引擎，不为固定流程新建旁路重试系统 |
| 多件事怎么交付 | 独立任务并行、依赖、共享预算、安静回流 | 一张便签对应一个可交付目标，不对应每次工具调用 |

## 建议但本轮不实施

- **能力健康与质量反馈**：区分配置可用、授权可用、最近调用可用；聚合不含个人正文的成功率/等待时间。短期供应商故障可降级提示，但不能未经批准换价、换模型、扩大知识范围或重复购买。
- **更精细的候选召回评估**：用脱敏合成任务持续测试“找对能力、选对组合、实际拿到成果”。有明确漏召回证据后，再考虑语义索引；不先引入新数据库或多智能体框架。
- **模块拆分**：coordinatorService 已较大，后续按发现、计划、执行、回流边界逐步拆分。此次只新增独立发现和固定配方模块，避免把稳定的计费/停止/恢复链整体重写。
- **平台能力合同**：新 Connector 接入时分别声明搜索/读取/写入、输入输出、副作用、权限与验收；不能因为 MCP 有一个同名工具就自动开放。现有 Notion 写入继续走独立确认合同。
- **成果优先，不是工具优先**：Muse 的设计材料也把并行后台工作、按任务呈现的交互成果、值得打扰才通知，以及关键动作的明确确认作为独立产品问题。ONE 已有持续主对话、任务便签和私有图文成果，应该继续沿这些边界改进；不因此引入自动购物、全天候监控或主动扫描个人资料。本轮不改变现有通知约定。

## 一手参考

- [Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)：固定工作流与动态 agent 是可组合的两种模式，选择最简单能满足目标的方式；不为动态而动态。
- [Anthropic：Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)：大目录按需发现与加载，避免所有工具说明竞争上下文。本轮采用供应商无关的本地目录发现，不依赖某家 API 的专有 tool-search 支持。
- [MCP：Tool Annotations as Risk Vocabulary](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/)：注解是提示，不是授权；权限及风险判断必须在宿主端实施。
- [Muse：How We Designed Muse](https://introducing.muse.ai/)：持续对话、并行工作、成果界面和打扰控制需要一起设计；不要把内部工具列表当成面向用户的产品。

## 验证边界

自动验证覆盖大目录上下文收敛、关键词/行业/分类/分页、显式选择保留、跨空间和用户隔离、发布与撤销、真实发现后执行、功能按实际用量结算、固定流程版本与已完成阶段复用。真实页面验收及发布结果另记录，不以文档或配置显示替代。
