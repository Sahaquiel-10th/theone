# 2026-10-15 任务恢复和反馈路径

## 本轮范围

用户确认继续优化发送、处理、恢复、失败反馈和人工继续的完整路径。不是把上次真实任务失败归为纯界面问题，也不重做任务调度架构。不重放旧业务要求，不删除 QA 历史、文件或用量，不修改生产价格，不自动解除任何安全锁。

## 修复

- 计费待核对只保留该笔预占，不再锁住账号或企业付款人的全部后续调用。新调用仍经过身份、余额、企业限额、批次预算检查，不释放、不花用旧预占，不编造用量或补扣。
- 图片 Responses 路线与 Codex 网关仅对明确的 HTTP 429 拒绝自动重试两次，退避 2 秒、5 秒，尊重最长 30 秒的 Retry-After。超过范围则交给用户，不提前重试。网络断开、超时、5xx、已开始返回的流均不重放；这些情况可能已有调用或外部操作，不能用盲目重跑冒充恢复。
- 每次自动重试前重新检查任务授权和停止状态；本机进展记录 / 图片侧栏显示正在重试。不增加成功次数或重复结算。停止、Key 失效后不得继续发起重试。
- 图片错误保存白名单化类别和 HTTP 状态，不保存供应商原始报文、凭据、堆栈。对用户展示具体但简短的下一步；不再把图片服务错误说成本机目录未授权。
- 图片失败页提供确认后的“重新生成图片”，复用同一任务和其窄范围要求，新建单独执行和计费记录；并发重复点击最多受理一条。已有结果、历史和原失败记录保留。取消 / 未知结果不会被后台自动重启。
- 主对话按任务选最新反馈，不再把一个任务多轮 QA 的回执逐条拼成链接。旧轮次仍有历史和精确回执确认，晚到新结果留给下一轮。
- 已读和主动收起会让已结束便利贴退出侧栏，但不伪造“调度已汇报”，不停止活动任务，不吞未来轮次。收起保留任务和结果，任务列表仍可找回。
- 本机失败 / 取消任务给出查看本轮操作与核对后继续入口；继续只准备原任务范围的核对要求，不自动执行、不覆盖已有输入草稿。新用户引导仍不在本轮范围。
