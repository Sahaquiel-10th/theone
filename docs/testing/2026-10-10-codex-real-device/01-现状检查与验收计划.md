## 调用与连续性

ONE 将事情的相关对话和已保存交接整理成执行指令，经已验证 Key 的本机连接传给 Mac 驻留程序。后者运行 Codex CLI，不是自动点击 Codex 桌面应用。命令使用 JSON 事件输出和 workspace-write 模式，在已选择工作目录中启动。

统一网关路线按设备与执行任务生成独立 CODEX_HOME，使用 ONE 网关的本轮短期令牌，不使用个人 Codex 登录配置。因此不能把 ONE 任务自动出现在个人 Codex 侧边栏作为设计前提。

同一驻留进程、同一 execution task 在收到继续指令时可使用内存中的 thread ID 续接。重启后该内存映射消失，云端编号尚未回传恢复。另一个隐患是同一“事情”重新创建 execution task 时，未必复用旧 Codex 会话。同一事情、执行任务和 Codex 会话是三个不同的标识。

云端回执与本机文件可以提供恢复资料，但不等于原 Codex 会话已恢复。回执只保留有限长度和最近轮次，不能保证任意长工程的全部决定仍在上下文中。

## 正式真机验收计划

以下全部未在本轮执行。先确定兼容 Responses 的工程模型和真实计价，不擅自更改生产价格。工具检查通过后，只使用桌面 test 中的新独立测试路径。

| 场景 | 验收标准 |
| --- | --- |
| 讨论后只说 OK 开搞 | 原目标、约束完整交接；创建指定文件并独立回读 |
| 同一事情第二步修改 | 保留第一步文件及正确上下文；记录是否复用相同会话 |
| 刷新网页后继续 | 不丢原话、不重复执行；仍能读取对应回执 |
| 驻留程序重启后继续 | 明确恢复旧会话或根据回执恢复，不伪称无缝续接 |
| 两件事情交替执行 | 任务、文件、回执和会话不混用 |
| 完成后追问文件位置 | 回答与真实完整路径和文件内容一致，不重新执行 |
| 同名文件和工具失败 | 不覆盖测试历史；不得因进程退出而宣称目标完成 |
| 运行中停止 | 取消状态不被晚到消息覆盖；明确已有修改不自动撤销 |
| 执行时编辑草稿 | 草稿和焦点保留；完成消息只回流一次 |
| 网页工程交付 | 依赖、构建、启动地址、预览交互分别验证，不能只看 HTML 文件存在 |

## 小白用户需要的明确边界

优先评估：任务是否开始、卡在哪、是否需要确认、结果能否打开、停止是否真正生效、重启能否继续、换电脑能否看到本机文件、更换目录会不会复用旧会话，以及模型用量不足时是否保留已有工作。

工程执行还需要单独管理依赖安装、网络授权、开发服务生命周期、端口冲突和预览。设置中的一个目录选择不能被表述为所有外部工具绝对无法读取该目录外文件的保证；应根据实际沙箱配置说明读写范围。

Windows 建议先接原生 Codex CLI，复用 ONE 网关、事情上下文、事件和回执契约；另做 Windows 程序发现与签名安装、原生沙箱、路径及中文空格处理、进程取消和开发服务验证。保持 ONE 独立配置，不要求普通用户学习 WSL；公司策略和操作系统兼容性需真机验收。
