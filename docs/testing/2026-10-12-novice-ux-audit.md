# ONE 公测前新手体验审查 · 第一遍

日期：2026-10-12。第一遍为只读审查；用户随后批准首批重点优化。原观察保留，实施范围见文末，供第二遍走查复测。

## 范围与证据边界

本轮按“小白用户能否理解用途、识别状态、找到下一步”的预期，走查真实线上 ONE：首页、工作台、任务、功能选择与详情、分身创建入口、个人设置、本机执行设置、知识连接、会员与额度、购买确认弹窗、历史与归档。补查对应前端、默认调度提示词及动效代码。

- 使用本人超管账号马超、Mac Chrome、原有 75% 缩放；没有改变浏览器缩放。普通用户界面的权限差异、首次注册、手机和 Windows 本轮没有实机覆盖。
- 没有发送新模型请求、执行本机任务、购买或创建订单、发布分身、断开知识连接、更改授权目录或后台配置。支付实测由用户用测试账号另行进行。
- 只打开本人已有测试对话。历史中的失败、旧文案和旧能力回答不等于新版功能仍然失败；本轮不重复此前通过的功能验收。
- 搜索文字与临时功能选择已清除；未修改已有聊天记录、测试文件和用户草稿。
- 证据为本轮实际页面、无障碍文本与截图观察，以及下文注明的代码位置。截图在本次审查对话工具记录中；未另存截图文件。本文件不包含密钥、其他用户聊天或个人资料正文。

记录共 40 项：UX-01 至 UX-35 基于实际页面观察，含体验判断，不代表 35 个功能故障；UX-36 至 UX-40 是代码与用户反馈支持的待场景验证风险。优先级只是优化排序建议，不是已批准修改方案。

P1：可能误解执行、费用或授权，或主要操作不可辨认。P2：明显增加理解与操作负担。P3：风格与细节统一。原观察不是完成验收结论；首批实施与待复测状态分开记录。

## 一、会员与额度

预期：十秒内知道“我是什么会员、还剩多少、何时更新、要增加用量点哪里”；只有打算购买时才需要比较套餐。

### UX-01 · P2 · 用量页同时承担套餐销售页

实际：会员状态、剩余进度、赠送说明、消费规则、月付年付、两档套餐、Key 首购、未来会员时间、额外额度和三类账单同时出现。购买内容占据主信息区域。

小白疑问：“我要看剩余用量，还是现在要买东西？”方向：状态页保留少数关键信息和一个续费/升级入口；点击后在购买弹窗比较套餐。复测：第一次进入能直接指出剩余量与更新日期，不必向下找。

### UX-02 · P2 · 消费规则是常驻长正文

实际：“先使用本月会员额度……额外额度长期保留”及额外额度解释占据正文，重复解释保留与使用顺序。

疑问：“这么多说明，哪一句是我必须看懂的？”方向：简短标签加信息提示，规则按需展开；购买前重要条款仍应明确展示。复测：不看说明也能读懂状态，需要规则时能立即找到。

### UX-03 · P1 · 两档套餐价格差异明确，价值差异不明确

实际：普通 99、高级 299；“适合日常使用”和“适合较频繁使用”不能让人判断为什么贵、是否需要升级。购买确认弹窗也没有清楚的套餐对比。

疑问：“贵三倍究竟多了什么？”方向：用可理解的额度差异、适用场景和共同限制比较，不承诺无法保证的消息条数。复测：用户能用自己的话解释两档差别。本项不建议改变价格。

### UX-04 · P2 · 不同购买动作共用“续费 / 升级”

实际：两张卡片按钮均为“续费 / 升级”；普通会员月付确认弹窗又出现升级暂停普通会员时间的说明。

疑问：“我点击后是在续现有套餐，还是换套餐？”方向：按钮按当前会员与所选产品显示具体动作；确认页显示实际生效安排。复测：点击前后对动作的理解一致，尚未付款也能知道影响。

### UX-05 · P2 · 更新日期、赠送起始日期与会员有效期难以区分

实际：剩余 99.6%、某日更新、赠送三个月与赠送生效日期同屏；会员到期时间不够突出。

疑问：“这个日期是额度更新还是会员到期？”方向：分开命名“本月额度更新”和“会员有效至”，购买页再解释续期。复测：不需要计算三个月即可回答何时到期。

### UX-06 · P1 · 同一个额度体系混用百分比、人民币和参考值

实际：月度额度用百分比，额外额度用大号人民币数值，下方又解释“参考值”；消费行是小数但单位不直观。超管余额特殊，不代表普通用户余额规模。

疑问：“这是钱、可以提现的余额，还是可使用额度？”方向：统一展示口径和单位；涉及金额的对应关系在详情说明，不能仅靠长备注消除误解。复测：用户能理解共用额度和扣除顺序，不误认现金余额。

### UX-07 · P2 · 消耗明细以模型和长小数为主，不以我的工作为主

实际：明细主要显示模型名称、四位小数和“额度参考值”；消费页数较多。支付记录、额度流水和消耗明细之间的区别不直观。

疑问：“哪次聊天花了这些？三个账单分别有什么用？”方向：优先显示关联任务/对话、时间、结果和统一单位；模型、精细金额和流水原因作为详情。复测：能从一条账单找到对应工作，而非只知道用了哪个模型。

### UX-08 · P3 · 套餐页仍有不属于当前用户阶段的信息与语言

实际：已拥有 Key 的用户仍看到 Key 首购套餐；年付标签为“20% OFF”。

疑问：“我是不是还要再买一次 Key？折扣到底是多少？”方向：已拥有设备时降低首购内容优先级，中文界面使用“年付八折”等统一表达。复测：购买入口不会让老用户误选设备首购。

## 二、首页与持续对话

预期：知道 ONE 能帮我什么；发消息、执行、选功能各有明确区别；状态回复能指导下一步。

### UX-09 · P2 · 首页示例不够具体，还默认用户已有可召回知识

实际：示例是“我最近在反复想什么”“把一个想法变成行动”“找找被我忘掉的好东西”；随机欢迎语出现“我假装早有准备”。

疑问：“第一次来还没资料，它能找什么？我该说哪种话？”方向：结合连接状态给可直接尝试的具体示例；欢迎语可以有性格，但避免弱化可靠感。复测：没有知识连接的新用户也能找到第一个可完成的请求。

### UX-10 · P1 · 普通发送与本机执行的适用条件不够清楚

实际：发送是箭头，旁边是“执行”闪电；执行的完整含义主要在悬浮/无障碍说明中，普通消息也可能被调度分派。

疑问：“是不是不点执行就不会干活？查资料也要点吗？点了会动电脑吗？”方向：保持聊天为默认入口，把本机执行与普通讨论的边界讲清；操作前明确目标目录和必要确认，不要求用户先理解执行器。复测：用户能区分讨论、后台处理和操作本机。

### UX-11 · P2 · 输入框没有就地添加功能的惯用入口

实际：空输入框键入 @ 后仅出现字符，没有功能候选；底部只有附件入口，没有添加功能的小加号。未发送 @，随后清空。

疑问：“想用已经有的功能，还得离开聊天去功能页吗？”方向：考虑 @ 与加号打开可用功能选择，清晰区分功能与附件；选择后显示下一条范围。复测：无需离开对话即可选择并取消多个功能。

### UX-12 · P2 · “已接住”是内部口语，不是用户可判断的状态

实际：已有对话反复出现“已接住、已入队、交给执行器”；默认调度提示词也有“告诉用户已接住”要求。未发送新消息验证当前线上配置，因此不推断新版每条回复仍如此。

疑问：“接住是什么意思，开始做了没有？我等还是要再点一次？”方向：用“已加入待办/正在处理/需要你确认”等真实状态加一个明确下一步；避免只换措辞而没有状态。复测：每个状态让用户能回答现在发生什么、是否需要操作。

### UX-13 · P2 · 同一任务的新旧结果混在持续对话，缺少轮次与结果层级

实际：历史主对话存在合并回流，“有两件事情返回反馈”中同一网页既有预览未通过，也有修改完成；正文很长，并含旧错误与技术细节。

疑问：“到底成功没有？这是我刚才那次吗？”方向：中心只保留按任务与轮次归属的简短结果，过程放任务侧栏；保留旧历史，不改写成假成功。复测：能区分文件完成、预览失败和之后新一轮结果。

## 三、功能选择

预期：能找到适合需求的功能，知道是否可用、需要什么、是否收费，以及选择后会发生什么。

### UX-14 · P2 · “我的功能”和“发现功能”的差别不易察觉

实际：本超管账号两页内容近似，功能均显示已开放。超管已拥有的范围不能代表普通账号，因此这里不是普通用户购买逻辑故障结论。

疑问：“为什么有两个一样的页面？”方向：以我可用与待获取的功能划分；全部已可用时明确表达，减少重复。复测：普通账号能理解两页差别，管理员全开放时也不会呈现无解释的重复。

### UX-15 · P2 · 分类很多，但卡片没有足够具体的输入示例

实际：22 项功能、10 类、分页；多个经营类描述相似，例如利润测算未在卡片提示应提供哪些数据。

疑问：“它适合我吗，我要发什么才能用？”方向：详情给一个实际输入例子及所需材料，卡片保留一个明确用途而非泛化文案。复测：用户选功能后能直接写出可执行请求。

### UX-16 · P1 · 费用术语还在使用“电力”

实际：功能卡片显示“按实际用量消耗电力”，会员页主要使用“额度”。

疑问：“电力又是另一份余额？选功能另外收费？”方向：统一用“消耗你的 ONE 额度”，必要时说明计费细节。复测：用户知道是一套额度，不是多个钱包。

### UX-17 · P2 · “选择”“加入对话”与“下一条使用”范围不一致

实际：卡片是选择，详情是加入对话，输入框选中标签写下一条使用；选择本身不执行或扣费的好说明只在详情。

疑问：“整个聊天都会用它，还是只用一次？”方向：同一动作同一命名，选中后明确使用范围，把非立即执行/收费的说明放到决定发生的位置。复测：选择后不用猜，也能容易取消。

### UX-18 · P2 · “我的分身”与工具发现混在一个层级

实际：功能页面第三页签是我的分身，包含创建和共享问答入口。

疑问：“分身是我买的工具，还是发给别人用的 AI？”方向：先定义它的用途，再决定是否单独作为共享/分身入口，不让新用户学内部架构。复测：不打开创建表单，也知道这项功能是干什么的。

## 四、任务与工作台

预期：任务列表告诉我正在做什么、哪个需要我处理、哪个已完成；返回主对话不会弄错下一条指令对象。

### UX-19 · P2 · 任务、事情和历史对话的名称还没统一

实际：顶栏已经是任务，内部仍有“事情”“这件事情”“其他事情”“继续这件事”“分派任务”；历史入口也叫最近任务。

疑问：“任务和事情是同一个东西吗，普通聊天也算任务？”方向：少量固定用户词汇；后台实体名不必直接暴露。复测：同一对象从入口到通知到详情都叫同一名字。

### UX-20 · P1 · 已结束列表没有明确区分完成、失败和取消

实际：已结束条目主要显示“分派任务·日期”，需要打开后读正文才能分辨。结束不等于成功，不能简单全部改叫已完成。

疑问：“哪些做成了、哪些还要我处理？”方向：列表显示真实终态和一句结果；已结束仍可作为包含各种终态的总筛选。复测：不逐项打开即可识别成功、失败、取消、未知。

### UX-21 · P2 · 空态、分页与加载更多的关系难懂

实际：进行中为空仍有加载更多记录；已有列表同时出现上一页/下一页和加载更多。待确认空态仅“这里暂时没有记录”，未解释谁需要确认什么。

疑问：“是真的没有还是没加载？下一页和加载更多区别是什么？”方向：统一分页方式，说明空态与确认责任，避免把数据加载机制交给用户理解。复测：空态无需试点才能确定是否还有任务。

### UX-22 · P1 · 任务绑定提示弱，切话题时容易发到旧任务

实际：任务放到工作台后，左右两组聊天共存；核心输入框附近仅较小的“正在聊·任务名/取消指定”。用户从任务返回主交流时需要自己记住绑定。

疑问：“我下一句话是在跟 ONE 闲聊，还是继续这项工作？”方向：输入位置明显显示接收对象，可就地解除；明确指向新任务应优先于旧绑定。复测：切话题时能预测这次消息会送给谁。

### UX-23 · P1 · 执行图标出现在不适合作为指令的消息下

实际：工作台任务区的受理提示、状态和执行回执下也可见闪电操作；未点击，未重复执行。

疑问：“这是不是还要再点？点结果消息会重新做一遍吗？”方向：针对有执行意义的目标/方案提供入口；状态和回执不应诱导重跑，重试必须明确本轮目标。复测：新手不会为了看到结果而重复启动已有操作。

### UX-24 · P2 · 同一任务在不同入口的阅读样式不一致

实际：任务页已经是气泡，放到工作台后的任务区仍以较宽正文、反馈行和回执卡呈现；任务中的每段过程回复也附反馈操作。

疑问：“是不是换了一个对话？这么多按钮哪个要点？”方向：统一消息样式与结果组件，把反馈用于有内容的结果，不给每句连接状态配置一排操作。复测：同一记录在两个入口一眼可认，并保留必要功能。

## 五、本机执行设置

预期：随时能知道当前电脑是否准备好、授权哪个目录、如何更换，点击检查后能看到新状态。

### UX-25 · P2 · 设备授权藏在个人设置中

实际：本机执行位于设置的个人设置页内，没有单独本机执行导航项；已授权目录可见，但需要知道去哪找。

疑问：“电脑权限为什么在个人资料里面？”方向：设置导航体现设备/本机执行，执行入口也提供查看目录链接。复测：用户不问开发者即可找到授权与更换目录。

### UX-26 · P1 · 检查工具状态后没有可感知的新反馈

实际：点击检查工具状态后无障碍树未变化，后续截图仍是通用准备说明；未见正在检查、成功/失败或检查时间。不能据此认定后端没检查。

疑问：“点中了吗？工具到底装好没有？”方向：显示检查中、明确结果与更新时间，已准备好的设备不要一直呈现待准备说明。复测：点击一次就有即时反馈，最终结果可验证，不需要重复点。

### UX-27 · P1 · 授权边界的解释需要用户先懂两套执行器

实际：页面写“外部执行器的权限与 ONE 原生文件工具的目录限制不同”，旁边是 Codex 安装说明、准备本机执行、检查工具状态与文件夹重新检查。

疑问：“到底只动这个文件夹，还是它还能动别的地方？”方向：按当前路线显示实际授权范围与限制，工具来源放详情；不能为了简洁隐藏重要风险，也不能把不同边界宣传成相同保证。复测：用户能准确说出本次允许操作哪里。

## 六、知识连接

预期：知道连了谁的资料、能查什么；未连接时知道下一步；绿色状态不会被误认每次检索都成功。

### UX-28 · P1 · 已连接来源缺少身份和范围信息

实际：得到大脑详情只有来源名、已连接和断开连接；没有可见账号、授权范围或简单试用入口。

疑问：“连的是哪个账号？我的哪些资料会被查到？”方向：显示安全的账号标识、真实检索范围、连接状态与首次提问引导，不展示秘密凭证。复测：用户无需断开重连就能核对来源身份。

### UX-29 · P2 · 全局“知识已连接”太笼统且重复

实际：顶栏和主聊天底部重复已连接；列表中同时有已连接、未连接、等待开通和需管理员开通的来源。

疑问：“绿色是不是所有知识都好了？查不到为什么？”方向：聚合状态表达已连接数量并可展开，检索时另给本次状态；来源可用与未开放应明确区分。复测：理解连接成功不等于每次查询都有结果。

## 七、历史与归档

预期：能找回普通聊天和任务，操作名称与入口一致，重要按钮肉眼可辨。

### UX-30 · P2 · 历史入口名称与打开后的内容不一致

实际：顶栏无文字的历史图标打开“最近任务”；列表包含普通聊天与分派任务，新建按钮叫新任务。

### UX-36 · P2 · 任务搜索与状态筛选的范围可能产生误解

### UX-39 · P1 · 连接异常的恢复需要比请求编号更明确的下一步

证据：`src/main.tsx` 的未登录/Key 异常页面有请插入、错误编号、重连与连接帮助。本轮不拔插设备，不重复此前通过的恢复功能验收。

疑问：“盘就在这，为什么仍说插入？该双击、等一下还是刷新？”方向：按真实阶段区分 Key 不在、启动器未连接、正在更新、授权受阻，提供对应下一步；编号放可复制详情。复测：各异常场景中，不懂技术也能按一条正确指引恢复，不自动重跑原任务。

### UX-40 · P2 · 眼睛移动明显提速，非阻塞与舒适节奏应分别处理

证据：用户反馈过快；当前 `src/main.tsx` 普通移动 560ms、任务侧栏移动 420ms，`src/interruptibleEye.ts` 绕行统一 850ms。对比引入可打断动效前的版本，普通移动为 1100ms、侧栏 480ms，绕行采用较长分段节奏。这里是代码时长对比，不是本轮逐帧测速。

原因边界：可打断动效改造时同时缩短了时长；并非解除点击阻塞必须采用更快速度。当前装饰层不拦截点击、中途从当前位置接续的方向应保留。

方向：按移动距离调整温和速度和减速，允许用户随时再次导航；尊重减少动态效果设置，不把“快”当“顺滑”。复测：连续点击几个导航都立即响应，眼睛就近移动，不追赶用户、不抢注意力。
