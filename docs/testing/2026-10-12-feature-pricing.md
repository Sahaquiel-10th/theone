# 功能使用倍率与单轮授权验收

日期：2026-10-12。范围：功能计费、后台定价、个人授权门槛、对话中的多功能调用。不是创作者提现或分账结算的上线。

## 规则

- 现有官方功能未配置倍率时默认为 0.6 倍。后台保存、认定、上架后，新发布价格用于后续任务；草稿不改变在用版本。
- 文字功能按实际调用模型的参考价格 × 本功能倍率计费，替换模型原零售倍率，不再次相乘。图片功能按已配置单张额度基价 × 功能倍率计费。
- 同一任务的各功能分别计费后相加；仅选择而未调用的功能不扣费。核心调度、任务整理和汇总的模型用量仍按原模型价格收取，不能把整个任务统一乘上多个功能倍率。
- 已发布参考价格缺失的旧模型，以其现有输入、输出及缓存单价作基准；没有偷偷修改供应商成本或全局模型价格。
- 所有扣除继续走同一份 ONE 额度和现有账本；会员月额度、额外额度、充值折扣、采购成本及历史扣费不重算。
- 默认严格大于 2 倍才需单轮确认，等于 2 倍不触发。设置中可调整个人门槛；确认绑定功能、上架版本和倍率，不通用于后续轮次或涨价版本。
- 旧排队任务未携带新计费版本时保留原执行和计费逻辑。新功能调用和用量记录保存价格快照，防止后续编辑覆盖历史。

## 自动测试：预期、实际与证据

| 场景 | 预期 | 实际 |
| --- | --- | --- |
| 默认官方倍率 | 10 输入、5 输出，参考价 2/4；0.6 倍扣 24 微额度 | 24，重复执行不重扣 |
| 两个功能独立计费 | 各 10 输入、10 输出，参考价 2/4；1 倍和 1.2 倍分别扣 60、72 | 60 + 72；第三个未调用功能扣 0；相同工具查询复用结果不重扣 |
| 原模型为 0.6 倍 | 功能 1/1.2 倍替代模型倍率，而不是乘以 0.6 | 独立扣费和余额、账本合计一致 |
| 缓存与长上下文 | 保留 >272K 全请求档位与缓存分类，应用 1.2 倍 | 65,381 微额度；成本 5,449 微额度不受零售倍率影响 |
| 图片功能 | 基价 0.1、成本 0.02、功能 0.6 倍 | 扣 60,000 微额度；成本 20,000；原模型基价保持 0.1；图片私有存储 |
| 高倍率授权 | 超过个人门槛且未确认时不得开始功能 | 拒绝，无功能调用、无功能扣费；旧发布版本确认不能授权新版本 |
| 管理定价 | 默认 0.6；拒绝负数、0、非数字及越界；草稿不覆盖已认定价格 | 全部符合；历史版本价格保留 |
| 隔离与权限 | 不接受伪造 workspace/user；他人任务、报价、额度不可读取或扣除 | 身份由服务端绑定；越权拒绝；其他租户余额不变 |

上述金额来自真实扣费逻辑及隔离的合成模型/数据库测试，不是生产用户的真实扣费实验。

证据：`server/modelBilling.test.ts`、`server/featureRuns.test.ts`、`server/coordinatorService.test.ts`、`server/officialFeatures.test.ts`。最终全量测试：568 项，567 通过、1 项既有跳过、0 失败。TypeScript 检查及生产构建通过；既有大包体积警告保留，不属于此次价格逻辑错误。

## 页面交互验收

通过隔离页面 `/output/playwright/feature-pricing.html` 使用实际 React 组件和模拟 API；不创建生产订单、不改生产模型价格：

- 功能卡片右上角显示 0.6、1.2、2.5 倍；选择入口同样显示倍率。
- 2.5 倍超过默认门槛时弹出页面内“确认高倍率功能”；拒绝不提交，允许仅返回本轮发布版本的确认。
- 个人门槛改成 1.2 后保存成功。
- 后台功能倍率从 0.6 改为 1.2 可保存草稿；认定、上架仍沿用既有流程。
- 拒绝授权不会冻结尚未提交的功能输入；失败后重试保留原提交编号，避免重复任务和扣费。

页面截图：`output/playwright/feature-pricing-evidence/approval.png`（隔离测试，不是生产扣费）。
