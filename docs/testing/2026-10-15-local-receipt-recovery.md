## 0.4.18 停止修复范围

先向精确自有 CLI 发送一次 SIGINT，走 Codex 原生中断并等待清理。需要兜底时，只处理从自有根进程登记、按内核父子关系观察到的同用户后代；每次信号复验 PID、UID 和出生时间。先冻结父进程及后代，再按父到子清理，避免杀掉 sleep 反而让 shell 执行下一句。无进程名扫描杀进程、无进程组广播、无 session 编号猜 PID。

同一 attempt 的重复停止共享一个取消 worker。正常路径继续等待 CLI 退出、stdout/stderr EOF 和该 worker，原命令生命周期缺乏可信结束记录时仍保留 `command_unconfirmed`，不能只凭已观察 PID 消失清锁。取消注册与最终状态快照在同一锁内封闭，避免终态绕过尚未完成的取消核对。

写入指令发生异常时，有已登记进程树就先收束该树，再明确保存未知结果并保持安全等待，不报成“未启动”；只有登记失败且未写过指令的自有新根进程才按启动失败处理。

尚存边界：任意自行 daemon 的未观察进程不在已跟踪集合证明范围；无法确认或无法清理的冻结进程保持需核对，不自动 CONT。未知子进程持续握住输出管道时，正常 EOF barrier 可能继续等待；同步大指令写入持锁时本机取消也可能延迟。因此本轮不宣称所有兼容包装器和异常路径均已实现有界停止，真实 ONE 的新版停止验收仍必须单独进行。
