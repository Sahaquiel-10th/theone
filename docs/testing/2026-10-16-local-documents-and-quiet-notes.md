# 2026-10-16 文档交付与安静的任务反馈

## 约定

- ONE 工作区仍是默认落点，不把“全设备授权”或提示词中的“不删不改”冒充系统级安全保证。本轮未扩大业务目录、网络、个人凭据或 macOS 隐私权限。
- 不做提醒五分钟自动删除；侧栏最多展示最新五件，旧任务仍在任务列表并有入口。失败、不确定和取消不自动夹进普通回复，只有明确追问才提供对应情况。
- 普通新建文档重名时保留原件、另存编号版本；明确要求固定名字且重名即停时仍遵守。回读自己本轮成果与读取无关文件不是同一件事。

## 定位与实现

现有 managed app-server 关闭系统 `/tmp` 和隐式 TMPDIR，长 here-document 因临时文件被拒而留下空目标。不能归因于供应商并发。新增每次执行独立、0700、POSIX realpath 归一化的 scratch；只把授权工作区与这一个私有目录加入 writableRoots。系统临时目录与网络仍关闭。zsh 还需要设置 TMPPREFIX，不只 TMPDIR；显式把四个运行变量送入 Codex shell_environment_policy.set，避免 shell 环境过滤。仅在进程树及输出收尾均确认后清理本轮 scratch，不确定时保留，不重跑。

启动器增加无网络、无 Key 发现、无驻留初始化的 `--one-create-document` 模式，复用描述符相对的文件检查。完整暂存、同步、回读匹配后用 linkat 排他提交；同名含空文件/符号链接自动编号，不覆盖。`--one-create-document-exact` 保留明确重名即停语义。空正文、超量、越界、敏感路径和伪装常见二进制格式拒绝，不留空成品。

运行策略引导新文档使用助手，不把旧测试约束复制给新业务任务。旧任务历史不重写；恢复按钮准备可编辑的新要求，不清空已有草稿、不立即执行。完整任意 shell 仍不是“不改已有文件”的强制只增模式，不能承诺绝对防误改。

反馈只把尚未查看、尚未汇报的最新成功结果附带到普通回复；失败后不翻出同任务更早的成功结果。失败回执不再仅因有文字就标为“部分做成”；执行器明确说未完成/无法验证时前后端均呈现待处理，不显示成功勾号。侧栏失败便签提供重试（先核对恢复方式）及忽略，忽略不删除或重跑。过往对话不删除。

图片统一紧凑完整预览，点击看原图；相同 Markdown 图片与 imageUrl 不重复展示。输入框默认一行、自增长，有对话时缩小眼睛标题及空隙，把纵向空间留给聊天。
