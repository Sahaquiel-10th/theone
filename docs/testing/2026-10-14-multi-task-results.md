# ONE 多任务派发与结果回流验收

本轮修复工作台只分派一件事、绘图落到文字执行器、完成结果停留在任务页的问题。GPT 执行逻辑分析，Claude 执行文章写作；图片走实际图片接口。本机操作保留目录授权和停止能力，不关闭沙箱，也不同时修改同一台设备的文件。

## 交互与执行约定

- 普通交流由 ONE 直接回答。明确的独立目标最多一次安排四件；独立云任务并行，同一任务内追加要求串行，真正有先后关系的任务等待前置成果。
- 后台能力入口统一管理执行 AI、业务功能与平台能力。“什么时候用”决定调度选择，“具体怎么做”约束执行。默认分工只新增缺少配置，保留既有提示词和价格。
- 图片配置可复用现有 GPT 授权，但图片接口、服务模型、每张售价和采购成本独立保存；不修改 GPT 的文字价格。图片必须私有保存为实际附件才算完成。
- 结果回执按任务和轮次保存。新结果进入 ONE 的下一次回答；调度空闲时可单独合并提醒。汇报与查看分别记录：已告诉 ONE 但尚未查看的结果仍在“待确认”。
- 停止优先于晚到结果。本批云端调用、本机交接编译、Codex 和 Local Agent 共用同一授权预算，排除旧项目历史费用和其他用户空间。

## 任务依赖边界

用户补充确认：执行器收到的单位应为各自整理后的任务简报，而不是整条复合指令。简报包含目标、必要素材与共同限制、输出及验收条件；原话继续保存为来源。

独立目标并行；需要前置成果的目标明确等待，拿到实际结果再开始。交接按来源任务、轮次与产物编号引用，不只传“已完成”状态。前置失败或取消时，下游停止并说明缺口，不猜结果、不自动重跑。执行器需要其他任务的信息时，由调度在精确用户空间内协调，不能借资料扩大目录权限或预算。

现有基础依赖已覆盖文字成果进入后续图片要求等自动回归；图片本体进入文档、本机文件进入后续任务仍需分别做实际产物验收。本段是交互边界，不表示这些方向已经全部打通。
