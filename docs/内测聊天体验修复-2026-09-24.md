# 内测聊天体验修复（2026-09-24）

## 引导退出

- 用户直接发送有效消息后，立即隐藏三步引导和“现在，问我一件事”。
- 服务端在当前账号的聊天绑定事务中记录引导完成，刷新或换设备不会再次要求走引导。
- 已有对话的账号不再显示新手引导；不伪造称呼，也不更改知识连接状态。
- 已完成引导但未填写称呼的账号，仍可稍后在设置中修改称呼。

## 飞书操作布局

“保存到飞书”来自 2026-09-21 的飞书读写流程（063d084），不是本次新增；需要主动点击并确认新建文档，不自动写入。

原因：回答操作栏将所有后代按钮固定为 30×30，文字按钮被挤成竖排，弹窗按钮也受到影响。

修复：仅为操作栏直接子按钮设置图标尺寸，文字按钮使用自适应宽度、不逐字换行；操作栏允许整体换行，弹窗保留独立样式。

## 公式显示

回答、执行结果及智能体预览使用统一 Markdown 渲染组件，支持 `$...$` 和 `$$...$$` 数学公式。代码块及行内代码不参与公式渲染。长块公式在容器内横向滚动。

保留不执行原始 HTML 的边界；TeX 禁止可信扩展，并限制宏展开与尺寸。刷新后已有内容也可正常渲染，不修改原始消息。

## 回答中断：已确认问题和诊断边界

截图不足以证明中转站故障，也不能证明历史回答一定触发长度限制。已确认代码未保留上游返回的结束原因，长度截断会被当作正常回答。

- OpenAI 兼容与 Anthropic 的普通/工具调用均规范化结束原因，并写入消息和用量记录。
- 上游明确返回长度限制时，保留部分回答并标注“本次回答达到长度上限，尚未写完”。最新一条回答可点击继续生成，先确认新的电力消耗，再走正常聊天和计费流程。
- 不自动续写，不擅自扩大默认输出额度，不重复结算上一笔调用。
- 过滤原因单独提示；未知原因保持 unknown，不猜测历史结束状态。
- 不完整的工具指令不执行；本机指令编译结果被截断时不下发。
- 若上游错误地返回正常结束，无法只凭文本可靠识别。再次出现时用问题编号定位对应调用，不默认读取其他用户私人聊天。

- 隔离浏览器页面使用实际渲染/飞书组件和项目 CSS，检查桌面、390px 窄屏和保存弹窗；未进行真实付费模型调用或飞书写入。
