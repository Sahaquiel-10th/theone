# 通用教学工具包实施说明

本文描述本次代码实现及其边界。浏览器验收、生产部署、线上健康和真实模型效果应分别记录；本文不将代码或本地测试当作部署完成的证据。

## 产品入口与复用方式

教学能力以“课前工具包、课中工具包、课后工具包”三个入口提供，共用课程和学生提交记录。教师可以只使用其中一个入口，例如导入已有作业后进行批改，也可以围绕同一课程组合使用三个阶段。

| 入口 | 活动类型 | 教师与学生的主要动作 |
| --- | --- | --- |
| 课前工具包 | `inquiry` | 准备导学说明或调研问题；学生提问、填写认识和兴趣；教师查看收取记录并汇总学情 |
| 课中工具包 | `scenario`、`inquiry` | 准备短情境及选择；学生提交决策并查看情境回顾；现场上传照片、补充或确认地点后，围绕课程材料提问 |
| 课后工具包 | `quiz`、`assignment` | 整理已有试卷、在线答题、收取作业原件；AI 提供评分建议，教师复核并发布反馈 |

“杭州通论”属于示例课程配置。课程名称、学科、教材、活动说明、角色情境、问题和评分标准均可替换，代码没有把其他老师绑定到杭州主题。示例配置中的教材占位内容需要由教师补充真实材料。

本期提供固定活动类型和结构化编辑，不包含完整 LMS 的学籍、排课、成绩册体系，也不包含任意节点编排的无代码搭建平台。数字人、硬件入口、学生制作并发布自己的游戏、咨询师售前和分身收费重构不在本次实现中。

## 课程与材料的两条边界

课程配置包含标题、学科、介绍、教学用量上限、课程学习资料和活动。课程学习资料与活动的教师专用资料分开保存。

| 内容 | 保存字段 | 用途和可见范围 |
| --- | --- | --- |
| 允许学生学习的讲义、教材、授课重点 | 课程 `materialText`、`materialAttachmentIds` | 可作为本课程学生导学问答的上下文；公开课程接口不直接返回完整材料或附件 ID |
| 已有试卷原文、参考答案、教师评阅参考 | 活动 `referenceText`、`sourceAttachmentIds` | 用于教师备课整理及本活动评分；不进入学生导学问答的私有参考上下文，不出现在公开课程 DTO |
| 结构化参考答案 | `questions[].answer` | 仅教师侧和评分程序可用；学生取得题目、选项及分值，不取得标准答案字段 |
| 学生正式提交 | `text`、`answers`、`attachmentIds` | 交给当前课程教师；学生只能读取自己会话的提交及教师已发布的反馈 |

教师应把试卷答案和私有评分参考放在活动的教师专用资料区。课程学习资料虽然不会被整份直接下发到公开页面，仍允许用于学生问答，因此不适合存放需要对学生保密的内容。

上传完成和能够用于 AI 阅读是两个不同状态。文档须处理为 `ready` 后才能关联课程或提交；备课、批改仍会检查可读取的内容及本次材料范围。资料不足时应补充原文或转人工处理。

教学 AI 只接收本课程选定材料、本次活动及获授权的提交，不借课程入口连接教师的整套个人知识库，也不读取其他课程或个人聊天。材料中的提示词、角色声明和改分请求均按不可信资料处理。引用必须对应实际传入材料的逐字片段；没有依据时返回资料不足，不编造页码或视频内容。

## 发布、提交与教师复核

1. 教师建立课程，保存允许学生学习的材料与课程用量上限。
2. 在相应阶段建立活动，手动填写内容或让 AI 整理已有材料。AI 备课结果是待审核草稿，教师核对后保存；保存活动不等于开放整个课程。
3. 教师确认开放课程后取得学生链接。学生填写姓名或昵称、选填学号或识别码，并确认提交及学情汇总的告知内容后进入。
4. 学生正式提交答卷、学习记录或作业；教师也可导入已经收取的作业，姓名或昵称必填，识别码选填。
5. AI 对支持的试卷或作业生成 `suggested` 评分。教师可以调整分项分数和反馈，再显式发布为 `published`，学生才会看到成绩与批注。

客观单选题按提交时的标准答案进行程序核对，选项和答案使用完整选项文本。主观题与作业按提交时的题目、参考答案或评分维度生成建议；总分由分项求和。评分依据须来自学生实际答案或可读取作品。AI 建议不会自动发布，也不会覆盖已经由教师确认发布的成绩。

每份提交保存独立的 `activitySnapshot` 与活动修订号，后续修改题目或评分标准不会悄悄改变旧作业的评分合同。情境活动的初始公开数据不包含反思内容；成功提交后，本会话可取得已答场景的 `learningReview`，其内容也来自提交时快照。

课程开放后配置只读。修改课程或活动前须先关闭学生入口；关闭保留已有作业与成绩，教师仍可复核这些提交。重新开放会生成新链接，旧链接和旧学生 token 不会在新入口继续有效。课程配置保存、发布和关闭均检查修订号，冲突返回 `409`。

当前前端可导出收取记录 CSV；作业原件通过具体提交关联的鉴权下载接口取得。这里不把 CSV 导出描述为作业原件的一键打包下载。

## 学生身份与隔离

教师管理接口沿用 ONE 登录与 ONE Key 校验，并再次验证用户启用、空间有效、成员未停用以及当前空间的 `owner` 身份。首版没有独立的教师授权项，普通公司成员不能仅凭成员身份发布课程或消耗课程预算；平台管理员也没有跨空间读取教学内容的例外。

学生使用独立、限课程的随机 token，服务端只保存与课程公开链接绑定的 token hash。会话有效期为七天；关闭课程、课程负责人失去权限或重新开放换链都会阻止旧入口继续访问。姓名和识别码是教师核对信息，不是认证凭据；两个使用相同昵称或均未填写识别码的学生仍按不同 `sessionId` 隔离。

学生只能读取自己会话的提交、附件和教学 AI 操作。教师可以查看学生正式提交给该课程的内容；学情汇总仅处理已告知用途的课程提交和导学问题，不因此开放学生的完整私人聊天或其他课程内容。

所有独立教学记录带有 `workspaceId`、`userId`，其中 `userId` 为课程所属教师。学生文件用 `session.id` 作为文件 owner；教师材料和手动导入文件用教师 ID 作为文件 owner。所有文件还须绑定 `conversationId = teaching:<courseId>`。教师读取学生原件时，必须同时满足“文件属于该学生会话”及“文件已关联本课程具体提交”，不能借文件 ID 任意读取学生上传。

公开接口使用明确字段投影，不返回教师 owner 标识、token hash、材料正文、试卷私有来源、标准答案或完整提交快照；未发布的评分建议也不会返回给学生。`publicUser` 同时排除整个 `teaching` 状态，避免经个人信息或管理员用户列表旁路导出。教学响应使用 `Cache-Control: no-store`。

## 预算、文件和容量边界

教学 AI 的准备、导学问答、批改和学情汇总共用教师设置的课程 `budgetMicros`。费用沿用既有模型网关和电力账务；个人空间由教师账户承担，公司空间沿用原有空间付款归属。模型调用前同时核对课程已用及预留额度，学生进入课程不另建付费套餐。本次未改生产价格、分账、兑换规则或公开咨询分身商业模式。

课程额度不是账户充值，也不是无限调用许可。当前 AI 层限制每课程同时运行四项操作、每学生会话同时运行一项操作，以及每课程每分钟最多 120 项新操作；模型可用性、账户余额、单次预计用量和内容上限仍需分别满足。仅含可按标准核对的客观题可不经过模型请求。

课程文件使用私有存储和鉴权下载。当前服务端每文件不超过 200 MB，每课程最多 3,000 个文件、总计 2 GiB，每文件 owner 最多五项正在上传。视频支持 `.mp4`、`.webm`、`.mov` 原件收取和格式核对，不送入文档解析器，不提供视频内容理解或自动视频评分。只有视频或没有可读取文本的作业应由教师人工评阅。

私有教学状态目前限制每教师账户最多 30 门课程、每课程 30 项活动，账户内最多 2,000 个学生会话、5,000 份提交及 10,000 项 AI 操作记录。达到上限时明确拒绝新建，不自动删除既有生产记录。

核心身份和提交接口的每课程每分钟请求上限为 1,200，以容纳同一课堂集中进入。已编写并运行的 100 名学生数据路径测试验证了同一分钟注册和正式提交 HTTP 成功；它没有调用 100 路模型，也不证明模型吞吐、生产服务器容量或全班同时 AI 问答的体验。

## 存储与迁移

教学状态保存在所属 `User.teaching` 下，包含 `courses`、`sessions`、`submissions`、`operations` 四组记录，复用现有 Store 持久化。JSON Store 写入原有私有数据库文件；MySQL Store 沿用用户记录的 JSON 数据保存，不新增教学表或 DDL 迁移。

已有用户没有 `teaching` 字段时按空状态读取，纯列表和查询不会初始化或修改用户记录；首次写入才初始化。备份和恢复须同时保留用户私有状态与既有私有附件目录，不能只备份课程链接或前端文件。本次没有生产数据删除或自动清理操作。

## API 摘要

以下路径均以 `/api/teaching` 为前缀。教师路径需要 ONE Key 身份和当前空间 owner 权限；学生路径使用当前课程签发的 `Authorization: Bearer <token>`，查看公开课程和创建学生会话除外。

| 接口 | 用途 |
| --- | --- |
| `GET /courses`、`POST /courses` | 读取本人课程、建立课程 |
| `GET /courses/:id`、`PATCH /courses/:id` | 读取或保存课程；修改携带课程 `revision` |
| `POST /courses/:id/publish` | 传 `revision`、`confirmed: true` 开放已保存活动 |
| `POST /courses/:id/close` | 传 `revision` 关闭学生入口，保留提交 |
| `POST /courses/:id/activities`、`PATCH /courses/:id/activities/:activityId` | 创建或修改活动；`revision` 指课程修订号，更新可同时核对 `activityRevision` |
| `GET /courses/:id/submissions`、`POST /courses/:id/submissions` | 教师读取或手动导入正式提交 |
| `PATCH /courses/:id/submissions/:submissionId/review` | 传 `{ grade }` 复核并发布成绩；分项必须对应提交快照的题目或评分标准 |
| `POST /courses/:courseId/ai` | 以 `operationId`、`budgetConfirmed: true` 发起 `prepare`、`grade` 或 `insights` |
| `GET /courses/:courseId/operations`、`GET /courses/:courseId/operations/:id` | 查询教师操作回执；支持按操作 ID 或原 `operationId` 找回 |
| `GET /public/:slug` | 读取允许学生看的课程及活动投影 |
| `POST /public/:slug/sessions` | 传姓名或昵称、可选识别码、`consent: true`，创建学生会话 |
| `GET /public/:slug/session` | 校验并取得当前会话的参与信息 |
| `POST /public/:slug/submissions`、`GET /public/:slug/submissions` | 提交本人的活动记录、读取本人的提交及已发布反馈 |
| `POST /public/:slug/questions` | 在已开放的导学或情境活动中提出课程问题 |
| `GET /public/:slug/operations`、`GET /public/:slug/operations/:id` | 只查询当前学生会话的操作 |

教师 `/courses/:courseId` 和学生 `/public/:slug` 两种前缀下均有 `POST /uploads`、`PUT /uploads/:id/chunks?offset=...`、`POST /uploads/:id/complete`、`GET /uploads/:id`。作业附件下载路径为对应前缀下的 `GET /submissions/:submissionId/attachments/:attachmentId/content`。附件必须上传处理完成后才能用于正式提交。

正式提交携带 `activityId`、`operationId`，以及 `text`、`answers`、`attachmentIds` 中至少一种有效内容；学生姓名来自服务端会话，不接受请求体冒充他人身份。同一归属下重复发送相同 `operationId` 和相同内容会返回既有提交，不重复收件；修改内容复用旧编号返回 `409`。学生本人回执包含 `operationId`，便于刷新后核对丢失回执。

## 故障与恢复

- 保存遇到 `409` 修订冲突时先刷新核对，不能用旧页面覆盖新配置。课程已开放时先关闭入口，再修改和重新开放。
- 提交或 AI 请求的响应丢失时，先刷新提交记录或查询原 `operationId`。未确认结果前保留原内容和原操作编号，不直接生成新编号重复执行。
- AI 操作先持久化回执，再开始执行；轮询只查状态，不重新调用模型。进程重启后，读取到缺少当前进程执行实例的 `running` 操作会标记 `uncertain`，不自动重跑。
- `failed` 或 `uncertain` 不等于没有模型用量。先核对原回执和账务；确需再次处理时由教师明确发起新操作。晚到的 AI 结果不能覆盖教师已经发布的成绩。
- 资料不足、视频不能解析或评分参考缺失时，教师可补齐材料或人工复核，不借其他空间连接兜底。
- 目前没有新增跨进程任务队列或共享作业租约；进程内执行状态不构成多 worker 并行调度能力的验证。
