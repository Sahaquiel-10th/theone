# 分身同链接版本更新

先完成现有问答分享的版本管理，不提前启用访客收费。原链接、发布者、累计费用与附件配额不变。

- 主人登录并插 Key 才能读取配置、编辑并明确发布。使用版本号防止覆盖他人或其他窗口的新配置。
- 更新重新校验模型、知识来源、费用确认与额度；总额度不能低于已消费与预留之和。有效天数从本次发布起算；关闭的链接不允许借更新复活。
- 有正在执行的问题时拒绝更新，待结束后重试。新问题与更新在存储事务中串行决定，避免半次任务用旧知识、半次用新配置。
- 更新使旧访客会话停止继续调用，提示重新开始；旧会话的历史和附件不进入新版回答。不自动发起收费任务。
- 保存最近 20 个配置快照，超过后丢弃最早的配置快照，不删除任何账单、任务或访客文件。历史只供主人查看，恢复历史内容也必须重新审核当前知识授权、明确发布新版本。
- 旧记录按版本 1 兼容；旧版合并过的系统提示词不当作用户指令再次拼接，编辑旧记录时明确重新填写回答要求。
- 不新增表，使用现有记录 JSON 扩展字段。验证跨空间隔离、并发版本、旧会话拒绝、预算不清零与原分享回归。

## 实施与验收

入口为“功能 → 分身 → 更新配置”，复用创建表单，明确显示版本和费用确认。最近 20 个历史配置按每页 5 条折叠展示；此批不提供自动回滚按钮，要恢复内容需重新编辑并发布。失效知识来源可以直接从编辑表单移除。

更新不允许旧访客读取旧会话接口或继续上传附件；访客收到明确的版本变更提示后可重新开始。新会话重新读取名称和附件开关，旧附件、历史回答不会带入新任务。任务和账单不删除。

开发验证：类型检查、336 项测试（335 通过、1 项既有跳过）、生产构建、diff 检查通过。覆盖真实 HTTP 权限/更新/旧会话拒绝、知识和历史隔离、同链接与累计费用保持、版本冲突、运行中更新拒绝。真人界面体验与真实供应商效果留作集中验收；未自动修改任何生产分身。
