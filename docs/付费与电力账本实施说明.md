# 付费与电力账本实施说明

## 已确定的产品规则

### 定价后台与通知（2026-09-19）

- 保留 1 电力对应 1 美元计价单位；人民币充值汇率保持独立，不修改已有余额。供应商进价填写包含采购充值折扣后的实际美元成本。
- 超管进入「电力与收费 → 模型与定价」，搜索模型，在弹窗内填写官方输入/输出参考价、实际输入/输出采购价（美元 / 百万 Token）、用户收费倍率。自动预览用户电力价格和估算毛利。
- 发布必须填写用户说明，可立即生效或指定北京时间。每个聊天模型最多一个待生效版本，须先撤回才能替换。历史版本及撤回记录保留在模型 record_json，审计记录保留发布与撤回动作；无需数据库迁移。
- 计费在调用开始时从已生效版本选取并冻结售价和采购成本。预约按时间解析，无需依赖定时任务或重启；在途调用不改价。
- 用户电力页及充值弹窗展示通知，详情含模型、原因、版本、生效时间和调整前后价格，历史分页。公开投影不包含供应商进价、密钥或地址。
- 本次定价发布入口针对聊天模型；图片仍按原有单次计费配置。未重新发布的现有模型价格保持原样，不自动套用八折。

- 首期只接微信 Native 扫码支付。
- 充值数量原样到账，不通过充值赠送实现消费折扣。充值汇率在订单创建时锁定。
- 支持按电力档位充值或自定义人民币金额（¥0.01–¥10000，最多两位小数，默认 ¥1）。自定义金额按订单汇率换算，向下取整到 0.000001 电力；二维码旁展示服务端确认的金额及到账电力。金额以整数分传输和核验，重试必须保持原充值方式和金额，不按新汇率重算旧单。旧电力订单继续兼容，无需数据库迁移或更新 U 盘。
- 模型按官方参考价乘以用户消费倍率计费：0.8 为优惠期，1.2 为官方参考价加 20% 服务费。
- 供应商进价独立配置，仅超管可见。进价计算所得是估算采购成本，不是供应商实际对账单，也不是现金净利润。
- 模型调用开始前锁定当时价格；修改配置不追改历史账单或已开始的请求。
- 普通用户只看自己的充值、用量和流水；服务端分页，每页 10 条，界面折叠展开。
- 批量赠送覆盖当前启用且有有效个人空间及成员关系的账号（含管理员），停用账号不参加。每个账号一条流水，批次号关联；无实际微信付款的赠送不能记作充值收入。

## 存储与保留

继续使用服务器上的 ONE 独立 MySQL 库 `theone_prod`，不用新购数据库实例。生产库内已有 `recharge_orders`、`power_accounts`、`power_ledger`、`model_usage_records`、`audit_logs` 表，字段通过各行 `record_json` 保存，隔离键有独立列。

订单记录保留人民币金额、电力、汇率快照、支付状态、商户/AppID、微信交易号、时间。普通接口只返回必要的订单展示字段。账本保留变更前后余额、发生金额、账号、workspace、赠送/订单批次号和操作人。业务记录不依赖 systemd 日志，发布版本、归档账号不能清理财务记录。

赠送批次的余额、逐用户流水和审计记录在一个 MySQL 事务中提交。操作 ID 重试不能重复赠送。微信订单按用户/workspace/操作 ID 去重；经微信验签的回调和主动查询使用同一个入账函数。支付交易号及批次流水还有数据库唯一键兜底。已过本地有效时间的订单如果收到真实成功付款，仍须核验入账，不能丢单。

现有存储层只适合单应用进程：它全量加载数据，在进程中排队后写 MySQL 事务。不要直接增加多个应用副本处理资金。扩大规模前改成数据库行锁/原子余额更新、按索引查询分页和唯一约束驱动幂等；更换为云 MySQL 并不能自行解决该问题。

COS 继续作为异地备份目的地，不作为在线订单库。付费上线前核验最近一次完整数据库备份，并进行恢复演练。每日备份意味着最多可能丢失上一次备份之后的变更；需要更低损失窗口时启用并异地保存 binlog，支持时间点恢复。微信对账可补核付款，不能重建所有消费和赠送，所以账本备份同样必要。退款或纠错要追加冲正流水，不能删除或覆盖原流水；本期不提供自动退款按钮，正式退款流程另行验收。

## 微信配置与发布

服务端配置下列环境变量（只配置值，不提交 Git，不贴进聊天）：

```text
WECHAT_PAY_APP_ID
WECHAT_PAY_MCH_ID
WECHAT_PAY_MERCHANT_SERIAL_NO
WECHAT_PAY_PRIVATE_KEY_PATH
WECHAT_PAY_PUBLIC_KEY_ID
WECHAT_PAY_PUBLIC_KEY_PATH
WECHAT_PAY_API_V3_KEY
WECHAT_PAY_NOTIFY_URL=https://theone.aiarrival.cn/api/pay/wechat/notify
```

私钥和微信支付公钥放 ONE 独立私密目录，允许服务账号只读；本期使用微信支付公钥模式。回调使用原始报文 RSA 验签、时间窗口校验和 AES-GCM 解密，再核对订单、商户、AppID、金额和币种。不要复制另一项目 `.env`；相同商户可以使用独立 ONE 订单号和回调，但需核验商户与 AppID 的绑定。

用户点“核对支付”时，服务端主动向微信查单并验签；前端传入的“成功”状态绝不触发入账。支付回调不依赖 U 盘在场；创建订单、查询个人账单仍要求当前 ONE Key。未配置微信时阻止下单，不伪装支付成功。

## 发布前验收

- 微信真实小额下单、付款、到账；重复通知只入账一次。
- 付款后关闭页面/拔 Key，重新登录仍可核对与到账。
- 回调暂不可达时主动查单补账，查单与回调并发不重复入账。
- 错误金额、错误商户、错误 AppID、伪造通知拒绝。
- 两用户同操作 ID、跨 workspace 订单查询均不串账。
- 批量赠送重试、异常账户导致整批失败；账本可追溯。
- 优惠期切换服务费，旧请求/历史价格不变，新请求按新价格。
- 现有余额迁移前后不变，不把旧售价擅自标为官方价；管理员核验官方参考报价与电力单位后发布。

本期按普通输入/输出计价；复杂缓存、长上下文阶梯、图片等报价不得虚称均已精确支持。具有这些差异的模型应先对账验证、补计费维度后再宣传“官方价八折”。图片仍沿用已配置的按次价格。
