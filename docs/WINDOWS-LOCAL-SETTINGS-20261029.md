# Windows 本机工作设置修复（0.4.28）

## 现场与根因

用户刘爽在新灌装 Windows 电脑上运行 0.4.27，选择工作文件夹返回“不支持目录设置”，工具检查显示连接未确认。真实 Windows 电脑本轮已不在用户手边，不以编译或 CI 替代原生弹窗验收。

- 0.4.27 Windows 只声明并实现 local_tools_v1、runtime_update_v1；缺 local_configuration_v1，升级到 0.4.27 并不能补上该协议。
- 工具状态此前仅有 Mac managed_codex_v1 路径，Windows 内置文件工具被误判为未连接；路由还提前受 Mac Codex 网关开关影响。
- Windows 同版本驻留缓存按版本文件名复用，因此采用新版本 0.4.28，不覆盖旧同名制品。

## 修复边界

Windows 实现只读目录查询与显式原生目录选择；GET 不弹窗，取消/不可用/保存失败不替换原目录。设置按设备保存在当前电脑；成功切换后当前连接直接使用新目录。目录窗异步运行，不阻塞 Key 签名；保存前复验同一 Key/连接，断线后旧窗口不可落盘。目录选择和更新互斥，设置文件先暂存再原子替换。

服务端仍按用户、工作区、Key、电脑绑定鉴权；连接变化与缺少协议分开报告。Windows 内置工具不下载 Mac 执行器，不宣告 Codex 工程执行或任意终端能力；工具状态来自当前已签名认证的 Windows 驻留与 local_tools_v1。前端显示“内置文件工具已连接”，不显示 Mac 准备按钮；目录复查失败不再保留成功检查时间。

## 自动验证与制品

- npm test：1848 项，1847 通过、0 失败、1 项既有压测跳过。
- TypeScript、生产构建及 git diff --check 通过。
- Mac 可执行的 Windows 模块纯 Go 测试 17 项及 race 检查通过；Windows 测试二进制与 x64 GUI PE 构建通过。
- 新增签名 WebSocket 集成覆盖目录读换、取消保留、账号/空间/电脑隔离、缺能力、断线、Windows 工具状态与禁用 Mac 网关时不下载 Codex。
- 新增 Windows-only 发布模式，从已验签清单原样保留 Mac 0.4.27 条目及 ZIP 字节，仅替换 Windows 0.4.28；包括真实 CLI 合成制品、错签/篡改/降版/错误 metadata/非 PE/原包摘要/已有输出保护测试。
- Windows 默认构建版本由 config/runtime-version-windows.txt 管理；Mac 继续使用 config/runtime-version.txt。双端可独立升级，正式校验器分别输出两端版本。

## 发布与仍待验收

本地 Windows 0.4.28 签名清单和双端制品已校验；保留的基清单与当前公开清单一致。网站 CI、生产部署和 Windows 包线上发布分别核对，不凭提交推送判断已上线。

Windows 真机待办：更新后确认实际驻留 0.4.28；选择含中文的目录；查询与取消更换保留原目录；检查工具显示内置文件工具；新任务只在所选目录创建并回读一份隔离文件；再次任务和重连不重复要求选择。没有设备时不勾选上述验收，也不在真实用户资料上重跑任务。
