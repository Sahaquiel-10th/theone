# ONE 执行交接与任务气泡实施计划

日期：2026-10-06。状态：规划完成，分阶段实施；本文不是上线验收结果。

本文补充《ONE统一对话与任务工作区设计方案-2026-10-04》。本轮以体验优先，不以减少模型调用为首要目标。新的完成气泡返回对话方案替代此前“只亮灯、不进入信息流”的方案，其他既有页面比例、导航和品牌交互不随本轮重做。

## 一、用户感受到的产品

用户一直与 ONE 沟通，不必管理多个聊天窗口。ONE 可以回答、查询资料或把工作交给独立事情；用户仍能打开事情继续讨论、纠正和执行。核心调度 AI 负责理解和分派，各事情的执行 AI 负责具体工作；模型、提示词和允许的工具均沿用管理员配置中心。

工作台的对话和输入框保持居中，初版扩大到桌面视野的一半以上，同时限制正文行宽。正在执行的事情以气泡移到右侧，多个任务依次排列。真实完成后，气泡返回中心，成为带有查看入口的结果消息。失败、等待授权、连接中断不能表现成完成。

只要开始操作本机，所有入口都使用同一种圆形扩散反色效果，从实际执行入口的位置开始。视觉反馈不替代 Key、文件夹和操作授权，也不能比实际接受执行更早宣称“已开工”。

## 二、任务与上下文的规则

路由优先级：用户明确指定的事情 → 用户所在的明确事情窗口 → 中心对话语义和近期交流 → 有歧义时简短确认。页面位置不能覆盖“那个 UI”等明确指向。

事情内点执行：读取该事情截至执行焦点的原始对话与已分派的交接内容，整理执行指令后进入本机执行链路。保留原文入口，不把“OK，开搞”单独当成任务目标。

工作台发消息：调度 AI 先理解意图。普通讨论直接回答；需要知识时按需调用已授权知识接口，不强制创建可见事情；需要执行时定位已有事情或新建事情，带上相关上下文再分派。需要查旧事情时先查任务名片，再读取相关详细记录，不把全部事情全文塞入每次请求。

任务名片包含标题、目标、关联项目、状态和近期进展。摘要是定位索引，不是事实或授权的唯一来源；具体内容、金额、文件内容和限制应能回溯原始消息。摘要覆盖范围与更新版本要明确，未覆盖的新消息不能丢失。

交接记录包含：目标、最新补充、已确认决定、约束、预期产物、验收标准及原始消息引用。每次执行使用独立快照；后来的补充进入同一事情队列，不悄悄改变正在执行的快照。不同事情可以并行，同一事情顺序处理。

## 三、执行入口与反馈

- 保留事情和已保存消息上的执行按钮。
- 输入框旁增加“执行”：保存当前消息后，带上当前上下文走同一条执行链路，而不是先生成一段普通回答才能执行。
- 自然语言“那就开工”由调度判断和交接，但不能扩大本机权限；删除、覆盖和对外发布仍需与风险相称的明确授权。
- “收到/正在查资料”的短提示由真实受理状态触发，不为这句话额外调用一次 AI。
- 完成消息尽量引用执行 AI 的结果简报和产物，不让调度 AI 每次重读整篇产物。需要解释时再读；结果消息记录来源，避免重复回流。

## 四、注意力与动效边界

任务气泡可打开详情和继续干预；数量多时折叠，不无限向下堆叠。不因任务完成抢焦点、挤掉当前事情、清空草稿或强制滚动。用户正在输入时暂缓回流展示，保留弱提示；空闲或发送后再呈现。窄屏采用紧凑任务入口，减少动态效果时采用静态状态变化。

保留既有 ONE 的轻微躲闪、欢迎语和彩蛋；本轮不增加持续循环或忽快忽慢的大幅运动。所有动效必须服务于“内容去了哪里、现在是什么状态”。

## 五、开发顺序

1. 修复现有断点：本机交接编译器补入该事情已经保存的调度交接，隔离其他用户、事情及执行焦点之后的内容。优先验证“创建文档 → OK，开搞”。
2. 补齐路由、名片和上下文读取：必要时读取详细记录；保留来源、队列和执行快照；提示词可配置。
3. 输入框执行与自然语言执行共用受理、权限、去重和错误处理，不增加平行的临时执行系统。
4. 工作台加宽、任务气泡去程/回程和全入口反色；先本地预览再做真实链路验收。
5. 按预期 → 实际 → 缺陷 → 修复 → 复测完成矩阵，区分本地模拟、服务测试和真实本机执行证据。

## 六、验收场景

| 场景 | 必须得到的结果 |
| --- | --- |
| 工作台讨论成熟后“OK，开搞” | 执行 AI 收到原任务、确认内容和限制，不只收到确认词 |
| 在事情里补充标题后点执行 | 执行快照含新标题和之前的任务内容 |
| 点 AI 方案上的闪电 | 截至所点方案的上下文，不包含之后的修改 |
| 露营中提到“那个 UI，加上……直接发布” | 定位 UI，保留明确指向与发布权限要求；随后露营不混入 UI |
| 两个 UI 项目均可能匹配 | 简短确认，不随意执行 |
| 同事情执行中继续补充 | 顺序排队、原执行快照不变、补充不丢失 |
| 多个事情同时执行 | 气泡独立呈现，状态和回流不串任务、不重复 |
| 执行连接失败或结果未知 | 不宣称完成，不自动重跑可能已发生的本机操作 |
| 用户正在输入时完成 | 草稿和焦点保留，无强制切页或滚动 |
| 不同用户、空间、公共分身 | 上下文严格隔离；公共分身不能获得本机权限 |

费用记录需可区分调度、上下文整理和执行；先观察实际调用量、耗时与体验，再调整模型和上下文预算，不以截断关键约束换取便宜。

## 七、首批实施记录

已修复本机交接编译器遗漏事情调度交接的问题：通过消息编号关联交接，只读取同用户、同空间、同事情且位于执行焦点之前的内容；保留用户原话，交接不作为新增授权。默认和管理员自定义整理提示词均采用同一上下文入口。

本地验证：全部自动测试 408 项，407 通过、1 跳过，0 失败；类型检查、生产构建通过。新增用例覆盖确认词带上文档任务、跨用户/空间/事情隔离，以及排除未来交接。此记录不等于真实本机产物验收；输入框执行、气泡动画和加宽布局尚未在本批实现。
