# ONE Key 灌装与交付

本文是 ONE Key 首批生产、交接和故障排查的操作基线。接手人不需要了解启动器内部实现，只需按本文完成“账号创建 → 凭证签发 → U 盘格式化 → 双系统灌装 → 实机验收 → 贴标交付”。

## 名词与职责

- **签发**：超管在服务器后台为指定用户创建唯一 ONE Key，并下载仅出现一次的私钥凭证。
- **格式化**：把空白 U 盘统一为 `FAT32 + MBR`；此操作会清除盘内全部文件，灌装器不会代替人工执行。
- **灌装**：在 Mac 上运行统一命令，把同一份凭证、Mac 启动器和 Windows 启动器写入一只空白 U 盘。
- **交付**：完成 Mac、Windows、拔插恢复和后台归属核对后贴标发出。
- **挂失**：服务器作废设备 ID；同一凭证即使被复制，所有副本也会一起失效。

灌装器是运行在生产人员 Mac 上的本地工具，不是线上服务。修改灌装器后需要提交 Git 以便版本留档和交接，但只有推送到 `main` 才会触发服务器自动部署；灌装器本身无需安装到生产服务器。

## U 盘规格与格式化

### 统一规格

- 文件系统：`FAT32`
- 分区方案：`MBR`（主引导记录）
- 建议卷名：`ONE`，或便于盘点的短编号；不要使用空格和过长名称
- 容量：1 GB 足够当前双系统启动器和凭证使用

`FAT16` 对当前约数 MB 的文件通常也能工作，但首批交付统一改为 `FAT32 + MBR`，以减少不同 Windows/macOS 版本的兼容性差异。

### 用 macOS 磁盘工具格式化

> 这一步会抹掉整只 U 盘。先核对盘内没有需要保留的文件。

1. 打开“磁盘工具”。
2. 菜单栏选择“显示”→“显示所有设备”。
3. 在左侧“外置”下选择 U 盘最上层的**物理设备**，不要只选下面缩进的卷。
4. 点击“抹掉”，填写：
   - 名称：`ONE`
   - 格式：`MS-DOS (FAT)`
   - 方案：`主引导记录`（Master Boot Record）
5. 点击“抹掉”。完成后选中卷，点“信息”，确认文件系统显示为 `MS-DOS (FAT32)`，分区图显示为 `Master Boot Record`。

如果弹窗中没有“方案”，说明当前选中的是卷而不是最上层物理设备。截图中只有“名称”和“格式”，就属于这种情况。

部分 1 GB 小盘通过图形界面抹掉后可能仍显示 FAT16。遇到这种情况，用终端明确指定 FAT32。先运行：

```bash
diskutil list external physical
```

从结果中再次核对 U 盘的容量和设备号。假设确认整只 U 盘是 `/dev/disk4`，再运行：

```bash
diskutil eraseDisk FAT32 ONE MBRFormat /dev/disk4
diskutil info /Volumes/ONE
```

`/dev/disk4` 只是示例，拔插后编号可能变化，绝不能照抄。必须以当次 `diskutil list external physical` 的结果为准，并操作整盘 `diskN`，不能填分区 `diskNs1`。最终检查结果应包含 FAT32、外置磁盘和 MBR。

## 当前 V0.1 灌装流程

1. 超管先在“账号”中创建 Key-only 普通用户；系统不要求给普通用户设置或交付密码。
2. 在“ONE Key”中选中该用户，填写印在 U 盘标签上的唯一序列号。
3. 点击“生成并下载凭证”。私钥只会下载这一次，服务端只保存公钥。
4. 使用一只空白 U 盘；统一灌装命令不会格式化磁盘、不会覆盖旧 ONE Key，也不会移动其他用户文件。把 U 盘插入用于灌装的 Mac，执行：

```bash
npm run provision:one-key -- --list-volumes
npm run provision:one-key -- --credential ~/Downloads/ONE-序列号.one-key.json --dry-run
npm run provision:one-key -- --credential ~/Downloads/ONE-序列号.one-key.json --volume /Volumes/U盘名称
```

其中：

- `--list-volumes` 只列出当前可选外置卷。
- `--dry-run` 只校验凭证版本、设备 ID 和生产地址，不写 U 盘。
- 最后一条命令才会构建、校验并写入目标卷。
- 凭证文件包含私钥，不要把内容粘贴到聊天、工单或日志；只传递本机文件路径。

命令先在电脑上构建并校验 Mac 通用版和 Windows x64 版，再暂存到 U 盘；只有两个启动器、凭证和签名/哈希全部通过后才完成灌装。目标不是外置卷、存在旧 ONE 文件、包含其他可见文件、生产地址不符或空间不足时会停止，不做覆盖。

5. 灌装完成后，U 盘根目录统一为：

- `ONE for Mac.app`
- `ONE for Windows.exe`
- 隐藏目录 `.one`，其中保存唯一凭证和简短说明

灌装器同时会把 ONE logo 写入隐藏的 `.VolumeIcon.icns`，并给卷设置 macOS 自定义图标。如 Finder 仍显示旧图标，安全推出并重新插入即可刷新。

Windows 构建需要 Go 1.23 或更高版本。可用 `--go-bin /完整路径/go` 指定不安装到系统的 Go 工具链。当前内测不使用旧盘覆盖模式；旧盘应由运营确认并清空后按新盘重新灌装，避免凭证串号。

6. 首次在每台电脑使用时：macOS 双击 `ONE for Mac.app`，Windows 双击 `ONE for Windows.exe`。两端共用隐藏的 `.one/credential.json`，因此对应同一个 ONE Key、账号和 Workspace。

当前出厂基线是 Mac/Windows 0.3.1，两个启动器都必须声明在线更新协议 V1 并内置同一发布公钥；灌装器会核对构建元数据，不接受缺少协议或公钥不一致的旧制品。以后页面提示新版时，用户只更新当前系统的 Launcher；更新器不得修改 `.one/credential.json`。另一系统会在下次使用该 Key 时单独更新。
7. 保持网页打开，拔出 U 盘后发起请求，应立即提示插入；重新插入后等待约 1～2 秒，同一网页无需刷新即可继续使用。
8. 在超管后台核对序列号、绑定用户和最后使用时间，再贴标并交付。新用户余额为 0，交付前在“电力”中赠送体验额度。

## 每只盘的交付验收

1. 根目录只能看到 `ONE for Mac.app` 和 `ONE for Windows.exe`；`.one` 是刻意隐藏的凭证目录。
2. Mac 双击后能以目标用户进入 ONE；Windows 实机双击后也能进入同一账号。
3. 首次用户能完成称呼设置和知识连接；已连接的知识源按账号/Workspace 跨设备生效。
4. 插着 U 盘可以发起受保护请求；拔出后请求在调用知识库和模型前被拦截，不消耗电力。
5. 重新插入后等待约 1～2 秒，不刷新网页即可继续使用；电脑重启后需重新双击启动器。
6. 超管后台显示的 Key 序列号、绑定用户、最后使用时间和实物标签一致。

任何一项失败都不要交付，也不要重新签发第二份凭证覆盖排查现场；先记录实物标签、设备 ID、操作系统和报错时间。

## 批量生产记录

首批可以人工逐盘操作，但必须保留一张不包含私钥的盘点表，至少记录：

- 实物标签/序列号
- 后台设备 ID
- 绑定用户
- 灌装日期与操作者
- Mac 验收结果
- Windows 验收结果
- 交付、库存或挂失状态

凭证 JSON 在灌装并验收后应移入受控的加密存储或安全删除，不要长期散落在“下载”目录；盘点表只记录设备 ID，绝不记录私钥内容。

## 失败处理与升级原则

- 灌装器报“不是空白新盘”：先核对实物和后台归属。不要为图省事绕过保护或覆盖旧盘。
- 灌装中断：工具会清理本次已写入的确定路径；仍需人工检查 U 盘，再格式化后重试。
- 凭证与用户绑错：在后台挂失错误 Key，重新签发新 Key 并重新格式化灌装，不能编辑 JSON 改归属。
- 启动器升级：凭证和启动器是两层。正式提供旧盘升级流程前，内测盘统一回收、核对、清空后重新灌装。
- 源码版本：以 Git 提交号作为生产批次的软件版本依据；未经 Mac 和 Windows 实盘验收的灌装器提交不要合入 `main`。

超管后台本身也要求管理员自己的 ONE Key 在场；管理员密码仅能建立受限会话/修改自己的恢复密码，不能单独打开管理数据或签发新 Key。内测前务必另签发一枚备用超管 Key，离线妥善保管；全部超管 Key 丢失时需服务器运维人工恢复，目前没有无 Key 的自助恢复入口。

## 当前边界

- 序列号是运营标签，不是普通 U 盘可靠的硬件唯一标识。
- 普通 U 盘里的私钥仍可被复制；挂失会让该设备 ID 的所有副本一起失效。
- 当前是“超管创建账号并预绑定 U 盘”，还不是用户收到未绑定 U 盘后自行认领。
- macOS 和 Windows 都不应依赖普通 U 盘自动运行应用；V0.1 保留“插入后双击对应 ONE 图标”。
- 首次双击后会把一个不含私钥的轻量检测器复制到当前用户目录。它把“同一枚 Key 可实时读取并签名”视为在场状态：拔出时立即断开，重新插入、休眠唤醒、临时断网或服务重启后自动重连；只有电脑重启或手动退出检测器后需要再次双击。
- 私钥和完整凭证不复制到电脑本地；每次受保护请求的签名仍直接读取 U 盘中的 `.one/credential.json`。
- ONE Key 浏览器会话默认有效 30 天，但每次受保护请求仍须由当前插着的 U 盘实时签名；延长浏览器会话不会让未插 Key 的页面继续使用。
- Windows V0.2 启动器内置 ONE Local Agent：首次执行选择授权文件夹；读取限制在该目录，写文件和运行 PowerShell 命令需要逐次确认。
- Windows 首版的命令确认不是完整系统沙箱；只应批准看得懂且符合当前任务的命令。正式大规模交付前还需完成 Authenticode 签名与系统沙箱加固。
