# 真实任务反馈闭环修复 · 2026-10-25

## 原始问题与边界

用户报告：原窗口一直显示发送中，而另一个窗口已能看到已落库的调度回复；分派任务因未找到对应日期资料暂停，但主对话只显示接单文案，没有解释阻塞原因。此次从当前线上 `32130ad` 创建隔离工作副本，不覆盖主目录已有修改。前端备份：`/tmp/one-task-feedback-ui-before-20261025.tgz`。

不重跑用户原专栏、不重复写入 Notion，不修改价格、余额、授权或视觉风格。

## 修复合同

1. **接收与恢复**：发送状态以同一提交编号的持久回执为准。网络丢包、单个任务详情超时、切后台、多窗口均不得永久挡住主消息核对；只取回已有结果，不自动重新执行。
2. **日期检索**：固定原任务的时区和日期。结构化日期条件与语义查询分开，按连接器真实能力传递。区分记录创建/修改日期与正文事件日期；有限召回不得宣称全库没有资料。
3. **结果回流**：成功、部分完成、需补充、失败均可报告。主对话空闲时直接报告；忙时合入回复，期间新到结果仍不得遗漏。只有真实保存了含结果的主回复，才标记已报告并让任务气泡回缩。
4. **人能看懂**：讲做成什么、卡在哪、下一步怎么做；不把原始工具错误、调用编号、笼统接单确认当成结果。模型报告不可用时以事实兜底，不让用户等空白。
5. **隔离与幂等**：跨用户/空间不串数据，同一回执只报告一次，已产生文件保留，读过详情不等于已经主对话报告。

## 验收矩阵

| 场景 | 必须证明 |
| --- | --- |
| 发送已完成但任务详情卡住 | 主回复仍更新，发送状态收尾，无重发 |
| 后台恢复/断网恢复/另一窗口完成 | 原编号核对成功，返回内容与状态一致 |
| 昨天的记录 | 上海时区日界、重试不漂移、日期参数或真实能力降级可见 |
| 日期无匹配/部分连接失败 | 不以旧资料冒充昨天，不声称全库没有 |
| 任务成功/卡住/部分完成 | 空闲主动报告，忙时合并，报告后气泡回缩 |
| 多任务/并发窗口/刷新 | 不漏报、不重复报告、不重复业务执行或扣费 |
| 旧结果与新结果交错 | 只确认实际报告的版本，新结果仍保留 |
| 跨账号/空间/授权撤销 | 丢弃旧响应，禁止越权查询和报告 |

## 执行记录

- 定位确认：旧 `refresh` 先等待全部任务详情再查提交回执；无读取期限，一个详情卡住会锁住后续轮询。另旧自动报告仅接收未读成功结果，且禁止空闲报告；失败、缺资料和看过详情的结果没有回主对话路径。
- `useCoordinator` 主回执独立核对，12 秒读取期限覆盖响应正文、30 秒提交响应期限只结束等待、不授权重新执行。结果先到可直接合入，首次列表未返回时也能显示已保存回复；迟到快照不倒退。后台恢复、联网恢复、跨窗口、账号/工作区世代和历史分页缺口一并覆盖。
- 主对话空闲时保存简短事实报告，忙时合入同条回答，不为轮询再增加模型调用。只有包含真实结果的回复保存后，才确认报告并收回任务气泡。失败、部分完成、需补充、停止和中断都进入同一合同。详情已读和主对话已报告分开。
- `interface-design` / `ux-copy` 用于状态完整性、返回后的阅读空间和简短下一步，未改配色、字体或主对话布局。任务短到两次轮询之间已经结束并报告时，也按真实结果返回，不依赖前端看见中间终态。
- 日期检索采用固定请求时间锚点与结构化范围。Notion 从实时工具 schema 决定支持的日期参数；得到大脑现接接口无原生日期参数，不越权改走全库遍历。返回日期候选、正文证据与有限召回诊断，不声称查全。
- 原始任务不重跑，不重复写入 Notion。代码增加新稿缺少必需日期素材的前置判断，避免为了满足保存步骤创建“待素材”空壳；已有文章修改和用户附件不扩大此门槛。
