# 补料自动续办与 Notion 真正更新 · 2026-10-25

## 本轮问题

主对话已经把补充交给同一任务，但后台仍保留 `workPaused`，只能进入任务详情再次确认。用户反复继续后，文章没有变化，结果却持续描述“已保存、部分完成”。

只读核对原任务：共四轮执行，最后两轮为 `task_step_limit`；最新一轮是保存返回后又重复调用保存、参数被拒绝，直至步骤耗尽。上一轮存在保存后才继续查询材料的顺序。原任务没有在诊断阶段被重发、解锁或重复写入。

## 需要统一的合同

1. 用户明确补充材料或要求继续，是新的续办要求，不再额外要求第二次点击。普通状态询问不是开工授权。
2. 等材料、正常部分完成与真正安全阻塞分开：用户停止、未确认外写、本机未结束、连接和授权问题不能靠清一个暂停布尔值绕过。
3. 同一任务串行执行；忙时保留补充，在安全边界接着处理。补充与原目标合并，但不恢复其他任务或重跑已完成部分。
4. 上一轮写入成功只说明旧版本已保存。新要求修改同一文档必须真正写入新版本并回读；不能拿旧保存结果冒充本轮完成。同轮可以在上一写入已经核对后继续顺序修改，当前页和正文随真实回读更新，相同参数仍幂等，不同参数不假复用。
5. 必须用来源材料的写作，先取得材料再保存正文。中间稿与终稿分开；只有明确终稿且本轮写入和回读均确认、其他必需步骤都完成后，才可直接交付，不再多跑一轮只为致谢或重复保存。它不是对文章文风、质量或语义完整性的自动审稿保证。
6. 汇报分别说明实际成果与真实下一步，不复制整段状态为“需要你补充”，也不让用户为了普通续办去找按钮。

## 验收矩阵

- 主对话补料、任务内补料、明确“继续”：无需额外按钮即开工。
- 连续部分完成后有新补充：仍能自动续办，不留下隐藏队列。
- 两个窗口同时续办、同一提交重放：只执行一次。
- 执行中补充 A、B：串行接办最新合并要求，不丢必要限制。
- 普通进度询问、用户主动停止、本机保护、外写不确定：不擅自恢复。
- 旧保存步骤跨轮复制、新正文参数、同轮同参数重复：分别证明本轮真更新、同页不另建、相同写入不重复。
- 已提供新来源材料：不机械沿用旧来源和旧失败目标；必要检索在保存之前完成。
- Notion 真写入并回读后直接交付，不再被无用的后续模型或重复参数调用拖成失败。
- 结果回主对话、草稿保护、气泡收回、跨工作区隔离继续覆盖。

真实验收使用一件新的合成任务，先缺材料、再补充、再修改同一篇测试文档；不拿用户原专栏反复试错。所有测试、部署、实页与正文回读分别记录。
