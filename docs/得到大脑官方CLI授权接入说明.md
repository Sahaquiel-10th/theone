# 得到大脑官方 CLI 授权接入说明

更新日期：2026-09-18。

## 实现选择

ONE 复用官方 CLI 的生产 Device Flow 协议和公开 OAuth 应用标识，不在用户电脑或服务器执行 CLI 命令。知识召回继续经过已有只读 Knowledge Connector。

与本地 CLI 的区别：CLI 默认保存到当前电脑的 ~/.getnote/config.json；ONE 将授权返回的 Client ID 与加密 API Key 保存到准确绑定的工作空间。因此连接随 ONE 账号跨设备使用，不依赖首次授权电脑。不能读取或导入电脑上现有 CLI 凭证来替用户绑定。

官方源码参考：https://github.com/iswalle/getnote-cli/blob/main/cmd/auth/auth.go 。采用的生产应用标识为 cli_a1b2c3d4e5f6789012345678abcdef90。它是公开应用 ID，不是秘密凭证。复用协议的技术可行性不代表得到已正式批准 ONE 云端托管场景；正式大规模发布前仍需确认该使用范围和官方应用稳定性。授权页保持官方身份，不伪装成 ONE 自有应用。

## 配置与兼容

- GETNOTE_OAUTH_CLIENT_ID：新的用户授权入口覆盖项；空值默认使用官方 CLI 生产应用。
- GETNOTE_CLIENT_ID 与 GETNOTE_TEST_API_KEY：仅管理员测试直连使用，不再决定普通用户 OAuth 的入口。
- 生产环境保持 GETNOTE_TEST_CONNECT_ENABLED=false。
- 已保存连接继续使用各自记录的 Client ID 和加密凭证，不批量替换、不清空。
- 授权事务保存发起时的 Client ID，后续轮询不受环境变量变化影响。
- 无数据库迁移、无 U 盘更新。需要部署后端代码，不能仅刷新旧版本网页使改动生效。

## 权限边界

官方 CLI 提供读写命令，但命令清单不等于每枚凭证实际获准的 scope；以官方授权页与平台校验为准。ONE 当前仅调用语义召回及其连接验证，不提供笔记写入、删除或任意 CLI 执行入口。应用侧只读不等于上游凭证本身只读。

## 诊断与验收

已完成：此前失败的会员账号使用官方 CLI 重新授权成功，CLI 搜索返回一条结果。该实验没有连接到线上 ONE。

待生产部署后验证：

1. 普通用户在 ONE 发起连接，确认官方授权页账号，完成授权和知识权限校验。
2. 两个不同工作空间分别授权，搜索各自测试标记，确认不串账号。
3. 同一 ONE 用户换 Mac/Windows，连接无需重新授权；拔 Key 禁止访问保持原行为。
4. 已有连接仍可使用；失效和取消授权仍正确提示。

错误处理修复：未知 token 错误不再误判为用户拒绝；保留错误响应中的上游编号；data.msg=server_error 允许重试。得到官网 confirm 请求仍由其页面处理，ONE 服务端不能捕获该浏览器请求的全部错误。
