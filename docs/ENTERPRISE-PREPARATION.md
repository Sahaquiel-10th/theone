# ONE 企业基础准备（2026-10-10）

## 交付边界

统一域名、统一源代码、统一启动器。服务器根据 ONE Key 的精确用户、工作空间、当前电脑绑定确定身份；企业管理员不获得平台 `admin` 身份。普通个人空间保留原有账号、Key、知识连接、聊天、附件、余额与功能发布记录。

本轮准备公司开户、成员管理、Key 配发及挂失、知识来源授权、企业功能发布、公司电力账户与对公到账记录。真实客户知识库部署、内网连接、部门/文档级权限映射及 Mac/Windows 换 Key 实机验收留到客户确定后的部署窗口。不把自动检查当作客户验收。

## 身份与管理

- 平台超管：管理公司开户、公司状态、协议、功能交付及对公入账；平台接口继续要求超管自己的 Key。
- 公司管理员：`company` 工作空间内有效 `owner` 成员，普通用户身份；管理本公司的成员、权限和 Key，使用公司已交付资源。
- 员工：有效 `member`，默认没有知识和功能授权。额度可限制累计使用电力，未设上限时仍受公司余额约束。
- 散户：未标记 `kind` 的既有空间按 `personal` 处理，不合并客户私人数据。

公司开户创建独立的 Key-only 管理员账号，不发放登录密码。员工首版同样开户新身份；不自动把个人账号、Key 或私人资料转成公司资产。至少保留一名有效公司管理员。

禁用成员保留历史数据、永久挂失其现有公司 Key、消费未兑换登录码，并停止未结束本机任务。恢复成员不恢复旧 Key，需要重新配发。公司只停用，不删除。成员修改按公司 `revision` 防止旧页面覆盖新授权。

插 Key 后登录兑换及 `/api/me` 返回服务端计算的 `access`，确定平台后台、公司后台或工作台入口。每个受保护请求检查成员状态和公司状态。浏览器同时绑定用户、空间及本次身份代次，换 Key 后旧组件不能继续提交，晚到结果不能写入新身份页面。

## 知识及功能

公司管理员授权现有 Knowledge Connector；员工仅可检索 `permissions.knowledgeConnectionIds` 中的本公司来源。正式问答、核心调度、功能执行均传入员工身份，权限在检索返回时再次检查。撤销某员工权限不把全公司共用连接标成供应商故障。

当前权限单位是连接，不是连接内单篇文档。当前各知识供应方仍是一空间一连接；多个同供应方知识库需要适配器支持按精确连接读取并升级唯一键，不可以只新增连接 ID 就宣称已支持。企业内网知识服务必须另做受审核适配器或受控通道，不放开现有私网/DNS 重绑定防护。客户实际资料范围由项目交付时配置。

官方功能保留个人账号发布机制，新增独立 `companyReleases`：每家公司有自己的发布编号和固定版本。修改草稿、认定新版本或交付另一家公司，不自动升级当前公司的版本。全局停用功能会撤下个人与企业发布，恢复草稿不会自动重新开放。

通用功能定义可交付多家公司；企业私有定义设置不可变 `workspaceId`，只能交付所属公司。知识、工具凭证和运行资料不能写入行业通用功能定义。员工功能权限同时要求公司已开通和成员明确获准；公司管理员可用本公司已交付功能。

本轮外部工具凭证继续使用现有使用者专属的加密机制，不自动共享员工凭证。企业共用服务凭证须后续经专属连接适配器接入，仍按公司、地址和能力绑定，不使用全局共享密钥。公司对外分身及公开 API 默认关闭，本轮不提供开启界面。

## 协议、公对公与计费

每家公司建立独立公司电力账户，账户主体为 `company:<workspaceId>`，不冒用老板或员工个人账户。实际模型用量仍保存员工 `userId`，另存公司付款主体 `payerUserId`；扣费账本记公司主体和实际员工 `actorUserId`。模型调用复用预占、真实 usage 结算、待核对、重启恢复和幂等账本。

公司管理员不能记到账。平台确认真实到账后，填写协议编号对应的银行流水、实际人民币金额（分）、协议电力（微电力）；同一银行流水跨公司或不同金额重试拒绝，相同重试不重复加款。协议电力与到账金额的换算记录在当笔到账，不改动全平台模型定价。银行流水需使用含银行/交易识别信息的唯一完整编号。

员工费用从公司共同账户原子预占；成员累计额度同时计算已扣和未决预占。未知 usage 保留公司预占待平台核对，不估算扣款。个人微信充值、手工充值申请、个人赠送路径及公开服务付费不能替公司入账。原有全员内测赠送仅面向个人空间。

公司开户余额为零；重启迁移不得为公司员工自动生成个人余额或体验赠送。当前持久化仍为单实例串行提交，不直接多进程扩容。

## 存储兼容与部署

新增字段存于既有 MySQL 每行的 `record_json`：工作空间公司信息、成员状态与权限、功能定义的私有所属及企业发布、用量付款主体、账本员工主体、对公到账元数据。无需重建表或改写历史迁移，原有工作空间/用户/父对象索引与唯一键继续生效。没有新知识正文同步或企业业务数据查询模块。

不创建真实公司、不灌装或挂失真实 Key、不记真实银行到账、不改变生产价格。版本发布只上线可配置能力；客户部署时再创建真实公司和授权。

## 客户部署窗口

1. 确认协议、付款规则、知识存放位置及资料发送到模型的范围。
2. 开户公司与管理员，灌装管理员 Key；配发员工独立 Key。
3. 接通该客户知识服务，配置员工知识、功能及累计额度。
4. 交付一个明确版本的企业专属功能，记录对公款项。
5. 两家隔离公司、管理员/员工/个人身份、换 Key、撤权、重启恢复及真实模型计费逐项验收。

自动测试与构建属于开发检查；真实 Key、真实知识服务和付款业务验收需分别记录。
