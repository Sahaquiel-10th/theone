# ONE 产品基线

> 状态：MVP 生产基线已存在；本轮内测修复为本地待发布版本，2026-09-14。尚未推送上线、尚未更新用户 U 盘；构建和自动化测试不等于 Mac/Windows 真人实机验收。

## 产品定义

ONE 是一个以硬件身份入口启动的多租户个人 AI 工作平台。用户只需登录一次 ONE、授权一次自己的知识平台，之后即可在 ONE 中让 AI 直接使用这些知识。

得到大脑是首个 Knowledge Connector；Notion 是第一个基于标准 MCP 的只读 Connector。业务层不绑定任何单一平台。

## MVP 用户承诺

> 插入已预绑定账号的 ONE Key，首次在电脑上双击打开 ONE；设置称呼、连接自己的知识来源，此后直接向 AI 提问。当前电脑上的 Key 在场才能发起受保护请求。

## ONE Key 产品结论

- ONE Key 首版使用普通 U 盘，不加入 NFC；NFC 名片只作为“批量生成唯一认领码、首次认领、不可重复绑定”的流程参考。
- 当前 3 人内测：运营人工创建无密码的普通账号，再为每枚 Key 写入相同 Launcher、独立设备凭证和唯一序列号，预绑定用户。用户首次双击直接登录，再授权自己的知识平台。
- 后续再做未激活认领码、手机号验证码/微信认领及用户端生成设备密钥；这些不是本次内测已经可用的能力。
- 一个账号允许绑定多枚 ONE Key，当前通过序列号、绑定账号、状态和最近使用时间区分；外壳标签由运营对应记录，用户自定义 Key 名称仍待补充，不与本轮用户称呼混淆。
- 挂失后设备永久作废，归档筛选与正常列表分开；服务端保留最小安全记录。运营不复用已挂失序列号。
- 普通 U 盘凭证可被复制，首版只作为产品原型安全边界，不宣传为安全芯片。

## Key 使用模式

- **严格模式（当前实现）**：页面可以保留已经显示的内容，但每次读取私人数据、发送消息、召回知识或修改后台前，都必须由当前电脑的 Launcher 重新读取 U 盘私钥并完成一次性请求签名；Key 不在场时该请求直接拒绝，不使用周期性业务签名，也不主动遮盖当前页面。
- 本轮把浏览器 Session、登录码和 Launcher 连接同时绑定到当前电脑本地生成的 `installationId`。Key 移到电脑 B 后，不能替电脑 A 的旧页面证明在场。它是安装身份，不是不可伪造的硬件认证。
- 首次双击后，检测器在同一电脑重插/休眠唤醒时自动重连，页面不必刷新；电脑重启后仍需双击一次。新版服务器要求新版启动器和重新登录一次，旧 U 盘不能只刷新网页完成升级。目标体验须再做两台真实电脑交叉插拔验收。
- **受信任设备模式（后续）**：未来可允许普通功能长期授权，敏感操作仍需 Key；本轮不开放无 Key 的长期使用。
- 普通 U 盘可以被复制，但副本只能克隆同一个设备身份，不能生成新用户、余额或独立 Key。多个副本共享账号和电力；同一设备 ID 只允许一个 Launcher 在线，并记录并发连接异常。真正的私钥不可导出能力留给后续安全芯片版本。

## MVP 前提

- 用户已经注册得到大脑并开通会员；
- 无账号用户暂由 ONE 运营人员逐笔协助注册和开通；
- 用户第一次仍需在得到官方页面完成登录/短信验证/授权；
- ONE 不绕过第三方授权，也不共享多个客户的得到账号；
- 生产基线已接产品方 AI 中转 API，采购 Key 和每用户零售电力账本保持独立。
- 普通用户无需理解模型或 Token；默认直接工作，需要时才在设置中切换模型、查看电力和充值。

## MVP 旅程

1. 运营人工创建普通账号和独立 Workspace，为用户预绑定并灌装一枚或多枚 ONE Key。
2. 用户插入 U 盘，双击对应系统的 ONE Launcher。
3. Launcher 完成设备 challenge，浏览器兑换绑定当前电脑的 HttpOnly Session 并进入 ONE。
4. 首次引导填写称呼；称呼独立于运营开户用户名，之后可在设置修改。
5. 选择连接已支持的知识来源，或暂时跳过；引导进度保存在账号中，换电脑或另一枚 Key 不会重新开始。
6. 用户在得到官方页面完成一次 OAuth 授权；用户不进入开发者后台、不复制 API Key。
7. ONE 按 Workspace 加密保存授权凭据。
8. 已连接用户先问一个其个人资料中特有的问题；服务端实时召回，不建立第三方笔记全量副本。
9. 召回结果作为不可信参考上下文注入 AI；回答持续显示命中、无匹配、未连接、部分失败或失败状态及可展开来源片段。
10. 同一电脑检测器运行时，重新插 Key 后继续原页面；知识授权按账号/Workspace 保存，只有失效、撤销或权限变化时才需要重新处理。

### 首批内测交付方式

- 首批 3～20 人由超管人工创建“一人一 Workspace”的无密码普通账号，并预绑定、灌装 ONE Key；手机号/微信自助认领不阻塞内测。
- 普通用户只能通过 ONE Key 登录。密码仅保留给超管恢复使用，所有超管接口仍要求超管自己的 Key 实时在场。
- 会话、附件、知识连接、模型调用和本机执行都属于 Key 保护范围；没有 Key 时既不能读取私人内容，也不能触发消耗电力的行为。
- 模型请求先预占本次最大电力，完成后按上游真实 usage 结算；上游不返回有效 usage 时进入待核对并保留预占，不估算收费。用户可看到说明，超管核对或免扣后恢复使用。
- 同一次消息提交使用持久化操作编号去重；响应丢失先查原结果，不直接重发模型请求。同一对话不并行处理两条新消息。
- 同一对话的后续问题可继续使用此前用户上传的附件，受文件数/图片数/上下文长度上限约束；未纳入部分会明确提示。这不是长期知识同步。
- 用户可按回答反馈“帮上忙了 / 没解决”，可选说明须明确同意分享；超管仅看用量、有效使用与获准分享的反馈，不看他人对话、附件和知识原文。

## MVP 必须有

- Workspace 数据隔离；
- ONE Key Launcher、设备凭证、challenge、一次性登录码和浏览器 Session；
- 人工开户与 Key 预绑定、一个账号多 Key、挂失归档、当前电脑在场证明；
- 首次称呼/可跳过的知识连接引导、异常恢复与设置中的称呼编辑；
- 得到大脑一键授权、连接状态、重新授权和断开；
- 得到全局语义召回；
- Notion 官方 OAuth 一键授权、只读搜索和页面读取；
- 召回结果注入 AI 上下文并展示来源；
- 模型网关与后续 AI 中转 API 的适配边界；
- 最小运营开户、Key 初始化、挂失和错误诊断；
- 超管模型上架、进价/售价、电力赠送、账单与非内容审计日志；
- 普通用户独立电力账户、充值入口与模型偏好；
- Windows x64 0.3.0、macOS 0.3.0 Universal（arm64/x86_64，构建最低目标 macOS 13），均包含在线安全更新协议 V1；系统实机兼容验收、Developer ID/公证与 Authenticode 仍需单独完成；
- 真实账号端到端验证、跨租户测试和基础监控。

## MVP 不做

- 在 ONE 保存得到/Notion/印象笔记知识正文；
- ONE 自有知识库、定时多渠道同步和本地向量库；
- 状态化 Memory、观点演化、动态知识 View；
- Notion 写入能力、印象笔记等后续 Connector；
- 完整笔记编辑器、文件树和知识整理系统；
- 自动支付到账（首版仅保留充值订单与人工入账）、智能体市场和复杂财务报表；
- 硬件安全芯片级不可复制承诺。
- 自助手机号/微信认领、受信任电脑免 Key 使用；
- 本轮暂缓 Mac Codex 与 Windows Local Agent 的统一，以及附件/密钥在内的完整异地备份改造。现有数据库备份不等于完整灾难恢复。

## 后续产品方向

V2 再建设多渠道内容同步和 ONE 自有知识副本；V3 再引入“文档是视图、知识是活记忆”的 Source/Memory/View 体系。相关理念保留为长期方向，但不得阻塞首版上线。

## 成功标准

- 新用户在人工预开通得到会员后，可以独立完成首次授权；
- 插 Key 到打开 ONE 的主流程可用；
- 严格模式拔出 Key 后的新受保护请求被拒绝，挂失后不能建立新许可；已显示内容不会自动遮盖，已发出的单次上游请求不承诺撤回，但不能再启动下一次付费调用；
- 已连接用户的普通问题可以命中其得到笔记并交给 AI；
- Workspace A 无法使用 Workspace B 的 Key、连接、召回结果或会话；
- 断开/过期后立即停止第三方召回；
- Provider 凭据不进入浏览器、URL、日志或 AI 上下文；
- 一次完整演示不需要打开得到大脑查看或复制笔记。
