# ONE 统一对话与任务工作区设计方案

记录日期：2026 年 10 月 4 日。

2026 年 10 月 6 日补充：[执行交接与任务气泡实施计划](./ONE执行交接与任务气泡实施计划-2026-10-06.md)。涉及上下文交接、输入框执行和完成气泡回流的最新决策以补充计划为准。

本文整理本轮关于统一输入、核心调度 AI、任务便利贴、注意力交接与灵动表达的讨论，作为后续设计和开发基线。目标是让用户一直与 ONE 对话，由 ONE 承接不同事情，而不是让用户管理多个聊天窗口。

当前进入本地 UI 交互预览阶段，不推送服务器，不宣称真实跨任务调度或耐久队列已经实现。本文补充既有《0.4.x核心调度与分身开放实施方案》，不把该文档中的历史实施记录当作当前完成证明。

## 已确定的产品原则

1. 用户只需要表达意图。统一输入框接受连续消息，不要求先选工具、模型、任务，或者点击新聊天。
2. 核心调度 AI 是直接面向用户的对话主体。它理解意图、寻找对应任务、传递消息与必要上下文、选择工具、承接结果。执行 AI 也属于可调度工具，不把每个执行者直接变成用户必须管理的聊天对象。
3. 统一入口不等于统一所有上下文。每件事情拥有自己的对话、要求、执行状态与成果。
4. 主入口采用短回合一问一答：核心调度回复前暂不能发送下一句，但允许编辑草稿。等待的是调度承接，不是任务完成。后台不同任务可以并行；同任务的补充排队，主入口解锁后即可继续提交，不必等待执行者回答。
5. 便利贴表示每件事情的持续承接。画布只是空间隐喻，不做需要用户拖动、缩放、寻找窗口的无限画布，也不复活已否定的技能树。
6. ONE 的眼睛形象是可选表达手段，不是每次动作的必经环节。需要解释任务移动或提供获得感时可以使用；直接展示状态更清楚时就不用。
7. 灵动、调皮、欢迎语、等待碎碎念与彩蛋保留。首页欢迎语在每次进入首页时随机，不隔几秒自动刷新。趣味不能替代真实任务状态，也不能成为必须阅读的操作说明。
8. 输入框与 ONE 在感知上是一体的，位置稳定、独立于具体任务内容。用户输入的是给 ONE 的话，而不是必须先选中的某个窗口。

## 消息归属与上下文传递

核心调度的首要验收不是调用了多少工具，而是本次用户意图是否传给最对应任务。本轮改为整理任务指令后分派，不直接复制主入口原文；原话留在主入口记录，与任务指令用消息标识关联。

| 统一入口的输入 | 对应事情 | 打开便利贴后的呈现 |
| --- | --- | --- |
| 明天干脆去露营吧 | 明天的安排或露营计划 | 创建明天露营安排的任务指令 |
| 好像上次的 UI 我有了个新的灵感 | 既有 UI 设计任务 | 整理新增要求，接上原有讨论 |
| 带上小王 | 最近正在讨论的露营计划，若没有歧义 | 补充同行人员，不因当前展开 UI 而归错 |
| UI 还可以加上这一点，一会补充上去 | UI 设计任务 | 补充指令立即出现，并标记已收到待处理 |

原话和调度信息分开保存与展示。不能整理摘要后删除原话，也不能把入口的全部历史复制进每个任务。执行者默认收到整理后的任务指令、所属任务上下文与必要关联信息。整理必须保留约束、否定、数字、时间与引用，不靠删短来冒充理解；有歧义先确认。附件也必须正确绑定，不向无关任务复制私有资料。本地预览只以固定格式演示任务指令，不声称已实现 AI 语义总结。

核心上下文保持轻量：近期入口消息、近期明确指代、用户当前意图、任务简短索引、进度和待确认项。具体资料、完整任务对话、工具结果与成果放在具体任务内，需要时按权限读取。新任务是独立上下文，不要求抹掉明确授权的通用用户偏好。

归属判断必须尊重消息顺序。后一句依赖前一句时，可以等待前一句完成归属，但不等待前一任务执行结束。界面正在看的任务和用户正在说的任务不是同一个概念，不能仅凭当前展开项决定归属。

高把握时无感分流，并以自然回应或轻量回执确认，例如“接着首页设计那件事改”。确实有歧义时简短询问。用户可以纠正归属；纠正要处理旧任务收到的指令与执行状态，不能只移动界面气泡。发布、付款、删除等高风险操作仍需必要确认。

一句话可能涉及多个任务。需要拆分时，每个任务保留对应要求与原话出处，不能把两件事的完整上下文混在一起。设计上保留原始消息标识与分配记录，支持去重和追溯。

## 同任务补充队列

主入口结束本次调度回合后，用户可以追加要求。完成归属后立即落入正确便利贴，不能因该执行任务正在回复而拒绝发送；主入口本身仍保持短回合串行。核心调度理解意图，确定性任务系统负责可靠排队，不能靠 AI 在上下文中记得稍后发送。

1. 第一条要求开始执行，执行使用确定的一版输入和要求。
2. 后续补充立即显示为已收到待处理，不偷偷改变当前执行快照。
3. 当前轮结束后，队列自动把补充与最新任务上下文送到下一轮执行。
4. 相容的连续补充可以合并成一次执行，但每条原话、顺序和处理状态仍保留。
5. 一会补上去表示允许后续执行；先记着别改表示只保存，不自动运行。
6. 删除要求、撤销、停止不是普通追加消息。应修正待处理内容或请求取消当前执行；已经发生的外部动作不能假装撤回。
7. 失败时保留队列，不把失败产物当作成功上下文继续。需要恢复、确认或重新尝试时明确说明。

完整后台阶段需要持久化、消息幂等、单任务串行控制、重启恢复、有限重试、状态版本和预算约束。外部动作结果未知时先核实，不盲目重试。合并补充是减少重复处理，不是承诺免费执行；计费沿用实际模型及工具调用记录。

灵感夹不作为用户必须学习的新入口。其能力内化为任务补充和暂存：用户直接说，ONE 负责接住。任务内可以按需看到待处理要求，不建立另一套需要手工归档的体系。

## 完成事件与交付简报

执行任务返回完整成果、简短交付说明、待确认项及任务和成果标识。完整成果留在对应任务，交付简报尽量由执行者同轮输出。简单完成通知可直接展示，不必额外调用调度 AI；综合多个结果或结合新问题时才由调度 AI 组织，必要时按权限读取成果，不默认全文重写。

完成事件先保存为待汇报，不注入正在生成的主入口回复。用户编辑草稿时只弱提示，不向 AI 发送未提交草稿。用户发送后，将已发送原话与相关待汇报简报作为新的调度输入；没有进入该轮快照的新事件留给后续，不中途改写输入。主入口空闲且无草稿仍不自动展开成果或抢占阅读；用户返回或主动查看时可汇总。

汇报优先承接新消息，无关成果只给轻量入口。完成通知按事件标识去重，汇报不等于成果已读。执行失败或停止不显示完成。闲聊不作为抢占当前界面的依据。

## 工作区与注意力交接

建议布局由三部分组成：稳定的 ONE 与独立输入框、当前展开的事情、收起的其他事情。只展开一个主要工作区，其他任务保留稳定标识和可找回的入口，不靠自动重排制造找不到原任务的问题。

便利贴既能查看对话，也能呈现成果。文章、方案、表格等在能力支持时作为成果主体呈现，不强迫每件工作都以长聊天记录为主；本轮不因此承诺开发通用文档编辑器。

| 时刻 | 表现目标 | 不允许的表现 |
| --- | --- | --- |
| 正在输入 | ONE 可以轻微关注输入区，输入与焦点保持稳定 | 跟随每次击键抖动，突然切换任务 |
| 消息发送 | 接收回执清楚，必要时短暂引导消息到对应便利贴 | 飞行动效代替实际接收成功 |
| 当前任务等待 | 碎碎念归属于当前任务，实际状态可辨认 | 在历史任务区出现当前任务的等待文案 |
| 其他任务完成 | 弱标记或可忽略的结果入口 | 挤掉当前内容、抢焦点、强制滚动 |
| 正在等待该任务 | 在其工作区展示结果，允许继续修改 | 结果出现在不相关任务内 |
| 用户回来 | 汇总完成与待确认事项，允许选择查看 | 自动把所有结果展开成长页面 |
| 恢复旧任务 | 保留阅读位置，提示停在哪和下一步 | 必须重读全部聊天才能继续 |

提醒有结果和展开结果是两个动作。用户打字时最多弱提示；正在处理其他事时不抢占；用户明确等待该结果时可直接呈现；用户回来时可以递简短进度汇总。闲聊不代表可以抢占注意力，不能用“没正事”作为自动切换的可靠依据。

完成结果留在任务中，统一入口可递摘要和查看入口。已收到、排队中、执行中、完成、失败和待确认必须有真实含义。不能把读取本机任务状态的能力误称为所有任务均已实现后台队列。

## ONE 的灵动表达

角色帮助用户理解与感知承接，不要求每次调用都经过眼睛动画。视线、形变、文字、任务条和结果卡是可组合手段。

普通移动就近、平稳，中间到侧面的移动不仓促；不以随机速度、停顿、反复探头作为常规工作动效。只在确实需要横穿全屏的特定左右切换中保留从边缘离开再出现的趣味表达。最上方功能入口的半露小形象不影响文字居中和点击区域，工作中不主动争夺注意力。

本轮固定路线：功能到设置、设置到功能必须从侧面离开、从另一侧探头出现，不再依赖宽度或距离阈值。首页到功能向上消失，再从功能所在侧上方落下。首页到设置保持直接、平稳移动。减少动态效果时直接切换页面。旧 bug 原因是选定边缘路线后，距离阈值再次否决路线并退回直线，现已移除该特殊路线的阈值回退。

## 事情列表与结果灯泡

顶部增加事情入口，作为完整记录的常驻位置。左侧是可搜索、分页的事情列表，右侧是选中事情的完整对话；本地预览允许直接向该事情补充，与 ONE 主入口的短回合、草稿及当前工作台分开。放到工作台是另一个明确动作，不能因浏览列表而替换当前任务。

工作台持续承接与 ONE 的对话，没有选中任务时呈现手头事情；分派后不自动打开新任务。任务完成在 ONE 旁显示灯泡，点击打开结果列表，再点具体事情才替换工作台。不修改统一输入草稿，不抢阅读位置。灯泡再点或关闭后彻底收起同一批提醒；未点的提醒二十秒后收起，结果仍留在事情列表。新的完成轮次可以再次提示，不把收起提醒等同于删除或已读成果。

采用独立任务可直接查看和干预的交互原则，参考 [Dot 任务与上下文官方说明](https://learn.chatgpt.com/docs/dots/tasks-and-memory)。灯泡和固定移动路线是 ONE 的产品设计，不宣称是 Dot 的现成实现或内部算法。

欢迎语每次进入首页随机一次；等待碎碎念和现有彩蛋方向保留；用户可见文案称 ONE，不称眼睛。趣味文案不伪造查资料、委派其他 AI 或完成执行等事实。尊重减少动态效果设置，动效取消后仍能完整理解状态。

设计假设是有意义的回应和交接能帮助注意力恢复，不声称通过光标、停顿或动画识别或制造心流。用户等待回复不等于注意力空闲。科学讨论用于启发设计，不作为效果已获证明的声明。

## 功能入口与既有边界

功能模块主要用于认识、开通、授权和管理 ONE 的能力。未来可用能力进入调度目录，用户不必每次先寻找工具；手动指定与查看入口仍保留。购买、企业专属权限与工具授权由服务器验证，不能只凭 UI 显示就成为可调用能力。

本轮不改变个人工作台 Key 在场原则，不修改启动器、计费、支付、模型生产配置或公开分身权限。公开分身原有只问答与附件边界保留，不因统一入口获得主人的本机或其他执行能力。所有任务、消息、结果和纠错记录仍要求服务端 workspace 授权，管理员不能借调试入口查看其他用户原文。

## 现有前端观察

2026 年 10 月 4 日只读检查可确认已有可复用组件，不代表新方案已完成：

- `src/main.tsx` 有工作区、ONE 指挥台、独立输入区域、其他事情、结果回执和手动新事情入口。
- `sendMessage` 当前按 `targetConversation` 发送，并在目标正在加载时直接返回。因此当前路径不能直接满足自动跨任务归属和同任务连续补充，需要后续适配，不能仅隐藏新事情按钮。
- `src/oneTaskAttention.ts` 已有按对话选择执行任务、任务动态、完成转换与已读判断，可复用状态能力；不等于已有耐久补充队列。
- `src/OnePersonality.tsx` 有欢迎语、等待文案与彩蛋；欢迎语按 context 变化更新。后续要核对首页进入的触发边界，确保不定时刷新欢迎语。
- `src/OneCompanionEye.tsx`、`src/oneEdgeMotion.ts` 有角色和移动基础。普通路线仍存在可选中途停顿，需按新原则收敛，不完全重做角色。

## 本地 UI 实施计划

本阶段在原工作台里接入隔离、合成数据做前端交互预览，不调用生产模型、支付、真实知识库或用户任务，不写入生产记录。预览复用正式界面，模拟发送路径与正式发送路径分离，保留已有未提交 UI 改动。不得另做一套缺少原导航、角色交互和样式的外壳。

| 阶段 | 实施内容 | 用户能预览的效果 |
| --- | --- | --- |
| 一 | 明确输入入口、聚焦工作区和其他任务的布局与状态 | 始终知道从哪里说话、当前在看哪件事 |
| 二 | 建立消息接收与任务归属的前端状态模型，连接显式演示路由 | 露营与 UI 两条原话分别落入各自最新对话 |
| 三 | 演示主入口短回合与同任务补充队列、暂存和停止 | 调度回复前等待，承接后恢复发送，不等后台完成 |
| 四 | 演示并行完成、弱提醒和重新进入后的汇总 | 新结果不抢当前内容，回来可以继续旧任务 |
| 五 | 将角色、碎碎念与必要交接动作接入上述状态 | ONE 有趣但不抢占，动效与任务状态一致 |
| 六 | 验证宽窄屏、键盘、减弱动效、滚动与焦点，交付本地预览 | 可以完整试三个场景，不需上线 |

演示路由只能使用明确标为预览的固定场景或可控规则，不假装理解任意用户意图。暂存在浏览器的演示状态与真实服务端耐久恢复分开标注。真实路由、队列和计费接线在 UI 方向确认后实施；不把演示通过当作真实 AI 调度通过。

提供调度延迟、执行延迟、暂停自动执行、手动完成或失败、重置等调试控制。延迟只模拟等待，不做生产模型调用。未知意图明确说明预览识别边界，不假装成功归属。首版是否支持刷新恢复按实测记录，不把页面内返回当作耐久恢复。

## 本地预览验收场景

1. 单任务：输入 UI 要求，接收，等待，看到结果，再补充修改。输入框始终可用，等待与结果属于同一任务。
2. 交替任务：先说露营，再说旧 UI 灵感，再回到露营。分别打开便利贴，原话与回复各归各位；当前查看项不强行决定输入归属。
3. 补充队列：UI 第一轮未结束时连续输入两条补充。原话立即出现在该任务中，下一轮处理补充；另一个任务可同时推进。
4. 暂存与取消：先记着别改不执行；不要第二点修正队列；停止有反馈，不声称撤回已发生动作。
5. 结果到达：编辑输入、阅读其他任务时收到完成事件，焦点、草稿、滚动位置均不改变。主动查看才展开。
6. 返回工作：离开演示再回来，汇总与任务归属可恢复；此测试只证明预览状态恢复，不证明后台恢复。
7. 错误与歧义：演示归属询问、纠正、失败和重复提交，不能重复落消息或用完成动画掩盖失败。
8. 可访问性：窄屏不出现拖画布才能找输入的情况；减少动态效果时功能完整；欢迎语不自动定时变换。

评估优先回答四个问题：这句话去了哪里，事情到哪一步了，我回来从哪里接着做，下一步需要我做什么。灵动和美观一起调，但不能替代这些验收。

## 后续真实调度阶段

UI 确认后再设计入口消息、分配记录、任务内消息、要求版本和执行轮次的服务端数据路径，追加迁移；复用既有权限、调度目录与账本，不另造互不相通的执行系统。

## 正式接线与联合上线计划（用户确认 UI 后）

用户已接受本地 UI，要求先完成真实调度、独立任务 AI、管理员提示词配置与现有功能验收，再联合上线。此节是新实施计划，不把上述演示计为正式功能。

### 当前核对结果

1. 现有 AI 任务配置中心支持模型、预制提示词、工具调用说明、草稿、发布、历史、回滚与修订冲突校验；官方功能配置支持独立模型、指令和受控 MCP/API 工具。
2. 正式 `/api/chat` 的现有 orchestrator 在当前聊天里执行知识检索/联网，并不分派到独立事情。附件和图片仍走原流程。不得将开启此配置当作新版持续主对话已经接通。
3. 主对话、灯泡、跨事情队列和多选功能目前仅在开发预览启用，刷新后演示记录重置。正式版不能开放此演示开关或合成卡片冒充真实执行。
4. 分享问答/API、访客账号与既有账本、正式官方功能试运行/灰度链路继续保留，不能重做而丢失权限/预算/幂等防线。
5. 首批实改：七种现有任务的预制提示词已补充；无发布覆盖时，运行时实际采用后台显示的预制模板。已发布配置不自动覆盖，包含有意留空的提示词；不自动启用旧调度、改模型或改价。正式目录空状态改为“即将上线”，筛选空结果保持“没有匹配的功能”。

### 一个主体，多种独立执行器

- 核心路由角色是持续沟通的 ONE，登记为与旧检索 orchestrator 不同的配置。负责普通交流、创建事情、继续事情、提出必要澄清及交接摘要，不依赖完整长任务原文作主入口上下文。
- 每件事情持有独立执行器配置引用：管理员维护的模板 ID/版本、模型、提示词、允许工具、知识使用规则、步数与预算策略。未明确选用专业模板时使用通用执行器；它不是第二个核心调度 AI。
- 官方 skill 是专业行为与能力包，不等于模型。一个任务可选择多个 skill，但由一个执行器承接，不能给每个 skill 复制同一句话各扣一次费。工具定义冲突须拒绝或用命名空间区分；多技能的权限不能简单扩大为全部来源和工具的并集。
- 外部 API/MCP 接入只提供经审核能力；不能在后台任意上传代码执行、绕过域名或私有网络限制。不同模型选择继续复用现有供应商配置及统一定价，不重复填写费用。
- 任务固定每轮配置快照；后台更新只影响后续轮次。停用模型、撤销知识/工具授权立即阻止后续步骤；不能靠旧快照延续已撤销权限。

### 核心调度配置与交接

后台应分为持续对话、任务执行器、辅助 AI 三组，复用现有详情编辑和版本发布方式。辅助 AI 包括交接整理、附件整理、执行指令编译、图片生成、分享问答；新增 AI 调用必须登记。平台权限和参数验证不是可编辑提示词。

核心可编辑项：模型、行为提示词、已注册操作的调用条件、允许的执行器/skill、步骤与预算策略。运行时动态注入经过服务端授权的候选事情及已连接知识目录，不把某个用户的目录写进全局提示词。

建议首版路由动作：直接回复、创建任务、继续任务、澄清。每个交接含目标事情、摘要指令、选择的执行器/skill、必要来源引用与用户原消息引用。服务端独立验证 ID、用户/空间、当前授权及参数后才能提交。正文里的任意 ID、他人任务、知识内容中的命令均不能授予权限。

原话完整存于对应事情最新消息；执行 AI 收到本轮交接摘要、该事情自己的上下文及必要原话，不能混进另一件事。主入口只看最近短对话、事情摘要/状态、显式指向和未读完成元数据。自动归属不确定就问一个问题；手动指定事情优先，查看事情本身不等于绑定输入。

首版不允许一句话默默拆成无限多任务；限定少量动作并且校验后逐项记录。不开启未经确认的发送/发布/删除等写操作。

### 持久化和执行规则

- 主入口短回合串行，接收到分派回执即可继续；执行任务之间有限并行，同一事情严格串行。补充保留原话，进入下一轮，不能修改正在执行的输入快照。
- 路由回执、任务指令、用户消息关联、队列状态、执行快照、模型费用和完成事件均持久化。复用既有 Store 与账本；新表如有需要采用追加迁移，部署前只读预检。
- 幂等键覆盖路由及分派，不因重复点击创建两件事或重复计费；重启不自动重放状态未知的模型/外部调用。未开始的队列可恢复，但只能在满足当前 Key/授权后运行。
- 个人入口拔 Key 后拒绝新消息和新模型步骤；已明确调用的外部工具按既有规则继续，不擅自停 WorkBuddy 等应用。公开分身/API 不接入私人核心路由和任务工具，维持只问答/授权知识/会话附件边界。
- 完成事件默认仅点亮灯泡，不替换用户正在阅读的事情，不主动塞长结果进信息流。原结果留在任务里；可选简报只处理短结果摘要和产物引用，不重复读一遍完整答案。
- 未发送的草稿不上传给调度模型。用户发送时才附带必要待通知摘要；后台任务完成不得触发偷读草稿、自动发送或自动清空输入。
- 全局后台只看配置和运营元数据；完整路由上下文/工具结果调试仅本人持 Key 可看，超管不能读其他人的原话。

### 2026-10-05 上线前核对

九类 AI 任务均有非空预制提示词，后台显示与实际默认调用一致，发布覆盖（含空提示词）继续保留；新增逐项模型绑定和发布回归。核心通过 `delegate_task` 选择执行器，执行器持有自己的模型、提示词、允许工具及固定轮次版本，属于“执行 AI 作为受控工具”的首版，不等于任意模型可以绕过权限直接被调用。
