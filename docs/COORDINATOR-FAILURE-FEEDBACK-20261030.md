# 主对话失败反馈与可用结果保留

## 本轮目标

不再把不同故障都归为“看看刚才那件事”。用户应能看出失败位置、已知进度和具体下一步；语气自然、带一点 ONE 的猫感，不能用玩笑掩盖事实。

## 实施范围

1. 服务端保存安全、结构化的故障分类和阶段；回执与错误响应共享该分类。保留操作完成与业务交付的区别，不记录供应商原始错误、密钥或其他租户资料。
2. 模型服务失败明确说明模型暂时没有回复；功能、预算、电力、Key、知识授权、配置错误分别说明修复入口。不再要求用户反复发送含糊的恢复暗号。
3. 能读的截断正文保留并明确未写完；残缺工具参数、过滤内容、不可解析响应不得作为可执行指令或成功成果。保留真实计费与授权检查，不增加自动重跑或自动补扣。
4. 修复提交异常后的回执状态覆盖：已完成优先；处理中继续核对；失败/停止保留确定的原因；本机与云端遵守同一状态原则。校验回执结构，网络/协议故障不冒充业务失败。
5. 故障恢复保留用户原输入及附件/功能引用（按账号与工作区隔离），明确尚未收到确认的边界。

## 验收合同

- 服务端：HTTP 400/401/403/408/429/5xx、空结果、截断正文、残缺工具指令、步骤/工具上限、电力预留不足、权限变更、结算与保存异常，各有明确反馈。
- 前端：提交失败 × 回执 completed/pending/failed/interrupted/404/超时/无效结构，覆盖云端与本机；已确认 completed 后再次断线不能恢复失败提示。
- 安全：没有新的自动付费调用或重复外部写入；跨工作区故障与草稿不得混用；授权撤销后不得展示新取回的私有结果。
- 必须执行类型检查、相关单元/集成测试、生产构建、diff 检查；提交推送并检查部署和线上健康。合成/浏览器状态测试与真实供应商/外部写入验收分别报告。

## 不在本轮变更

不调生产价格、余额、套餐，不重跑原用户任务，不解除未知副作用保护，不把计费结算失败变成免费交付，不改启动器版本，不读取公测用户私人聊天。

## 实施与验收记录

- 故障使用白名单 `code/stage/outcome`，与回复是否持久化分开。Key、登录、知识授权、额度、账单核对、功能配置和模型错误分别反馈；不展示供应商原始错误。
- length 正文原样保留；工具前言与正文区分，残缺工具指令不执行，也不提供正文续写入口。过滤内容、工具参数不作为部分正文落库。
- 嵌套功能返回的部分正文与故障分类写入原步骤，同一轮换措辞不再次购买该已返回结果；有故障的回复不能被当作 Notion 原稿。
- 本机与云端的 pending 均继续按原提交编号只读核对。已确定完成或失败不会被随后网络异常覆盖。确认终结的失败重试使用新编号，查无接收记录时才以相同完整参数沿用旧编号。
- 草稿按账号和工作区隔离，仅在本浏览器会话存原话与引用，7 天、最多 20 条；不存文件正文或凭证，恢复附件/功能需当前账号重新校验。
- 聚焦后端、计费、权限与调度集成 284 项通过；最终全量、合并最新线上分支、构建和发布核对另记，不以该数量替代业务验收。
- `scripts/qa-coordinator-failures.ts` 的浏览器验收经过真实 `CoordinatorService.dispatch`、真实 hook 和对话组件，只注入合成模型响应及网络故障，不直接伪造完成记录。
- 浏览器已验证 503、401、可读截断正文、残缺工具前言，以及丢 POST 确认并暂断 GET 后找回原正常结果。恢复 GET 前后模型调用数不增加、外部写入为零。浏览器网络层可能重送同一 POST，服务端依原编号去重，不能把 HTTP 请求次数当执行次数。
- 电力不足的浏览器验收未增加模型调用；最终重启加载修复后再次验证工具截断，无正文续写标记、无新子任务、无外部写入。
- 截图与 CLI 状态证据在忽略目录 `output/playwright/`；均为本地合成，不是生产用户或真实供应商故障现场。
- 合并最新线上教学功能分支后：全量 1,973 项，1,972 通过、0 失败、1 项既有 110 MB PPT 压力测试跳过；TypeScript、生产构建、diff 检查通过。构建仅有既有大 chunk 提示。

### 验收边界

故障提示、去重、授权、结算和结果保留可用合成故障确定性验证；本轮不声称消除供应商超时、限流或接口故障，也不通过重复付费调用模拟可靠性。新旧业务都应继续观察真实交付结果，不能用 HTTP 200、服务健康或测试总数推导任务完成率。
