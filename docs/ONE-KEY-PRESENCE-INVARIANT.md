# ONE Key 在场体验硬约束

状态：不可回归

这份文档不是功能设想，而是 Launcher、Bridge、在线更新、灌装器和服务端都必须遵守的产品底线。任何新功能都不能以破坏以下体验为代价。

## 用户可见行为

1. 用户在一台电脑上首次双击 ONE 后，Bridge 留在本机等待这枚 Key。
2. Key 插着时，ONE 可以登录并执行需要身份、知识或电力的请求。
3. Key 拔掉后，下一次受保护请求必须在调用知识库、模型或读取私人数据之前被拒绝，并提示插入 ONE Key。
4. Key 拔掉不强杀已经交给外部工具的独立任务；但 ONE 不再派发新的受保护步骤。
5. 同一枚 Key 再次插入后，Bridge 自动发现并重新连接。用户不需要刷新网页，也不需要再次双击 U 盘图标。
6. 电脑休眠、唤醒或网络短暂中断后，只要 Key 仍插着，Bridge 自动恢复连接。
7. 双击已经有 Bridge 驻留的 Key 只负责重新打开登录页面，不能再创建第二个驻留进程。

## 实现约束

- 每台电脑、每个 `deviceId` 同时最多有一个 Bridge；Mac 使用本机排他锁，Windows 使用命名互斥量。
- 服务端对同一 `deviceId + installationId` 保留同版本或更高版本连接，拒绝重复或降级连接；新版可以接管旧版。
- Bridge 在 Key 缺席时保持低频等待状态，不退出、不持续枚举所有移动磁盘，也不反复触发系统权限提示。
- 插入检测和请求前的即时签名共同构成“在场”；浏览器 Cookie 不能替代 Key。
- 在线更新只替换 Launcher/Bridge，不得修改 `.one/credential.json`，也不得绕过上述单实例和自动恢复约束。
- 灌装验收必须检查双平台版本、更新协议和同一发布公钥，但不得通过启动多个 Bridge 来验证。

## 每次 Launcher / Bridge 变更的必测项

- [ ] 首次双击后可以登录，且本机只有一个对应 Bridge 进程。
- [ ] 连续双击五次仍只有一个 Bridge；每次都能打开登录页面。
- [ ] 拔掉 Key 后，发消息在模型和知识检索前被拦截。
- [ ] 拔掉 Key 后，已经交给外部执行器的独立任务不被强杀。
- [ ] 重新插入并等待数秒，无需刷新或双击即可继续发消息。
- [ ] 休眠并唤醒后，无需刷新或双击即可继续发消息。
- [ ] 挂失后即使 Key 插着也不能恢复。
- [ ] Mac 不连续弹出可移动宗卷权限框；Windows 不生成多个后台进程。
- [ ] 在线升级后重复以上全部测试，而不是只验证版本号变化。

任何一项失败，都视为阻断发货的问题。
