# 0.4.x 剩余功能实施

用户授权完成本版功能，真人体验集中验收。先完成实现、必要自动回归并部署。新收费政策需管理员显式配置启用，不自动替现有分身改价。

1. 对外 API：主人持 Key 为已发布分身签发独立密钥，绑定版本、到期、总额度和单次额度。只存哈希、只展示一次；支持撤销。异步问答、幂等提交及结果查询复用分享执行器，API 每个问题独立，不继承其他问题历史，不提供本机或外部工具。
2. 访客账号：账号＋密码，使用独立会话 Cookie，不能用于私人工作台认证。账号与现有 ONE 用户体系共用，购买 Key 后仍用同一账号。无自动注册赠送，后续快捷登录与增长奖励另做。
3. 访客自付：发布者显式选择主人请客或访客自付并填写百分比；0 表示主人承担。大于 0 按平台实际模型费用倍率扣访客余额，低于 100% 的差额由主人承担。每次执行固定发布版本与倍率，限额覆盖实际模型调用。
4. 账本：充值本金、赠送、预留、消费与发布者待结算收益分开。旧余额缺乏本金来源时保守归非收益余额；新充值按已核验支付本金记录。赠送消耗不生成收益。充值不计发布者收入。收益仅来自实际已结算消费的本金部分，暂不提现，不自动转入发布者可消费余额。
5. 访问与赠送：可要求登录并指定访客账号；主人可为指定访客设置使用赠送额度，使用额度由主人承担实际成本，不向访客钱包凭空充值。
6. 官方功能仍由官方配置、认定和指定账号上架；创作者收入与提现不自动开放。计费策略后台可配置，默认保持当前运营状态，所有新价格启用留审计。

自动验收覆盖密钥撤销、Key 管理权限、跨空间/会话/结果隔离、幂等与并发预算、异步恢复、付款人及本金/赠送拆分、收益幂等、旧免费分享兼容、部署健康。真实支付不自动发起。

## 本批入口与验收边界

- 超管：管理 → 官方智能体 → 访客付费与收益政策。默认关闭；管理员主动确认后，发布者才可设置正数收费比例。停止政策会阻止新的付费调用，不撤销已实际发生的消费。
- 发布者：功能 → 我的分身 → 编辑，设置收费百分比、登录要求与允许账号；同一链接发布新版本。分身列表的「API、访客赠送与收益」管理独立 API 密钥、定向赠送额度和分页收益记录。
- 访客：直接打开分享链接；免费匿名分身仍可直接问答。需要身份或自付时，在同页注册/登录、充值，确认当前版本费率后提问。每条回答显示本人实际已结算电力；账号与余额以后购买 Key 仍沿用。修改密码撤销其他访客登录；忘记密码当前由运营协助，尚无短信/邮箱自助找回。
- 程序：`POST /api/v1/tasks`，Bearer 独立 API 密钥，传 `question` 和 16–80 位英文、数字、下划线或连字符的 `operationId`。返回 task.id；`GET /api/v1/tasks/:id` 查询，`POST /api/v1/tasks/:id/cancel` 取消后续步骤。重试保留同一编号，改变问题换新编号。API 首版仅文本问答、每个问题独立，无附件上传；网页分身原附件流程不变。
- 密钥只展示一次，只存哈希；创建另一枚即可轮换，随后主动撤销旧密钥。更新分身后旧密钥拒绝运行，需签发绑定新版的密钥。每分身最多 50 枚密钥记录；每密钥会话最多 100 个问题，沿用公开入口限流。
- 账本存既有服务器数据库，新增字段随记录持久化，不需要新增数据库或手动迁移；重启测试覆盖计费政策、访客密码版本、API 哈希、本金和收益。旧余额不改总额，只是不凭空认定为可分成本金。

仍待人工集中验收：Mac/Windows Key 实机拔插、真实知识来源质量、真实外部 MCP/API 兼容性、浏览器交互与真实微信小额支付。自动回归不是这些体验的替代。官方功能的行业套餐购买、创作者收益分账、提现、增长奖励、微信登录属于后续产品阶段，本轮不自动开放；官方配置与指定账号上架已可用。
