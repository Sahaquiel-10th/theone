# 官方精选功能体系与标准接入规划

状态：2026-09-28 用户确认并授权分阶段实施。阶段 A 先开发官方后台配置、版本认定、停用与审计；不开放动态执行和新收费。本文中的后续阶段不是已上线功能说明。

## 1. 已确认的产品边界

- ONE 不做任何人上传后即可公开售卖、完全依赖创作者自行负责的开放市场。至少早期采用官方筛选、测试、认定、上架与持续维护。
- 作者可以是官方、行业合作企业或受邀创作者。官方认定不等于官方原创，不保证永不出错，需展示适用范围、局限和版本。
- 统一账号，网页访客轻量验证后使用与充值；Key 绑定原账号，个人工作台仍须插 Key。发布、管理权限沿用 Key 边界；访客不因此获得主人的本机能力。
- 功能包括专家分身、企业行业包、精选通用智能体。可以由提示词、知识范围、工作流、标准工具和远程服务组成，不限于提示词或 Skill 文件。
- 可见范围、付费主体、知识范围、工具权限分别授权，不由一种配置隐式推导另一种。
- 公开分身维持只问答及访客附件；未来其他功能的云端动作需独立审核授权，不能扩大既有公开分身的权限。
- 创作者收益按实际消费及结算规则形成，不是充值即归作者；充值本金、赠送、运行成本、待结算收益分账，暂不自动提现。

## 2. 已确认的审核范围

官方功能目录、企业目录及创作者售卖必须审核。现有个人分身链接不是官方目录条目，不能被标为官方认定。

个人分身独立：每个人可以创建并分享自己的分身，自己负责，不进入官方功能上架审批；仍须遵守平台权限、安全和费用边界。默认不进入官方目录，不标为官方认定。每个人的私密知识不交给超管全面阅读来审核。

创作者通过活动或比赛报名，官方与其线下接触、收集材料后，由官方在后台配置和接入。不开发创作者上传、在线提交、送审工作台，不让创作者拥有平台接入与发布权限。已有个人分身链接不受官方目录流程影响。

## 3. 技术选型：功能包不是通信协议

推荐统一 ONE 功能包作为产品单位，MCP/OpenAPI/内部适配器作为接入方式。不要二选一，也不要为每个工具再造协议。

| 层 | 用途 | 初期范围 |
| --- | --- | --- |
| 功能包 | 用户看到的完整任务：输入、输出、说明、版本、依赖、权限、费用 | 配置型，官方管理 |
| MCP 接入 | 发现并调用远端工具，获取参数/结果结构 | 审核的 HTTPS Streamable HTTP 只读工具，明确兼容范围 |
| OpenAPI 接入 | 从 HTTP API 定义生成候选工具、表单和参数校验 | 明确支持的 OpenAPI 3.1 JSON HTTP 子集；不宣称支持所有接口 |
| 内部适配器 | 特殊鉴权、多步请求、CLI、厂商特有语义 | 工程师审核开发，统一执行合同 |
| 对外 API | 别人的系统调用 ONE 的已授权发布功能 | 后续明确独立客户端身份、版本、额度和任务回执 |
| 对外 MCP | 其他支持 MCP 的助手把 ONE 的发布功能当工具 | 建在对外 API/统一执行合同上，不开放私人工作台 |
| A2A | 与独立外部 Agent 系统交接任务与状态 | 预留适配位置，不在首批实现 |

Skill 是指令/资源组织形式，不是天然的远程调用协议，也不是安全沙箱。初期仅导入审核的文本指令、资源引用和已批准工具依赖；不执行上传包中的任意脚本。

“标准接口免改后台”的承诺只覆盖已支持的参数类型、鉴权和传输；导入只产生候选草稿，仍要授权、字段映射、样例验收、官方审核。特殊签名、复杂上传、异步状态机等超出范围时，需要新增适配器，不能伪装为接入成功。

## 4. 两个方向独立建设

### 外部能力进入 ONE

管理员导入标准定义/填写受信任 MCP 地址 → 解析候选工具 → 配置凭证引用、输入输出映射 → 自动测试 → 人工审核 → 指定灰度范围 → 发布功能。

一个数据查询 API 是工具，不自动成为完整智能体。需再组合任务说明、输出要求、必要模型/流程、错误处理和费用，才是用户可用的功能。确定性任务无需额外套一层模型；不可为了“智能体”标签增加无用模型调用。

### ONE 进入外部系统

外部业务系统通过 API 调用 ONE；支持 MCP 的系统通过 ONE MCP Server 调用；网页嵌入只解决界面嵌入，授权和费用仍走同一后端。平台原生插件可以封装这些接口，但不是接通所有系统的万能安装包。

不能把个人 Key 凭证给外部系统。对外凭证单独签发、绑定发布版本/使用者/付款主体/范围/限额，可撤销。外部传入的 userId/workspaceId 不构成授权。

## 5. 功能包建议字段（设计，不是现有 API）

- 标识、名称、作者、维护者、版本、兼容版本、适用任务与不适用场景。
- 输入/输出 JSON Schema、样例输入与验收结果、产物类型。
- 执行模式：模板问答、确定性流程、受控调度、远程服务。
- 模型及提示词版本、依赖工具的批准版本/定义摘要、知识访问范围、数据发送目的地。
- 风险等级：只读、生成产物、外部写入/发送、破坏性操作、本机动作；不可仅相信供应商自报标签。
- 可见范围、企业资格、Key 要求、逐次确认要求。
- 价格版本、付款策略、预算、步骤/时间/结果大小限制、重试及幂等策略。
- 审核证据、审核者、发布时间、灰度范围、回滚目标、全局停用开关。

凭证仅存服务端加密存储，包内只能使用凭证引用；每个用户/企业绑定自己的授权实例。不能在导入包中携带可直接使用的共享密钥。

## 6. 统一执行合同

上下文由服务端解析：主体、所属空间、企业资格、入口、发布版本、付款人、授权连接、允许工具、请求幂等键、超时/预算。

输入验证 → 当前授权检查 → 预算预留 → 工具/模型执行 → 结果及副作用确认 → 费用结算 → 任务回执。

结果区分完成、失败、中断、等待用户确认、状态未知；超时不等于没执行。读取请求只在供应商允许时重试；写入、发送、支付等不能盲重试。供应商不支持幂等或状态查询时，必须显式降级为待核对。

统一记录调用来源、工具版本、耗时、状态、外部请求号与用量。普通运营只看元数据，创作者不得查看用户知识原文。超管调试默认仍只看本人资料；评测用公开/合成或明确授权的测试集。

## 7. 安全底线

- 上传/导入/发现工具均不等于批准执行；工具描述、网页、MCP 返回值是数据，不是高优先级指令。
- 地址 allowlist、DNS/重定向复检、禁止云元数据/内网目标、连接和响应上限；禁止通过 OpenAPI 外部引用绕过网络策略。
- MCP 工具清单及 schema 漂移先隔离新增或变更能力，不能自动授予旧功能。即便固定定义，也不能保证远程实现不变，仍需运行监控、回归和停用。
- OAuth 授权绑定用户、客户端及准确资源；不透传另一个服务的 token。标准化不了第三方资格申请、scope 审批和用户同意。
- 初期不允许运行上传的 Python/JS、任意 npx 或 shell。确有代码插件需求时，另做隔离执行器，不在 ONE 主进程加载第三方代码。
- 发布依赖与版本固定；新增数据外发范围或写入权限需要重新审核及用户授权。
- 审核与限额检查服务端执行。公开入口不得触达本机工具，持有分享链接不等于持有用户 Key。

## 8. 官方认定流程

活动/比赛报名与线下对接 → 官方录入草稿 → 技术接入测试 → 质量与权限评测 → 官方批准版本 → 小范围灰度 → 指定目录上架 → 监控与复评 → 回滚/暂停。

只有超管录入与批准，不开放创作者上传、送审、自动上架或任意安装。活动报名不等于取得后台权限。

评测至少包含：目标问题成功率与引用、无资料时不编造、失败恢复、权限与跨用户隔离、真实成本和耗时、错误价格/超额保护。行业功能还需合作方提供验收案例及维护责任。

公开目录的新增条目不自动获已有用户私人知识权限。用户选择“使用我的资料”才绑定本人授权来源；创作者提供的公共资料与使用者私有资料分离。

## 9. 与当前代码衔接

- server/connectors/registry.ts 已有服务端审核登记、域名及读写策略，当前是静态登记，不支持动态标准导入。
- server/connectors/remoteMcp.ts 已有固定提供方的 MCP 知识适配，不能等同于任意 MCP 工具网关。

- server/aiTaskCatalog.ts 已有入口权限上限，公开分身只读；继续保留为不可由提示词抬高的边界。
- server/publicSharing*.ts 已有发布快照、访客隔离、限额和回执，可逐步复用，不推翻重写，不把匿名 session 当永久用户。
- 保持模块化单体；暂不新增通用代码插件集群、复杂工作流编辑器或新向量数据库。

## 10. 分阶段实现与验收

### A：规则和底座

先定义功能包 schema、审核状态机、版本/权限合同、付款主体与身份边界。新增单元/隔离测试，默认关闭新入口；不接真实供应商，不收费。无审核记录不能上架；旧分身权限与 Key 插拔回归必须通过。

### B：最小标准接入

先做一种只读 HTTP/OpenAPI 接入和一种远程 MCP 接入的纵向样例，均由超管导入，不追求全规范覆盖。用两个参数结构不同的工具验证无需修改核心调度代码即可接入；同时验证越权、恶意地址、工具漂移、超时、取消、费用上限。

### C：身份和消费闭环

选择并核验快捷登录渠道资格；访客账号与 Key 绑定复用。做指定访客访问、主人请客/访客自付、定向赠送、订单/使用/收益分账与幂等。赠送量、价格、分成、退款规则由超管明确配置后才能生产启用。

### D：精选试点

一位专家分身、一个行业合作功能试点；企业资格可先人工开通。先验收真实任务、成本和复用，再做创作者目录和对外 API；A2A/代码插件运行时/提现继续后置。

测试通过且灰度验收后再发布；新表使用追加迁移和备份。文档先行不代表已有上线授权可替代未确定的收费或权限选择。

## 12. 阶段 A 实施记录

已实现官方全局配置登记：超管且 Key 在场才可访问；普通用户无登记、上传或送审接口。后台“管理 → 官方功能”支持搜索、10 条分页、草稿编辑、验收说明、认定版本、停用、恢复历史到草稿，历史每页 5 条。服务端使用 revision 防止多窗口相互覆盖，每次变更保留审计元数据。

配置放入既有 system_settings，随既有数据库备份，无需新增数据库或迁移。此处仅存官方功能定义，不存用户知识、第三方凭证。恢复历史不会自动重新启用；修改草稿不修改已认定快照。

这一批刻意不提供执行接口、用户目录上架、真实 HTTP/MCP 请求或新增计费。后台的“计划接入方式”只是下一阶段的类型声明，runtimeEnabled 始终为 false。认定配置不代表接口验收通过或用户已经能运行。

验证：配置不可变快照、无效字段/脚本/密钥字段拒绝、并发 revision 冲突、实际 HTTP 权限拦截与审计归属、真实 JSON Store 重启保存及旧个人分身保留；Playwright 使用隔离数据验证后台表单。未在生产创建测试功能或调用付费模型。
