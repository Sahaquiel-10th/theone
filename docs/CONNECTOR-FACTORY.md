# 内部连接工厂 0.1

## 验收前提

2026-09-08 产品方确认：首次授权、授权过期、执行中断线/取消、换设备与 Windows 实机均已完成测试。这是产品方验收确认，不代表本次代码改造已经重新执行了全部实机用例。

## 本轮实现

- 服务端维护经过审核的连接器登记表，描述 ID、版本、知识/执行分类、能力与授权方式。
- 第一批连接器为得到大脑、Codex，以及保留现有 Windows 路径的 ONE Local Agent；没有新增外部平台。
- KnowledgeService 通过登记表调用知识适配器；执行启动/继续/取消通过 ConnectorService 分发。
- 连接器内部保留各平台的实现：得到设备授权、知识凭据加解密、本机通道与 Runtime 均不替换。
- 统一状态查询和显式检查接口，不把“存有凭据”“通道在线”伪装成“已成功执行”。
- 原有前端、授权接口、任务/事件格式保持兼容；无需数据库迁移或重新灌装 Launcher。

## 状态与检查证据

| 状态 | 含义 |
| --- | --- |
| not_connected / pending | 尚未连接 / 正等待用户授权 |
| configured | 授权资料已保存，未验证本次远端可用性 |
| expired / error | 已知授权过期 / 已记录故障 |
| offline | 当前用户设备通道不可用 |
| transport_ready | 当前设备通道可用，不保证本地账号、目录权限与 Runtime 均就绪 |
| unavailable | 该启动器选择了另一条执行路径 |
| disabled | 运维明确停用该连接器 |
| verified | 本次显式远端检索接口检查成功，不代表一定命中知识 |

`GET /api/connectors` 只读取当前租户的状态和本机通道，不触发远端请求。
`POST /api/connectors/:id/check` 对正常已配置的得到授权发起小型检索检查；其他状态返回对应修复提示。Codex/Local Agent 只检查通道，不启动模型、不读写文件、不隐式申请权限。
检查结果附版本、时间和证据类型，不修改原连接状态，也不自动重新授权。已有 error 状态目前仍需沿原连接流程恢复。

## 安全边界

- API 继续使用现有 Session、Workspace Membership 与 ONE Key 请求证明；Key 严格模式离线仍返回 428，不为显示离线状态放宽认证。
- 服务层再次校验启用用户、活动 Workspace 和 Membership；客户端传入的 workspaceId/deviceId 不参与新接口身份解析。
- 执行任务必须同时匹配 workspaceId、userId、deviceId。已创建任务不切换提供方、不借用其他设备兜底。
- 共享诊断接口不返回凭据、原始平台错误、聊天或执行指令；执行上下文继续走独立的任务所有者接口。
- 连接器能力描述仅用于发现，不代替任务授权、文件权限和本机确认。
- 不提供任意 URL、脚本、命令、模块或文档上传注册接口；AI 输出不能修改登记表。

## 发布与停用

每个适配器声明版本，随服务端代码审核和发布。运维可设置 `ONE_DISABLED_CONNECTORS=getnote,codex` 并重启服务，阻止这些适配器的新检索、检查和任务分发；未知 ID 导致启动失败，避免拼写错误被静默忽略。
停用不撤销上游授权、不自动杀死已在本机运行的任务；已运行任务仍可通过原连接执行停止，不能因停用而失去取消能力。重新启用后恢复原路径，不切换账号或执行器。
第一版没有可视化版本切换、自动升级或任务级版本锁定；回退使用原有服务端发布回退流程。
