# 后台定价与列表交互规范

## 定价入口

- 模型接入页只配置连接参数；模型价格统一在「电力与收费 → 模型与定价」配置。
- 新模型保存后停用，确认价格后再启用。现有模型不自动改价。
- 聊天模型填写一套官方输入、输出、缓存读取、基础写入和一小时写入价格，单位为美元 / 百万 Token。
- 进货系数和对外系数各填一次，应用于所有 Token 类别。例如进货 0.2、对外 0.8，分别为官方价两折、八折；对外 1.2 表示增加 20% 服务费。
- 服务端计算采购价格，不把采购系数放进公开价格快照。用户接口不得暴露采购价格。
- 旧采购价格比例一致时推算回填；不一致时留空，请超管确认，不自动迁移或覆盖价格。
- 图片模型仍按张计费，价格入口也在定价列表；不能用 Token 官方价代替每张价格。
- 预约价格、撤回、旧请求价格快照和账本保持原有规则。没有缓存价格的调用仍按原规则进入待核对。

## 用户通知

- 调价说明是主要内容，突出显示生效时间。
- 通知不并列展示调整前后价格；当前具体价格仍可从用户电力页的「计费价格」查看。
- 历史通知、撤回记录、审计记录及旧账单不得删除。

## 列表与充值

- 账号、用户用量、模型、Key、待核对充值使用搜索和固定页大小，不用「继续加载」堆成长页面。
- 使用活动日志翻页；个人调用明细保持已有服务端分页。
- 充值核对、单人赠送、批量赠送、赠送记录、充值汇率分别切换，不垂直堆放所有表单。
- 微信订单点击「核对微信支付」，通过微信签名查询与既有幂等结算路径入账；人工旧订单保留确认收款操作。
- 未支付的微信订单核对后保留待处理，并显示结果；不因二维码过期就假定未付或擅自删除订单。
- 页面必须显示失败原因和处理中状态。

## 发布与限制

本轮为网站与服务端更新，不需要重新灌装或更新 U 盘。没有变更生产价格或实际账单。
当前后台汇总列表仍从超管接口加载后在页面搜索分页；这是界面分页，不是数据库分页。用户量显著增长时再把这些汇总查询迁移到服务端分页，仍须保留超管 Key 校验。
