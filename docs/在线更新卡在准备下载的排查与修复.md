# 在线更新卡在准备下载的排查与修复

日期：2026-09-22

## 现象与证据

- 用户从网页更新到 0.3.9，页面在“准备下载”停留超过一小时。
- 本机只读检查：TESTONLYONE 的 Mac 应用版本为 0.3.9，对应驻留进程仍是 0.3.8。没有读取或输出凭证内容。
- Mac 和 Windows 已发出的启动器都在 WebSocket 收包循环中执行安装；安装期间不能及时处理请求签名。
- 网页每 2.5 秒轮询更新状态，但原状态接口也要求新的 Key 签名。休眠修复引入的 2 秒超时断线会打断安装连接。
- 原网页忽略轮询错误；重新连接后即使进度记录消失，也没有结束本地 busy 状态。
- Mac 安装完成后若发送完成事件失败，会走错误分支而不启动新版。这解释了“盘内新版、驻留旧版”的可能路径；没有本次服务器事件日志，不能声称已逐条还原用户现场。

## 本次修复边界

本次仅更新网站和服务端，兼容已发出的旧启动器，不重灌、不改凭证、不修改签名包和版本号。

1. 只有 `GET /api/runtime/update` 可以免本次即时签名读取更新元数据。仍验证登录用户、成员关系、有效 Key 的所属用户和 workspace、当前安装 ID 与已认证连接。无连接或挂失依旧拒绝。
2. 发起更新的 POST、聊天、知识、附件和管理员接口仍要求即时签名；不允许将更新豁免扩大为业务放行。
3. 安装的最长 30 分钟窗口中，普通请求签名超时仍拒绝请求，但不终止安装 socket。超过窗口恢复普通超时断线机制；这不是延长业务在场凭证。
4. 同一连接已有更新时不重复下发；同电脑同版重复启动不能顶掉正在安装的连接。新版仍可接管。
5. 进度查询有 10 秒网络期限，连续不可达约 30 秒后显示检查状态。检查状态只发 GET，不重复安装。
6. 已断线、长时间准备、完成后未接管等情况不再永久锁住按钮。页面重新加载后可根据服务器进度继续轮询；新版接入后隐藏提醒。

## 现场恢复

先部署本次网站/服务端修复，再刷新一次旧页面以加载修复代码。

若盘内已是 0.3.9，但驻留仍是旧版，单纯双击会因单实例锁复用旧进程，未必换版。先由维护人员核对该盘对应的精确 PID、确认没有安装或磁盘校验子进程，再正常终止这一枚 Key 的旧驻留进程，从该盘打开 ONE for Mac；也可在没有安装进行时重启电脑后打开。不要结束其他 Key 的进程，不覆盖文件、不修改凭证、不重做灌装。不要在仍进行文件替换或磁盘校验时强杀程序或拔盘。

其他尚未升级用户可以继续从网页更新到现有签名版 0.3.9；本次不需要重新上传相同更新包。

## 验收

- 自动测试覆盖旧版同步安装时业务签名拒绝但连接保留、更新重复下发拦截、更新状态所属用户/工作区/电脑绑定、挂失拒绝、限定 GET 豁免、其他路径仍签名。
- 前端状态测试覆盖刷新后恢复轮询、准备/下载/安装/重连超时、重连无进度、失败和最新版。
- 完整测试、类型检查、构建及浏览器检查结果见本次任务报告。
- 仍需真实 Mac/Windows 完整在线升级和升级后的拔出拦截、重新插入、休眠恢复验收。模拟测试不能替代真机结果。

## 后续维护约束

健康检查、请求前即时签名与启动器更新不能共用无条件断线策略。新增任何“超时关闭连接”代码，都必须测试旧版同步安装器。

未来启动器可进一步将安装工作与签名收包解耦，并让完成上报失败不阻止已校验新版接管；不能仅发布新版来修复“旧版无法更新到新版”的引导问题。
