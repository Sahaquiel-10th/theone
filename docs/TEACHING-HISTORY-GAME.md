# 课程历史情境：从知识辅导到学生作品

本轮依据《杭州通论》原始教学方案及 2026-11-05 的明确需求实现。课程管理仍独立；课程知识来源只按既有授权实时检索。

## 学生入口

课前知识问答链接内提供“课前学习与知识辅导”和“上传游戏设定”。文字游戏入口直接进入剧本工作区。TXT 模板可下载；支持上传 TXT、Markdown、DOCX、PDF，最多 3 份，另可输入 6000 字补充内容；合并解析文字最多 60000 字。原始附件保留在课程私有上传范围。

同一链接在同一浏览器保存参与凭证，服务端期限仍为 7 天；刷新先恢复身份，再显示登记。退出、过期、教师关闭或撤销入口后需要重新登记。缓存不扩大课程或活动授权。

## 审核与导演方案

1. 服务端验证课程、活动、参与身份、附件归属与知识库绑定。
2. 实时检索课程资料，AI 检查普通人物身份、杭州时地、时代制度、事件事实、五轮冲突和学习目标。关键史实缺少课程证据时不发布。
3. 批注必须逐字定位到上传文字；史实引文必须逐字存在于本次取回的资料。退回时给具体修改意见。
4. 审核意见先落盘，再生成私有导演方案。编译失败时保留审核意见；不把未生成完成的作品显示为可分享。
5. 完整通过后作品以审核操作 ID 生成链接。另一位参与者只读作品摘要、角色和公开史实依据，不读取原稿、作者身份、导演提示或原作者对话。

系统提示分为史实审核、导演方案编译、逐轮主持三段；逐轮主持在结局时生成第四段作图提示。教师“学习说明”约束课程内容，“角色提示词”控制叙事特征；均不能覆盖系统权限、史实与输出校验。

## 五次选择

- AI 开场给第一幕及恰好两个选项。
- 服务端只接受上一幕真实返回的选项；浏览器不能指定轮数或提供历史记录。
- 每次选择后 AI 根据本局实际历史生成后果。第五次选择后产生结局，不再给选项。因此完整一局是开场回应，加五次选择后的回应。
- 角色为杭州历史环境下可能存在的普通人；排除扮演帝王名臣、历史名人、穿越者或超能力者。
- 叙事采用普通人生计、人情、文书与制度阻力构成的历史悬疑。小人物的行动通过合理因果参与大事，影响个人命运及参与过程；真实历史大事件的基本走向不能改写。
- 采用类 DND 的主持与后果推演；资源、人情、风险由导演方案组织，首版不增加复杂战斗或玩家手动掷骰。
- 每局有独立随机种子，重新体验可产生不同细节与个人结局；并非预先写死分支，也不保证任意两次生成绝不重复。
- 结局附选择的因果回顾、课程史实解析、虚构说明与反思问题，再按实际结局生成插画。

## 电力与恢复

审核与编译分别使用独立计费请求编号；每次剧情与结局图片也有各自回执。完整通过的一局通常包含 2 次剧本处理、6 次剧情回应、1 次按张计费的作图。具体电力由现有已发布的模型和图片配置决定，本轮不调整价格。

学生所有请求受课程累计保护上限与支付账户余额双重约束；教师试玩保留原有手动操作的课程/余额模式。图片调用复用已发布图片能力，私有像素存入该玩家课程操作结果，不生成公共对象存储地址。

重复原请求只返回原回执。未知状态不自动另建请求；作图失败保留文字结局。关闭入口、移入回收站、课程材料/知识授权变化时继续使用现有生命周期与来源校验。学生游戏对话不进入教师学情汇总，教师只看到自己的试玩。

## 教师体验

教师“试玩”使用和学生相同的审核及五轮流程，按教师身份结算且不冒充学生参与。教师辅导预览与学生辅导使用统一的左右聊天气泡，沿用 ONE 配色，不套用微信绿色；辅导显示检索来源数与匹配来源数，并可展开逐字课程依据。游戏使用独立的角色卡、历史背景、五幕进度、当前剧情场景与两张行动按钮卡，玩家不使用文字输入框。过去的选择收入“选择手记”，结局单独呈现。旧试问记录保持原样，不伪装成重新生成的回答。
