# 异常后能继续使用：恢复出口闭环计划

2026-11-03；基线 `a63e6c5`；隔离分支 `codex/recovery-closure-20261103`。

## 目标和完成定义

用户可以接受模型或网络失败，但不能被要求猜测系统状态。每个纳入本轮的异常出口必须能回答：已经完成什么、卡在哪一步、系统是否还会继续、用户现在需要做什么。提示里的操作必须有实际可用的处理链；没有用户能解决的事项时，不要求用户改问法、重选功能或反复点击。

保留线性 workflow、TaskStep 检查点、原成果和原回执，不引入第二任务引擎。未知模型/付费调用、未知写入不盲重放。用户停止、预算增加、设备/保存位置变更继续要求明确决定。原业务文章/myspace/Excel 不重跑，不改价格、余额或授权。

完整源码/前端备份：`/tmp/one-before-recovery-closure-20261103.tar.gz`。原工作树和其他分支保持原状。

## 已确认的问题与设计决定

1. Key/来源授权失败被整类保护；恢复连接后用户说“继续”，仍可能只记录补充并要求进详情启动。不能仅删保护：普通 enqueue/retry 会创建新轮，可能重新生成完成的内容。新增窄范围同 run 恢复，先做新鲜授权校验，再原子认领并从未完成阶段推进。
2. Notion 未返回 pageId 的未知写入，当前既建议用户提供链接，又缺少处理该链接的核对入口。增加候选原页的只读核对与显式采用流程。候选在通过授权位置、标题和全文验证前不写入原 receipt/target；保留原 delivery=unknown 的事实，不伪称收到供应商写入回执。
3. 参数错误已有同轮纠正机制，但入口限制、诊断传递和最终提示不一致；部分配置故障也误入参数修正。复用现有内部纠正，不增加一层外部功能重跑。真实缺用户资料、系统参数错误、配置/授权故障、效果未知分开处理。
4. 在现有 TaskRecovery/公开进度投影上提供统一恢复说明与允许的动作；不维护第二套可变任务状态。阶段、成果和恢复决定以已有持久记录为准。

## 实施顺序

### 0. 计划和基线

- [x] 读取当前代码、三个方向独立只读分析、确认旧恢复路径可能重做成果。
- [x] 隔离工作树与完整备份先于应用代码修改建立。
- [x] 本文先落盘，之后按下列边界实施。

### 1. 同一任务恢复连接后继续

- [ ] 主对话与任务内明确“继续”均接到同一个受控恢复入口，唯一同 scope/最新任务匹配；有歧义只问选哪件事。
- [ ] fresh Key、来源账户/凭证、功能版本、保存授权、原剩余预算与停止状态检查；认领事务再检查 latest/version 和这些条件。
- [ ] 同 run ID/revision/binding/原预算，成功步骤与成果原样复用；不得为了续做重买已完成模型或重写已保存文档。
- [ ] 已开始但结果未知的 paid/model/artifact/write、本机 hold、用户停止、预算不足不解锁。云端使用当前有效 Key；本机保留原设备/安装/目录绑定。
- [ ] 重复/并发“继续”只认领一次；原失败证据保留，完成反馈不重复。

验收：读资料/写稿完成后，在下一步发出前 Key 校验失败；恢复说继续后自动交付，原已完成调用计数不增加，保存一次；撤权/停止/换来源/新要求/跨租户的竞态均拒绝。

### 2. 用户给原页链接后能真正核对

- [ ] 扩展现有只读核对入口，携带精确任务/原 job/版本与当前用户确认的候选链接；主对话和任务内自然语言也能接入，绕过模型生成、enqueue 和写入。
- [ ] 只接当前用户原话中唯一、明确用于该任务的链接；多个任务/多个链接需要选择，不使用模型参数或历史正文链接作用户确认。
- [ ] 原未知写入、worker 写入检查点、原正文摘要/长度/标题、来源和保存 grant/parent 全部保留并验证。已知 pageId 不换绑，有 asyncTaskId 先按原异步任务核对。
- [ ] 用原授权只读验证候选属于原保存位置、实际标题和完整正文；拒绝已知绑定其他独立 ONE 任务的页面。正文差异/错父页/撤权/不完整/旧版本不能绑定。
- [ ] 匹配后 CAS 记录用户提供并核对的交付证据，推进原 workflow/通知；没有新建/覆盖，没有再次生成。原 delivery 未知仍保留，不冒充原 create ACK。
- [ ] UI 提供实际可用的“核对这页”动作；错误指出链接/位置/内容哪一项没对上，并保留已有成果。

验收：创建响应丢 pageId → 给正确原页链接 → 只读全文匹配 → 原任务完成；write/model 计数不增加。错页、旧独立页、另一租户、来源变化、并发选择/停止等负例全部拒绝。

### 3. 参数错误由系统先纠正，失败也不让用户猜

- [ ] 审核现有 correction pass 与所有相关入口限制，统一可证明未执行时的有界纠正；相同错误参数不重复花费，预算/次数不因重启或外层重试归零。
- [ ] Office 等原生校验给内部 runner 安全、具体的字段/结构诊断；缺已有授权附件绑定可修正，配置未就绪、授权/读取失败不进行参数修正。
- [ ] 不将 inner 的“这一份尚未保存”证明扩大为整个父功能未产生效果。多文件部分成功、saver 已进入、检查点写入失败保留未知效果防重。
- [ ] 参数修正耗尽明确为系统未完成，保留已有成果和安全诊断；只在真实缺模板/业务资料时提出具体问题，不要求用户猜 schema 或重新选功能。
- [ ] workflow 中的相关故障保留准确原因和恢复决定，不退化为无限等待原结果。

验收：错列数后自修成功只保存一次；重复同参停止；配置/授权问题零修正；缺模板只问模板；跨空间附件拒绝；部分保存不重跑整功能；停止/预算/重启/诊断脱敏回归。

### 4. 一个清楚且接通的用户出口

- [ ] 复用现有恢复 DTO/动作，公开字段白名单：已有成果、卡住步骤、原因、自动恢复与否、一个主动作；无原始参数、异常体或凭证。
- [ ] 自动恢复期间显示进展，不制造等待用户确认的假暂停；恢复耗尽说明已停止，不让用户无限等。
- [ ] 主对话/任务详情/任务动态对本轮纳入状态使用一致事实；历史文字保留，当前操作指向真实处理入口。
- [ ] 系统参数问题不出现“请重选功能/猜列名公式”；预算/授权/用户停止等真正决定明确说明后果。
- [ ] 沿用 ONE 的简洁、友好语气，先说明是否需要用户操作；用 `ux-copy` 检查每个按钮标签是否等于实际行为。

## 故障矩阵（最低要求）

| 故障 | 必须看到的结果 |
| --- | --- |
| Key 在下一步之前失败，恢复后说继续 | 保留原成果；无需进详情点启动；只执行未发出的步骤 |
| 来源同账户 token 轮换 / 换成另一账户 | 前者在授权复核后可恢复；后者不静默复用 |
| 用户停止、预算不足、待确认本机效果 | 不因“继续”或网络恢复直接越过保护，说明所需决定 |
| 重复继续、校验后停止/撤权、新要求抢先 | 一次认领或拒绝旧轮；零额外写入 |
| Notion 未返回页号，用户给正确原页 | 原页只读匹配后推进，不新建/改写 |
| 候选正文/标题/父页不符，或属于旧独立任务 | 不绑定、不伪报成功，说明具体差异类别 |
| 列数错误、模型漏字段或已有附件绑定 | 同轮有界修正，成功只保存一次 |
| 相同错误重复、连续不同错误、配置缺失 | 不无限生成；配置问题不买修正调用 |
| 已保存一份后下一份失败 / checkpoint 写失败 | 首份保留，不重跑整功能、不重复保存 |
| 真缺模板 / 跨空间模板 | 前者只问缺的模板；后者不泄漏存在性 |
| 前端断线、返回旧轮、刷新任务详情 | 同一事实与动作，不清成果、不重提要求 |
| 所有未知/不支持的恢复情况 | 明确已停或继续核对，给实际可用动作，不说空泛“核对后继续” |
