# ONE Key 内测量产放行门槛

状态：强制执行

适用范围：普通 FAT32 + MBR U 盘的灌装、在线更新与首批朋友内测。本文记录已经发生过的问题和不可省略的验收，不以“页面能打开”或“消息能发出”代替底层检查。

## 1. 不可退让的产品体验

- 插着 Key 即可使用；拔掉后，下一次受保护请求必须在模型、知识库和附件处理前被拦截。
- 重新插入后应自动恢复，不要求刷新网页或再次双击；电脑重启后允许要求双击一次。
- 多枚 Key 同时出现时，驻留进程只认启动时传入的那一份精确凭证，不能扫描并误选其他账号。
- 在线更新只替换当前操作系统的 Launcher/Bridge；不得改写、重新签发或上传 `.one/credential.json`。
- 超管与普通用户使用同一套启动器；权限只由服务端账号、Workspace 和 Key 绑定决定。

## 2. 已发生过的失效模式

1. **功能正常不等于磁盘健康。** 0.3.6 → 0.3.7 更新后可以登录、驻留和发消息，凭证也未变，但 `fsck_msdos` 检出了 FAT32 目录父簇异常。没有文件系统验收就发货，会把潜在损坏留给用户。
2. **FAT32 目录不能跨父目录搬运。** 在隐藏子目录中暂存 `.app`，再移动到根目录，可能让 `..` 仍指向已删除的暂存目录。灌装和更新都必须在最终父目录逐层创建，最终替换只能同父目录重命名。
3. **macOS 元数据会变成 AppleDouble 文件。** 发布包中不得带 `._*`；写入 FAT32 后必须 `dot_clean`、清理扩展属性、在目标卷重新签名并再次验签。
4. **设备编号会变化。** 挂载测试镜像或插入另一只 U 盘后，`disk4`、`disk5` 等编号可能重排。生产工具和修复命令必须使用已经核对的卷路径，不得缓存或照抄磁盘号。
5. **驻留代际必须可接管。** 新版完成替换后要启动新版驻留，旧版释放单实例锁；拔出、重插、休眠唤醒都不能留下两个 Bridge 或失去自动恢复。
6. **版本发布是独立链路。** Git 提交、网站部署和启动器发布不是一件事。启动器只有在签名清单和双平台制品完整安装到服务器后才应提示更新。
7. **普通 U 盘不是安全芯片。** 凭证可被复制；遗失必须服务端挂失。当前安全边界是在线吊销、Workspace 隔离和每次敏感请求的即时在场证明。

## 3. 每只盘的灌装门槛

只允许使用 `scripts/provision-one-key-dual.ts`，禁止手工拖拽 App 或凭证。

- 整盘必须是 FAT32 + MBR，卷路径必须是 `/Volumes` 下当前核对的外置卷。
- 输入必须是后台为目标用户新签发的生产凭证；一只盘一个设备序列号，多盘可绑定同一用户。
- 出厂版本不得低于 `config/runtime-version.txt`；当前首批基线为 0.3.8。
- Mac 必须是 arm64 + x86_64 Universal；Windows 必须是 x64 PE32+；两端必须内置同一更新公钥并声明更新协议 V1。
- 写入后必须确认：凭证字节一致、Mac 签名有效、Windows 哈希一致、App 内无 AppleDouble、卷图标有效。
- 必须执行 `sync → diskutil verifyVolume <卷路径> → 重挂载后二次验签/验哈希/验凭证`。校验非 0 时不得发货。
- 安全推出后重新插入，Mac 和 Windows 至少各在真实机器完成一次启动；不得把“编译成功”当作真机通过。

## 4. 每个启动器版本的发布门槛

- 先在可丢弃 FAT32 测试卷模拟旧版 → 新版，验证目标 App、旧版备份、签名和 `fsck_msdos`。
- 使用仓库外的 Ed25519 私钥生成完整签名清单；服务器只保存公钥和已签名制品。
- 服务器安装必须原子切换完整目录；不能让网页看见半个版本。
- 在真实 Mac 上检查：提醒出现、更新成功、凭证哈希不变、Windows 文件不变、提醒消失、驻留切换、文件系统校验为 0、拔插恢复。
- 在真实 Windows 上检查同一套流程；Mac 通过不能代替 Windows 通过。
- 更新失败测试必须证明旧版仍能启动；断网、Key 中途拔出、摘要错误均不得留下半个启动器。

## 5. 首批朋友内测的放行结论

满足以下条件才可以批量灌装并发货：

- [ ] 0.3.7 → 0.3.8 Mac 真机在线更新完整通过，包括更新后的 FAT32 校验。
- [ ] Windows 真机至少完成一次旧版 → 0.3.8 在线更新、重启和拔插测试。
- [ ] 使用正式灌装器制作一只 0.3.8 样盘，安全推出、重新插入并完成双系统抽检。
- [ ] 台账记录用户、设备序列号、凭证签发时间、出厂版本、灌装人和验收结果；台账不保存私钥正文。
- [ ] 管理员确认挂失入口、用量/电力查看和单用户隔离仍正常。

在 Apple Developer ID / Authenticode 完成前，可以进行小范围、当面可支持的朋友内测，但必须提前说明系统可能显示未知开发者或安全提示；公开测试和规模发货前必须完成正式签名。

## 6. 故障处理

- 先停止继续灌装或发布，不用“再点一次”掩盖未知状态。
- 先按卷路径读取凭证哈希并与安全恢复副本核对，再进行文件系统修复。
- 文件系统修复后重新验证 Mac 签名、Windows 哈希、凭证哈希和驻留版本。
- 线上稳定清单有问题时回滚服务器更新目录；已经签发的身份凭证不随启动器版本回滚。
- 每次事故都要补充到本文和自动化门槛中，不能只修当前这只盘。
