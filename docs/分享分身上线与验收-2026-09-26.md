# 分享分身上线与验收

## 开放内容

设置 → 分享分身：填写名称、介绍、回答要求，选择问答模型与知识来源，确认限额后生成链接。链接访客可独立问答、上传附件；无需主人的 Key 在场。发布、关闭和查看自己的用量仍需主人插 Key。

注意：知识来源勾选表示分享该连接的全部授权搜索范围，不是单篇笔记。链接可以转发，不应拿它当保密访问控制。附件只属于访客会话，不进入主人知识库。不开放本机、联网、写入、发布、图片生成等能力。

## 服务器启用

代码可先部署到仍为 V2 的数据库；分享入口显示准备中，不自动执行 DDL。代码已部署后，在腾讯云终端执行：

```bash
sudo systemctl start theone-db-backup.service &&
test "$(sudo systemctl show theone-db-backup.service -p Result --value)" = success &&
sudo bash -c 'mysql < /srv/theone/current/deploy/migrations/003-public-sharing.sql' &&
sudo -u theone node /srv/theone/current/deploy/check-mysql-schema.mjs &&
sudo systemctl restart theone.service &&
curl --fail --silent --show-error --retry 5 --retry-connrefused --retry-delay 2 http://127.0.0.1:3091/api/health
```

命令只针对 `theone_prod` 和 `theone.service`。不会修改支付配置或中转站，不删除旧表/旧账单。若备份、数据库权限或有进行中请求导致失败，后续命令不会继续；保留输出定位，不执行删除重建。

迁移幂等；重启前预检会阻止在已知模型/公开任务进行中时重启。仅重启一次才能加载新表。需看到 V3 ready 和健康检查 ok，再刷新页面。

## 已自动验证

- Key 管理入口与无 Key 访客入口分离；不同账号不能管理他人的分身。
- 两个访客不能读取彼此的任务和附件；主人用量接口不暴露访客原文。
- 真实 HTTP 分片上传、实际文本解析、假上游模型回答、计费归属、重复请求不重复调用、关闭后的拦截。
- 显式知识来源筛选不扩大到其他账号或未勾选来源；检索中撤销授权会在模型调用前停止。
- 并发计费预留计入分享额度；JSON Store 实际重启保留记录并终止未完成任务。
- 页面使用 Playwright 隔离数据验收，未进行真实付费模型调用或向真实外部平台写入。

## 上线后真人验收（仍需执行）

1. 用自己的测试账号，只选择可公开的测试知识；先设小额度。
2. 无痕窗口打开链接，询问一个答案明确的问题；核对实际引用和账单。
3. 上传一个 PDF/PPT/文本附件提问；再换一个无痕访客，确认不包含前一人的内容。
4. 主人拔 Key 后访客仍可问答，主人管理操作被拦；重插后关闭分享，访客新请求被拒。
5. 测试额度不足、重复点击、刷新与网络中断恢复。

本批发布后不可原地修改：关闭后重新发布新链接。公开 API、访客收费、自动提现、自动清理历史附件均不在本批。
