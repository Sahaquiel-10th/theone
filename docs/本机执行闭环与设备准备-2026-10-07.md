# 本机执行闭环与设备准备

日期：2026-10-07。沿用既有系统，先修 Mac Codex 闭环，再补 Mac 原生文件工具。未经真实页面与本机文件验收，不视为上线完成。保留 2026-10-06 的历史、文件和证据。

## 产品约束

- ONE 是持续沟通主体；执行器、命令行和文件工具是内部能力，不要求用户每次选择。
- 点击执行立即反馈，但受理、授权、运行、结果验证、失败和取消必须区分。
- 设置中显示本机授权目录，允许重新选择；第一次执行才请求目录。换设备重新授权，换目录不得默默沿用旧执行会话。
- 工作台中心保留对话，右侧任务区默认折叠；阶段日志不逐条刷进对话。结束可以简短汇总，以用户主动展开查看完整过程；重复回流必须幂等。
- 运行中必须可见正在调用的工具、必要问题及返回结果。没有反馈不能伪装成工作中；断连且结果无法确认时不得自动重跑。
- Mac 原生 Local Agent 首版只提供授权目录内的文件工具，不提供任意 shell、提权或系统控制。路径和符号链接边界由本机代码约束，不依赖模型承诺。
- 设备准备检测适配器、版本、登录和实际接口，不扫全盘、不读取凭证；系统权限由用户决定。新用户完整引导，老用户新设备仅设备准备。

## 实施顺序

1. 修复 Codex 输出读取、事件顺序、真实结果终态；取消后拒绝晚到完成。
2. 按事情、执行轮次保存结果回执；普通聊天、调度读取事情、执行整理使用有来源的有限回执，不加载全部执行历史。
3. 完成目录设置和任务右侧折叠、实时反馈；避免草稿和焦点受影响。
4. 补 Mac 原生文件能力，使用同一授权、状态、回执与验收链路。
5. 增加轻量设备准备；只对已适配工具声明可用。

## 2026-10-09 决策：ONE 统一入口，成熟工具负责执行

本节是后续开发依据，不表示下面的安装、网关与工程执行已经上线。此前外部 Codex 的登录检查描述的是旧路径，不是新方案要求用户另行注册的产品目标。

### 用户体验与责任边界

用户只在 ONE 登录、对话、付费。ONE 负责调度、按需补充知识库和事情上下文、目录授权、执行过程与真实回执；Codex 是背后的执行工具。2026-10-09 补充决定：本轮只接 Codex，不接 Claude Code，先跑通一个执行器。默认不要求用户购买工具订阅、注册第三方账号、填写 API Key 或自行安装命令行。

新用户首次进入完成 ONE 引导；老用户换设备仅完成设备准备。轻量扫描只检查已适配工具的固定安装位置、版本与实际接口，不扫描用户文件或读取其他软件的密钥。发现工具不等于可用：接口、供应商协议、授权目录和健康检查通过后才显示可执行。

缺少工具时提供一个“准备本机执行”按钮，说明下载大小、来源、授权范围和是否安装新组件。确认后由 ONE 下载、校验、安装并验证；不把技术选择交给用户。已有工具可以复用兼容的执行程序，但 ONE 使用独立配置和会话，不能改写用户原有 Codex/Claude 配置或借用其订阅。

部署目标是无需用户翻墙的 ONE 服务和下载通道，但不能承诺任意外部依赖均可访问。项目需要联网下载依赖时，也必须在真实目标网络中验收，失败提供明确原因而不是无限等待。

### 统一 API 与收费

- 工具调用 ONE 执行网关，网关再使用管理员配置的供应商。供应商原始密钥只留服务端，绝不放入浏览器、启动器、工具配置或安装包。
- 下发短时执行凭证，绑定精确 Workspace、用户、设备、安装身份、事情及执行轮次；服务端再次校验绑定、Key 在场和取消状态。凭证撤销后拒绝新调用，不能以任务 ID 充当授权。
- Codex 与 Claude Code 的协议分别适配。Codex 使用经验证的 Responses 接口；Claude 使用经验证的 Anthropic 接口。普通聊天的接口兼容不等于编码执行器兼容，不把任意模型或 API 宣称为可用。
- 供应商、模型和提示词均可管理员配置；采用能力白名单，配置变更不偷偷改变正在执行的任务。
- 每个供应商调用关联任务轮次与独立请求 ID，沿用 ONE 计费账本与幂等结算；重连、重复事件不得重复扣费。对未知用量先对账，不用估算数字伪装真实用量。本阶段不调整生产价格。

### 安装、更新与权限

首选可按许可条件分发的官方 Codex CLI，不默认打包桌面应用。服务器缓存固定版本、固定平台架构的制品；发布清单必须包含来源、大小、SHA-256、许可文件与第三方声明，经过离线签名。工具清单与启动器清单使用不同种类标识，不能互相替代。

Claude Code 的源码仓库许可不是 Apache/MIT；在分发权确认前，不将其二进制镜像上线。保留受支持的本机已有安装接入路线，但它也必须走 ONE 的供应商网关，而不是使用用户个人账号。CodeBuddy、TRAE、OpenClaw 均需独立验证官方接口和许可，不因为扫描到应用就宣称接管成功。

安装顺序：下载暂存 → 签名与文件校验 → 安装到本机受控目录 → 独立配置 → 无业务数据的健康检查 → 可用。下载可续传，半包不可运行；失败保留可用旧版本，更新不得覆盖用户项目和 Key 凭证。任务运行中不更换执行程序。启动器升级与执行工具升级分开，继续遵守单机单 Key、驻留进程交接和旧版本回退约束。

首次明确选择授权目录，设置中随时查看、更换与撤销。可对本轮或项目内的低风险写入做预授权，避免每写一个文件弹一次 ONE 提示；删除、覆盖、联网、运行命令等风险另行界定。ONE 授权不等于 macOS 系统授权，不能绕过或保证一次性授予所有系统权限。

尤其注意：命令行的工作目录不是沙箱。调用外部执行器时必须验证实际文件与网络隔离；不能只设置 `-C`，就承诺绝不越出用户授权目录。

### 开发顺序与交付门槛

1. **制品基础**：独立的签名执行工具清单、来源与分发许可检查、平台选择、篡改与错误包测试；没有合法可用包不显示可安装。
2. **ONE 网关**：先接 Codex 的供应商 API，做协议事件、短时凭证、用量归属、撤销与跨 Workspace 隔离测试。真实供应商不支持协议时明确禁用，不退回用户订阅。
3. **Mac 准备流程**：扫描、一次点击准备、独立配置、安装/升级/失败回退和设置中的工具状态。改启动器必须另发版本，并确认本机实际运行新版。
4. **执行闭环**：复用已有任务摘要、原话、队列、取消与回执；任务细节默认在右侧折叠，中心仅简短回应。展示调用工具、关键问题、实际产物位置和验证情况；结束只回流一次，不清草稿、不抢焦点。
5. **真实工程验收**：在用户授权的独立目录，由 ONE 完成网页项目、依赖准备、启动、动态可用端口的 localhost 预览、交互测试和定向修改。不固定承诺 3000；停止时关闭自己启动的服务，不杀用户已有服务。完成后追问必须与实际文件一致。
6. 其他执行器暂不开发。原生 Local Agent 继续作为文件基础能力和受限兜底，不为了赶进度重做完整编码代理。CCS 仅在真实供应商不兼容、且兼容层确实能解决时考虑；当前真实测试已证明不需要 CCS 就能执行。

每一步记录预期、实际与证据。自动测试、供应商兼容性、真实 ONE 页面、工具安装成功、启动器版本、工程文件与网页交互分别验收。取消后晚到结果、断连不重跑、同名不覆盖、换目录不越权、重复结算、制品篡改和旧任务历史保留均为必测项。

### 第一批代码的范围

### Codex 直连 ONE 网关

第二批增加 `codex_execution` 管理员配置项，模型和默认提示词与原生 Local Agent 分开。服务器通过已认证的 Launcher 通道下发短时、精确事情与轮次绑定的授权；启动器使用独立 Codex 状态目录和环境凭证，不读取个人 Codex 登录，不改个人配置。每个模型请求先检查所有权、Key 即时签名、当前轮次、终态和用量；请求不接受其他响应 ID 或客户端供应商地址。供应商密钥始终留在服务器。

真实 Codex CLI 0.160.1 使用 function 与 namespace 工具定义及 client_metadata。网关支持这些本地工具定义，拒绝 namespace 内夹带服务器托管工具；丢弃客户端元数据和缓存键，以服务器绑定确定归属。重复输入不重复调用，取消后不回传晚到完成，用量落账后才发送完成事件。

真实供应商及 CLI 的隔离测试已创建并回读 HTML，最终 3 次供应商调用均完成测试账本结算。测试账本为内存数据，缓存价格明确为测试值，不代表正式价格或生产计费验收。先前一条本地模型配置返回 404，另一条成功；正式启用必须指定通过测试的模型并配置真实缓存售价及成本，不能直接沿用错误模型名称。

启用参数：`ONE_CODEX_GATEWAY_ENABLED`、`ONE_CODEX_GATEWAY_URL`、`ONE_CODEX_GATEWAY_MODEL_ID`；默认关闭。网页真实链路、新版启动器发布及升级、缓存价格和一键准备仍须验收，现有原生文件执行路径不改变。证据与复测入口见 [2026-10-09 Codex 网关验证](testing/2026-10-09-codex-one-gateway/01-实施与验证.md)。
