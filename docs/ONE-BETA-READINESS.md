## 已实现的约定

- 普通用户无需密码；运营开户 → 每人独立 Workspace/电力账户 → 签发独立 Key → 赠送体验电力 → 交付。一个账号可绑定多枚 Key；复制同一凭证不会生成独立身份或余额。
- 对话读写、附件读写、知识连接/召回、账单、模型调用、本机执行和超管接口要求在场 Key。超管权限还必须匹配当前数据库角色和本人 Key。普通密码不能登录；超管密码不提供管理旁路。
- 已显示在浏览器上的内容不主动遮盖；拔出后不能再发起受保护请求。Local Agent 每个模型步骤也再次要求 Key 证明；已经提交上游的单次调用可能继续结算。
- 账号只停用归档，不删除资金账本。挂失 Key 默认在归档筛选中；支持按用户/序列号搜索。序列号贴在实物 U 盘上。
- 用户列表显示今日、近 7 天、累计用量和余额，展开一个用户看分页明细。支持时间筛选，保留用途、模型展示名、时间、耗时、输入/输出 Token、实扣、按配置计算的上游成本、请求编号和状态。统计“今日”按北京时间；日志按浏览器时区显示。
- 超管只能看其他人的非内容用量；不得展示其聊天标题/正文、附件名称、知识片段、执行指令。超管自己的上下文调试功能保留。

## 计费边界

1. 每次模型调用先持久化独立预占记录，按发起时的价格快照结算，不受调用中途改价影响。单进程内并发不能重复占用同一余额。
2. 用量合法时按真实 Token 结算，零售实扣最多等于预占；若触发上限会标记，差额由平台承担。按配置进价记录成本；它仍需与上游账单对账。
3. 失败不扣用户电力，保留失败时间记录；上游是否收了费用可能未知，不能显示为已确认免费。
4. 没有有效 usage，不猜测 Token 收费。保留待核对预占，暂停该用户后续模型调用；超管在“用户用量”展开记录，填写上游真实 Token 或明确免扣。重复确认不重复扣款。
5. 服务异常退出时，未决调用重启后进入待核对。正常已结算数据不受影响。图片模型需要先配置固定单次售价和进价，未配置时不请求上游。
6. 赠送电力不是现金收入，“实扣减配置成本”不是利润报表。充值仍是申请 + 人工确认，不承诺在线支付自动到账。

## 每位内测者验收

- [ ] 首次双击对应图标，进入自己的账号，能发起一次真实问答。
- [ ] 连接自己的知识来源；另一台 Mac/Windows 使用同一账号 Key 不需重新授权。

- [ ] 插回 Key、不刷新重试；休眠后唤醒重试。Windows 必须实机验证，不能以跨平台构建成功替代。
- [ ] A 的 Key 不能读取 B 的对话/附件/用量/连接；普通 Key 不能打开超管 API。
- [ ] 低余额同时发出两个请求，不能透支或重复扣费。上游缺失 usage/失败时符合上述规则。
- [ ] 超管能按人查看使用时间、模型用途、耗时和电力；不用进入任何人的私人会话。

## 最小运维与已知限制

- 总览检查数据库连通、磁盘可用空间、本地备份和异地上传的最近成功标记。新代码部署后，手动执行一次 `sudo systemctl start theone-db-backup.service`，确认成功后刷新页面；没有新版标记显示“未验证”，不会误报健康。
- 超过 36 小时未成功备份会在总览提示，但没有主动告警通知。COS 上传成功不等于恢复成功，需在独立临时数据库做恢复演练，禁止覆盖生产库。
- 当前 MySQL 实现仍将状态载入一个服务进程，串行事务写入；未来多进程扩容前要改数据库原子扣款与锁，不可简单横向加进程。
- Windows Authenticode 是程序发行签名，不是 Claude Code/API 接入。代码签名、公证、完整本地命令沙箱加固属于扩大内测前的后续事项。

## 附件：本轮只讨论，不改存储流程

现在：原文件保存为服务器私有附件；解析文本随附件记录持久化，发送时选中的附件文本注入这一轮模型上下文。默认每次最多 4 个文件、每个 10 MB、文本上下文总预算 24,000 字符。历史追问不保证重新附上原附件全文；扫描 PDF、图片/复杂表格的识别能力也不能等同专业文档系统。

建议下一步单独确认：默认附件只属于当前会话；保留私有原文件，解析文本供该会话追问使用，大文档按需检索而非每轮全量塞入。将来迁至私有 COS 存文件、MySQL 存元数据和权限；这与数据库 COS 备份不是同一功能。没有明确同意前，不自动把附件加入长期个人知识库。
