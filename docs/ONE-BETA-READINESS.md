## 已实现的约定

- 普通用户无需密码；运营开户 → 每人独立 Workspace/电力账户 → 签发独立 Key → 赠送体验电力 → 交付。一个账号可绑定多枚 Key；复制同一凭证不会生成独立身份或余额。
- 对话读写、附件读写、知识连接/召回、账单、模型调用、本机执行和超管接口要求在场 Key。超管权限还必须匹配当前数据库角色和本人 Key。普通密码不能登录；超管密码不提供管理旁路。
- 已显示在浏览器上的内容不主动遮盖；拔出后不能再发起受保护请求。Local Agent 每个模型步骤也再次要求 Key 证明；已经提交上游的单次调用可能继续结算。
- 登录、会话、在场证明及已有执行任务绑定当前电脑安装身份。Key 移至电脑 B 后，B 的通道不能解锁电脑 A 的旧页面或承接 A 的本机任务。旧版启动器/会话没有安装身份时明确要求升级，不兼容降级。
- 首次使用填写称呼、连接知识或跳过；之后设置内可改称呼。回答显示独立的知识检索状态；暂时失败不永久禁用连接。
- 得到授权保留官方 10 分钟有效期；等待、限速、拒绝、过期和已消费状态分别处理。换取凭据后先加密暂存再验证，取消或断开后旧轮询不能恢复连接。
- 每用户详情新增有效问答、知识回答、使用天数、首次/最近使用时间及折叠反馈。只显示用户主动勾选同意分享的说明，不自动附带对话/附件/知识内容。
- 每次提交保留稳定编号；响应丢失查询原结果，不重复调用或扣费。进行中、重启中断和已失败区分处理，未知结果不自动当作免费重试。
- 账号只停用归档，不删除资金账本。挂失 Key 默认在归档筛选中；支持按用户/序列号搜索。序列号贴在实物 U 盘上。
- 用户列表显示今日、近 7 天、累计用量和余额，展开一个用户看分页明细。支持时间筛选，保留用途、模型展示名、时间、耗时、输入/输出 Token、实扣、按配置计算的上游成本、请求编号和状态。统计“今日”按北京时间；日志按浏览器时区显示。
- 超管只能看其他人的非内容用量；不得展示其聊天标题/正文、附件名称、知识片段、执行指令。超管自己的上下文调试功能保留。

## 计费边界

1. 每次模型调用先持久化独立预占记录，按发起时的价格快照结算，不受调用中途改价影响。单进程内并发不能重复占用同一余额。
2. 用量合法时按真实 Token 结算，零售实扣最多等于预占；若触发上限会标记，差额由平台承担。按配置进价记录成本；它仍需与上游账单对账。
3. 失败不扣用户电力，保留失败时间记录；上游是否收了费用可能未知，不能显示为已确认免费。
4. 没有有效 usage，不猜测 Token 收费。保留待核对预占，暂停该用户后续模型调用；超管在“用户用量”展开记录，填写上游真实 Token 或明确免扣。重复确认不重复扣款。
5. 服务异常退出时，未决调用重启后进入待核对。正常已结算数据不受影响。图片模型需要先配置固定单次售价和进价，未配置时不请求上游。
6. 赠送电力不是现金收入，“实扣减配置成本”不是利润报表。充值仍是申请 + 人工确认，不承诺在线支付自动到账。

## 本次修复版的数据库发布前置条件（V2，尚需线上执行）

本次新增 `chat_operations` 表，为每次用户提交保留所属个人空间、用户、提交标识、处理状态和结果引用。它不复制聊天正文，不代替电力账本。**必须先由数据库管理员应用 `deploy/migrations/002-chat-operations.sql`，再切换到这次修复版**；不能先发布、等服务启动失败才补表。已共享的 `001` 迁移不得重写。

1. 先确认没有内测者正在发消息或执行任务，在维护窗口操作。执行现有 ONE 数据库备份任务并检查成功；本次没有增加附件或密钥备份。
   先从经核对的本轮版本更新服务器已安装的 `/usr/local/sbin/theone-deploy`；只更新 Git 仓库不会升级该独立部署器。未升级前，新增的只读结构预检门禁不会生效。不要在准备迁移之前直接推送 `main` 触发自动发布。
2. 把此次版本的 `002-chat-operations.sql` 放到服务器一个确定的暂存路径，校验它来自将要发布的 Git 提交。使用服务器现有数据库管理员身份执行；脚本只选择 `theone_prod`，仅新增表及版本号，不修改其他项目数据库，不调整应用账号权限。不得把 MySQL 密码粘贴到终端命令或对话中。
3. 在准备发布的版本目录运行下列只读预检。该脚本读取 ONE 的受保护配置，但不输出凭证；只检查 ONE 的结构版本、应用账号是否可读新表及待处理数量，**不会自动执行 DDL 或修改业务记录**。

```bash
node deploy/check-mysql-schema.mjs --env /srv/theone/shared/.env
```

应用迁移的示例（将完整路径替换为刚刚校验的真实暂存文件；`sudo mysql` 仅适用于本机已配置的管理员 socket 登录，不是要求开放无密码远程登录）：

```bash
sudo mysql --database=theone_prod < /完整暂存路径/002-chat-operations.sql
```

4. 预检若发现正在处理的消息或模型调用，应保留当前服务、等待用户任务完成后再检查。若数量长期不变，先核对请求和上游用量，不得手工删除记录或把状态批量改为成功。预检只是当时的快照，不能代替维护窗口内停止新请求的操作约定。
5. `needs_review` 是已有待核对账目，不表示正在执行；发布前后都应在超管用户用量明细里逐项处理。服务重启时未完成的消息标记为 `interrupted`，同一提交不得自动重新检索或调用模型；未决模型用量继续保留待核对预占。
6. 发布后测试“后端已完成、浏览器没有收到响应，再用原提交标识查询/重试”：应返回原答案，模型用量和扣款只有一份。两个标签页同时向同一对话提交不同消息时，后一条应明确提示等待。

回滚约定：旧代码回滚时**保留 `chat_operations` 新表和版本记录，不 DROP、不恢复旧备份覆盖现有业务数据**。旧代码不识别新表，不具备此次请求去重能力；回滚期间暂停内测发送，不能承诺重试仍安全。再次启用新版前，核对回滚窗口内的消息、未决提交与用量。生产仍是单进程，当前去重不支持直接扩为多个应用实例。

## 每位内测者验收

- [ ] 首次双击对应图标，进入自己的账号，能发起一次真实问答。
- [ ] 连接自己的知识来源；另一台 Mac/Windows 使用同一账号 Key 不需重新授权。
- [ ] 拔 Key 后分别尝试新消息、读历史、上传/下载附件、知识召回和管理 API：必须拒绝。
- [ ] 插回 Key、不刷新重试；休眠后唤醒重试。Windows 必须实机验证，不能以跨平台构建成功替代。
- [ ] 将同一枚 Key 从 A 电脑移至 B，A 的旧页面仍拒绝新请求；移回 A 后恢复。确认拒绝时没有新增知识/模型调用和电力预占。
- [ ] A 的 Key 不能读取 B 的对话/附件/用量/连接；普通 Key 不能打开超管 API。
- [ ] 低余额同时发出两个请求，不能透支或重复扣费。上游缺失 usage/失败时符合上述规则。
- [ ] 超管能按人查看使用时间、模型用途、耗时和电力；不用进入任何人的私人会话。

## 最小运维与已知限制

- 总览检查数据库连通、磁盘可用空间、本地备份和异地上传的最近成功标记。新代码部署后，手动执行一次 `sudo systemctl start theone-db-backup.service`，确认成功后刷新页面；没有新版标记显示“未验证”，不会误报健康。
- 超过 36 小时未成功备份会在总览提示，但没有主动告警通知。COS 上传成功不等于恢复成功，需在独立临时数据库做恢复演练，禁止覆盖生产库。
- 当前 MySQL 实现仍将状态载入一个服务进程，串行事务写入；未来多进程扩容前要改数据库原子扣款与锁，不可简单横向加进程。
- Windows Authenticode 是程序发行签名，不是 Claude Code/API 接入。代码签名、公证、完整本地命令沙箱加固属于扩大内测前的后续事项。

## 附件：本轮已补会话连续性，存储位置不变

原文件仍保存在服务器私有目录，解析文本随附件记录持久化。本轮补齐同一用户、同一 Workspace、同一会话的历史附件追问，以及重启后的附件展示恢复。默认每次上传最多 4 个文件、每个 10 MB；模型上下文按当前上传优先、较新历史附件随后，最多 10 个文件/4 张图片，文本预算 24,000 字符。遗漏或截断会提示，不承诺整份大文档进入模型，扫描 PDF/复杂表格不等同专业识别系统。

将来的大文档按需检索、附件迁至私有 COS、完整附件/密钥备份单独规划；这与现有数据库 COS 备份不是同一功能。本轮不把附件自动加入长期知识库，不增加新 Local Agent/Codex 功能。
