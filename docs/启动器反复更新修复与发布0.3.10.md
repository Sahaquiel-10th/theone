# 启动器反复更新修复与发布 0.3.10

日期：2026-09-23

## 根因与发布事实

- 客户反馈 Mac 0.3.8 → 0.3.9 安装后仍提示更新，和此前超管盘现象相同；没有客户机器的进程/文件证据，不能确定所有客户都已成功写盘。
- 排查时生产 stable.json 仍是 0.3.9（2026-09-22 01:11 UTC 制品）。网站提交 407ced2 已部署，但其中 Mac 源码修复不在该二进制包内。
- 旧 Mac 在安装成功后必须先成功发送 completed 才会启动新版；完成上报失败会留在旧驻留。网页显示运行版而非盘内版本，因此提示可以是真实的“旧进程仍在运行”，不是缓存。
- 过去更新进度仅在 WebSocket 内存状态中保存。重连/服务重启后会丢失，重复安装防护也随之消失。

## 本次范围

1. Mac 0.3.10：安装提交与完成上报分离；上报失败仍返回已验证的新程序，完成上报限制等待时间。新旧交接前取消旧监测/登录任务，交接期间不因唤醒事件重开旧连接。
2. 服务端：更新指令发送前、各阶段进度写入现有数据库审计表，不新增数据库；记录 workspace、用户、Key、电脑 installationId、平台、目标版本和请求 ID。无凭证内容。
3. 重连后恢复精确所属的进度。状态不确定不自动重发安装。完成事件不能假定新版已运行；仍以新连接报告的版本为准。旧历史日志没有电脑/平台字段，不猜测归属。
4. 网页：区分重复下载与恢复启动；不再建议用户仅双击即可替换被单实例锁占用的旧驻留。
5. Windows 0.3.10 没有更改原安装逻辑，沿用释放锁后启动新版流程；与 Mac 同版本打包供统一发布。

## 已卡住客户的恢复

先停止重复更新。确认安装程序、文件替换和磁盘检查均已结束后，重启电脑，再从 U 盘打开 ONE。若盘内已为 0.3.9，运行版本会随之变成 0.3.9；不修改凭证、不重灌。若仍显示旧版，需核对实际盘内版本和安装错误，不继续盲目重复。未知状态不能自动判断失败或成功，必须人工检查。

新包无法回溯改变已运行的旧安装器。0.3.8 → 新版的首次交接仍可能需要上述一次恢复；不能承诺上传 0.3.10 后所有旧进程自动痊愈。

## 发布

网站代码通过现有 GitHub Actions 部署。签名更新包单独发布，不覆盖 0.3.9 同名制品。

本地完整包：`output/theone-runtime-0.3.10.tar.gz`；内含 `one-runtime-0.3.10/stable.json` 和两平台制品，不含身份凭证或发布私钥。上传服务器 `/tmp` 后：

```bash
tar -tzf /tmp/theone-runtime-0.3.10.tar.gz
sudo mkdir -p /tmp/theone-runtime-0.3.10-release
sudo tar -xzf /tmp/theone-runtime-0.3.10.tar.gz -C /tmp/theone-runtime-0.3.10-release
sudo bash /srv/theone/current/deploy/install-runtime-update.sh /tmp/theone-runtime-0.3.10-release/one-runtime-0.3.10
sudo -u theone node /srv/theone/current/scripts/verify-runtime-update.mjs --manifest /srv/theone/shared/runtime-updates/stable.json --public-key /srv/theone/current/config/runtime-update-public-key.txt
```

没有服务器发布成功与公共清单校验，不称为启动器已上线。不通过受限源码部署 SSH 绕过更新发布流程。

## 验收边界

### 2026-09-23 重启后现场补充

本机重启后 TESTONLYONE 已运行 0.3.10；网页实际登录超管账号，其 ESD-USB 仍运行 0.3.9，盘内已是 0.3.10。浏览器直接读取当前账号更新状态，返回 current=0.3.9、target=0.3.10、installing/recoveryRequired；不是把另一枚 Key 的新版本用来判断此账号。确认无安装子进程、盘内签名通过后，仅结束 ESD-USB 旧驻留并重新打开，确认两个进程都运行 0.3.10，超管网页更新提示消失。未修改凭证或重灌。

网页“检查状态”原本只有 GET 查询，无重启能力；相同结果无视觉反馈，且恢复说明被单行省略。补充手动查询中/完成时间/失败反馈、当前账号与运行/目标版本，恢复文字允许换行。手动检查仍不下发安装，不修改服务器在场权限。此现场恢复不等于已验证未来版本全自动交接。

- 自动测试覆盖：持久进度恢复、跨租户/用户/Key/电脑/平台隔离、旧连接重连不重复下发、完成后迟到失败不回退、新版连接清除旧任务影响、原 Key 即时签名与拔出拦截测试。
- Swift 独立可执行测试覆盖真实调用安装交接函数：安装成功但上报异常仍交接；安装失败不报告成功；正常路径。两平台构建、Mac Universal/签名与制品哈希检查。
- Mac 构建 SDK 更新后使用 CommandLineTools 当前 SDK，不写死 15.4。桌面目录可能被附加 FinderInfo；仅将构建产物复制到本机临时目录清理元数据、验签后打包，不修改用户 U 盘。
- 仍需真机端到端：安装后新进程版本、网页提醒消失、拔盘请求拦截、重插自动恢复、休眠恢复。自动测试和编译不能代替客户实测。
- 未知更新记录目前需维护人员核实恢复，不开放“强制重试”按钮；避免在文件替换不确定时重叠安装。
