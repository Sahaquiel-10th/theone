# 在线更新自动交接流程与验收 0.3.11

## 产品验收标准

用户点击一次更新后：下载 → 验签 → 原凭证校验 → 备份及替换 → 新驻留自动接管 → 服务端确认新版本 → 原网页自动结束提醒。最多允许用户刷新一次；拔插、结束进程、重启电脑不能算通过。更新后拔盘必须阻止新业务请求，重新插入仍自动恢复。不得修改凭证。

## 本次证据和限制

用户反馈 Windows 0.3.8 → 0.3.10，网页显示断线，插拔后恢复。没有客户系统日志，不能凭截图确定是下载失败、重启竞态还是旧连接超时；不能只凭消失的提醒声称已升级。已确认两平台旧实现将安装置于收包循环，Windows 还存在更新进度写 socket 没有期限的问题。Mac 已有丢失完成上报阻断交接的历史证据。

## 实现

- Windows 安装在独立任务执行，原 WebSocket 循环持续处理 ping 和请求签名；socket 写入限制 3 秒。任何收包/签名错误退出前都等待安装任务的最终结果；若文件已安装，仍启动新版，不让连接错误吞掉交接目标。
- Mac 安装放入独立任务；收包循环继续签名。断线后等待安装结束才重连/交接。任务进行时不因系统挂载、网络和唤醒事件启动第二个安装/连接循环；拔出仍关闭 socket，签名仍每次直接读 Key。进度上报限时，失败不影响已验证文件交接；下载有总时限。
- 两平台由新版执行后续更新时传递 update-resume，后台恢复原网页连接，不再依赖自动打开新的登录标签。Windows 显式传递原 Key 的路径和设备 ID，避免更新重启扫描到另一枚 Key。首次从旧版升级仍可能走旧登录路径。
- 服务端完成事件后的短交接窗口保留传输，不把它当作新请求的签名成功。
- GET 更新状态在短暂无连接时，可读取最近 30 分钟、精确 workspace/账号/Key/电脑绑定的更新日志，明确返回 reconnecting。它不是在线证明，不开放聊天、知识、附件、账单、管理或 POST 安装。过期及归属不符仍拒绝。
- 网页持续检查新版连接；短交接不提示用户反复插拔。超过 90 秒明确说明未恢复，提供刷新页面入口，不无限宣称即将成功，不自动重新安装。旧日志没有新元数据时不能猜测平台。

## 验证

- Go install job 单元测试支持在 Mac 执行；Windows 专属集成测试使用真正 WebSocket 与真实收包循环，只替换文件安装：安装暂停时挑战可签名；断线不能提前结束安装；提交的新版目标最终返回。加入 Windows CI 并设为部署前置检查。它没有覆盖真实 U 盘、SmartScreen 和 Windows 进程启动，不能代替真机验收。
- Swift 测试覆盖任务互斥、安装成功但上报失败仍交接、失败不返回成功。Mac Universal 编译和签名验证。
- 服务端测试覆盖交接元数据可读而业务拒绝、跨用户/工作区/设备/电脑隔离、失效窗口和新版恢复。
- 最终仍需 Mac 与 Windows 实盘按上文流程验收，并观察实际驻留版本与提醒，不以模拟测试代替。

## 发布规则

网站修复单独部署；0.3.11 双平台签名包单独上传服务器。不覆盖已发布的 0.3.10。没有公共清单验签与两平台制品下载核对，不算包上线。

旧 0.3.8/0.3.9/0.3.10 已运行的安装器无法被网站或未执行的新包回溯修改；服务器兼容处理可以减少中断，但不能承诺所有旧版本一次跨越必然自动完成。若旧版卡住，记录为迁移未通过，不能要求客户反复更新并声称修复成功。本次不更改灌装基线文档为“验收通过”，也不覆盖用户 U 盘。
