# 分身工作台生命周期与草稿恢复 · 2026-10-27

## 起因与范围

用户在实际工作台发现：关闭分享后难以继续编辑、重新开放或删除；创建和试聊也需要避免刷新、误关或失去回执后丢失上下文。本轮在现有分身列表 → 单个分身配置 → 明确分享的结构上补齐状态流转，不重新设计收费，不改生产价格、用户余额或已有服务资格。

本轮前后端已完成实现及本地验收；生产发布与线上确认分开补录。不得把本地夹具、自动测试或构建成功当作线上真实用户验收。

## 生命周期决策

| 当前记录 | 保存配置 | 开放分享 | 删除／恢复 |
| --- | --- | --- | --- |
| 未分享 `draft` | 保存后仍未分享 | 单独确认后开放 | 可移入回收站，恢复后仍未分享 |
| 已开放 `active` | 更新同一链接，旧会话不带入新版 | 已开放，不重复创建 | 关闭不受在途问题或已有服务资格阻拦；删除另检查在途问题和客户承诺 |
| 分享已关闭 `closed` | 允许编辑；保存仍关闭 | 明确重开，同一分身生成新链接 | 可恢复删除；恢复后仍关闭 |
| 回收站 `deletedAt` | 先恢复，不在回收站编辑 | 禁止直接开放 | 不物理删除；恢复不自动公开 |

关闭分享是隐私退出，不能要求作者先取消客户权益。关闭、删除、重开均保留原分身身份、已有用量及实际账单；关闭／删除撤销原 API 授权，重开不复活旧链接、会话或令牌。客户服务码及已兑换资格并不因此撤销、退款或延期；原有效期照常经过。

删除不能当作取消订单或取消服务：有运行中访客时明确拒绝；有有效未兑换服务码或已发行服务资格时也明确拒绝，作者仍可立即关闭分享。如需撤销资格，应走既有的明确服务管理操作，不静默删除承诺。

## 实现范围

### 后端已实现

- 关闭记录可回读与保存配置；`update` 返回真实 `status`，不会因保存表单而公开。
- 显式 `publish` 支持未分享和关闭记录；关闭记录重开旋转 `slug`、增加版本，现有来源绑定、模型、功能与服务承诺校验继续生效。
- 旧混合提示词没有独立作者字段时，直接重开明确拒绝，要求先编辑填写自己的回答要求并保存；不猜拆模型系统提示词，不以空字符串静默覆盖旧方法。
- 增加 `delete` / `restore`，管理列表默认不显示删除记录；`trash=1` 列出本人回收站，支持名称和介绍搜索，返回独立 `trashTotal`。
- 关闭、删除、恢复和开放均要求 `version + confirmed:true`，最近一次原版本请求可核对落盘回执，不重复转换或增加审计；新修改发生后旧操作不能覆盖新状态。
- 使用现有存储增加可选 `deletedAt`，无物理清理、无历史账单改写；回收站中仍可读取本人的无正文用量明细。
- 配置历史沿用最多 20 份，历史快照不复制客户信息、服务码及资格清单；实际清单留在原分身记录，不通过公共或管理员接口增加正文可见范围。

### 前端已集成

- 关闭记录保留显眼编辑、重新开放入口；删除和关闭区分，删除有确认及可恢复说明。
- 增加独立回收站切换、恢复入口；恢复后不显示为已分享。
- 编辑新分身、已有分身和试聊时继续区分当前作者、Workspace、分身及配置版本；草稿恢复不得恢复分享同意或费用确认。
- 刷新、误关和未收回执场景需要在真实组件中逐一验收；配置本页暂存不等同服务端已保存，也不把私有试聊正文缓存到公共配置或一般管理日志。
- 保留现有分裂面板与唯一主列表滚动面，不以卡片内部嵌套滚动代替列表滚动。
- 提示词使用直白名称，补充回答要求折叠保留；顶部常驻原生表单保存按钮。私有保存不要求额外勾选，公开更新与开放仍单独确认范围和费用。
- 本页 sessionStorage 只保存作者填写的配置，按账号／工作区／分身／基础版本隔离；不存调试回答、检索结果或凭证。刷新可恢复，关闭标签页后不承诺保留，最长七天。
- 保存发出前单独暂存“结果待核对”标记，成功或确定拒绝才清；断网刷新后仍锁住重复提交，必须先核对列表。不声称新建分身 POST 已实现服务端 operationId 幂等。
- 配置版本冲突保留旧草稿，不覆盖新版，可另存新分身；完全撤回修改会同时清理对应暂存，防止旧修改复活。
- 访客式调试复用公开页身份、欢迎语、引导问题和消息呈现；顶部弱提示作者电力，无必选费用框。试聊仍限问答及所选知识，不伪装成工具／附件／收费服务的完整实测。
