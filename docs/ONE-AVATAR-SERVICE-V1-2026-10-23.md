# 分身服务化改造 V1

## 目标与本轮边界

让咨询师、讲师把方法、知识和 ONE 已有功能组合成可分享的服务：可以接售前咨询，也可以交付知识服务。用户 2026-10-23 确认先落计划、再实施。

- 老师配置名称、回答方式、方法资料、模型、开场问题和允许调用的功能，以及各功能的使用条件和工作流程。
- 复用已审核、已发布的 ONE 功能及其工具，不复制一套“分身专用计算器”；运行中重新核对版本、授权、额度。
- 基础配置由老师自行完成；代搭使用相同配置，不增加管理员读取私人会话的权限。广告、私有功能可见策略后续处理。
- 作者名字由服务端账号资料取得，与可自由命名的分身区分。
- 第一版增加有期限、有额度的服务资格和兑换路径，为老师自行收款后的交付提供入口。套餐权益与 ONE 全局会员、电力、现金收入分别记账。
- 不改变现有生产价格、余额、商业化开关；不虚构官方原价或折扣。零售价格、服务额度、有效期与费用承担要明确。
- 平台代收、微信商户入驻、真实分账、提现、自动续费需要另行取得支付产品权限，本轮不伪装为已开通。

## 实施顺序

1. 保留当前发布版本和前端备份，在隔离工作副本改造；旧分身不自动新增工具或付费限制。
2. 增加服务配置及基础界面：售前/知识服务、方法资料、开场问题、作者身份、功能选择和调用条件。
3. 接入可公开交付的已有功能：优先计算、表格和私有网页/文档类；不开放本机、任意网络、外部写入、发布或凭证访问。功能说明不授予额外权限。
4. 增加服务方案与限额兑换：30 天含额度、额度包、赠送资格；兑换幂等、精确绑定分身和访客，不把手工发放冒充真实支付。运行前及每次结算前都核对权益和预算。
5. 售前表单与联系请求由访客明确提交，教师仅看到已同意发送的资料；不默认展示原始对话和附件。
6. 持久回执、进度、私有成果取回、出错后的下一步与重复请求保护一起验收；工具失败时保留已产生的成果，不静默消失。
7. 相关单元/HTTP 集成与跨空间、跨访客测试，全量测试、类型检查、生产构建、差异检查后提交发布，再检查线上版本和健康状态。

## 技术约束

- 所有新记录带 workspaceId，发布者身份取自认证会话；访客只访问自己的会话、成果和权益。
- 教师的功能选择绑定已批准发布版本；修改/下架后不能悄悄运行另一版本。
- 重用真实工具实现和模型网关计费；纯计算/导出不额外套模型。模型与工具的所有实际费用归属本次公开任务，不重复结算。
- 成果保存在私有附件目录，不在 URL 放令牌、路径或密钥；下载由访客会话认证。
- 新业务数据使用现有持久记录的可选字段，旧数据默认兼容；不重写历史账单或已共享迁移。
- 关闭、过期、撤销、并发耗尽均重新核对；无法确认的执行不自动重跑。

## 界面工作约定

采用 interface-design 与 ux-copy 指南，沿用 ONE 的纸白底、灰绿边线、墨色主按钮和安静排版。领域词汇：老师、方法、试聊、服务资格、交付。色彩来源：纸白、墨黑、鼠尾草、暖灰、浅苔绿。特征是“作者身份 + 服务内容 + 可点的开场问题”，不是通用 SaaS 数据卡。

拒绝默认彩色仪表盘、堆满技术参数、把未开通收款做成可购买按钮。配置按“对外介绍 / 方法与功能 / 访问与费用”分组，主要操作唯一，错误提供下一步。公开页优先手机阅读，兼顾桌面；不重做主工作台。
