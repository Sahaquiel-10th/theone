# 文本分析与材料补充可靠性修复

日期：2026-11-04。实施前计划；基线 `4a2c8f4`。在独立工作树实施，保留主工作目录的全部未提交修改。

## 已核实的问题

生产仅查账号、长度、附件状态、调用和步骤元数据，没有读取用户剧本或聊天正文。

- 15:27–15:44 的旧任务三轮复用相同交接、原消息和两份附件；两次模型请求约 150 秒超时，一次未解析到可用响应。
- 两条 1,666 字的新补充在主调度读取旧任务后，输出各达到 3,000 tokens 并截断，没有新的派发或晚到子任务。
- 旧任务没有 workflow，使用携带 27 个工具的通用循环；模型请求未提供的 `Bash`，参数纠正后再超时。
- 两份附件已解析成功；当前整份分析可能只做相关片段召回，全文预处理也没有逐批断点。
- 主对话有 8,000 字符提交上限，超限提示、草稿恢复和拒绝留痕不一致；不能从现有元数据还原约一万字那笔提交。

## 目标与不变条件

用户交付目标决定步骤：纯正文分析/创作默认一个无工具模型步骤，文件、已选功能、知识检索、保存等仍由明确步骤负责。不按“剧本”等行业词硬编码。

原始消息由服务端按 workspace/user/task/message 精确绑定，调度只生成短交接，不复制整份材料。最新补充真正进入新的执行输入；重试旧任务不得假装已合并尚未交接的新材料。

保留现有 Key、空间权限、模型配置、额度及取消检查。任何重试都受原预算约束；未知上游用量按最坏预留计入内部重试上限，不修改钱包、生产价格或用户授权。不得重放外部写入、功能或本机操作。

## 实施步骤

1. **统一输入规则。** 主对话和任务补充支持 32,000 个 JS 字符；超过时明确反馈并完整保留草稿、附件，不进入回执未知。服务端专用分类及安全长度事件；8,000 的历史分页保持原大小。
2. **缩短且保真地交接。** 保留当前原消息的精确引用及完整正文；大段原文不重复塞入 instruction/workflow。只在没有已派发任务且本轮截断指令尚未执行的范围，允许一次受原步骤/纠正/预算限制的短参数修复；不能执行截断 JSON。
3. **纯正文使用标准模型工作流。** 无已选功能、无外部交付或必需工具的任务走标准 model 节点，tools 为空，结果直接交付；模型不能借通用循环请求 Bash 或额外结尾总结。
4. **长材料完整覆盖与断点。** 整份分析明确使用完整覆盖模式，逐批处理所有段，区分完整原文、全段摘要、检索片段。每批及归并输出存私有、同任务、内容/目标/配置绑定的完成断点。失败后不重复购买已完成批次，不把摘要称为逐字原文。
5. **有限纯模型恢复。** 对已分类的暂时服务错误/无可用响应，最多再试一次；保留持久尝试次数和未知成本上界，重新核对 Key/取消/授权/预算。不自动重试授权错误、过滤、输出截断或外部操作。可读部分完整保留并标明部分成果。

## 验收标准

- 8,000/8,001、32,000/32,001 边界一致；中文/emoji 一致；超限零模型、零 worker、零扣费，草稿/附件不丢且不查虚构回执。
- 一万字粘贴的首中尾标记逐字进入实际模型输入，而非只有 4,000 字交接。千字新补充绑定新消息；旧附件选择明确；跨用户、跨空间和改动来源均不误用。
- 读旧任务后截断派发指令：一次短参数恢复可以产生恰好一个 worker；已派发、取消、预算不足、身份失效时不重复派发。
- 合同、论文、剧本等任意纯文本任务默认一个 model 节点，实际 tools=[]，不调用 Bash/feature，也没有模型为最终通知再总结一轮。
- 双文档至少五万字，首、中、尾及第二文件标记全段覆盖；第 2 批故障恢复不重买第 1 批；修改文件/目标/配置不能复用旧摘要。
- 150 秒超时和空响应以可注入故障验证：总调用有界，未知成本计入本轮预算，401/过滤/截断不自动重买；并发唤醒不能越过尝试上限。
- Notion 原页保护、已选功能、本机、图片、知识来源与显式多步依赖回归不变。
- TypeScript、相关单元/集成与隔离测试、完整测试、production build、diff check 均通过后提交推送；核对 CI、线上 revision/静态资源/健康；另做新合成材料闭环，不重跑原客户任务。
