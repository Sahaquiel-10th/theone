## 目标与不变条件

用户交付目标决定步骤：纯正文分析/创作默认一个无工具模型步骤，文件、已选功能、知识检索、保存等仍由明确步骤负责。不按“剧本”等行业词硬编码。

原始消息由服务端按 workspace/user/task/message 精确绑定，调度只生成短交接，不复制整份材料。最新补充真正进入新的执行输入；重试旧任务不得假装已合并尚未交接的新材料。

保留现有 Key、空间权限、模型配置、额度及取消检查。任何重试都受原预算约束；未知上游用量按最坏预留计入内部重试上限，不修改钱包、生产价格或用户授权。不得重放外部写入、功能或本机操作。

## 实施步骤

1. **统一输入规则。** 主对话和任务补充支持 32,000 个 JS 字符；超过时明确反馈并完整保留草稿、附件，不进入回执未知。服务端专用分类及安全长度事件；8,000 的历史分页保持原大小。
2. **缩短且保真地交接。** 保留当前原消息的精确引用及完整正文；大段原文不重复塞入 instruction/workflow。只在没有已派发任务且本轮截断指令尚未执行的范围，允许一次受原步骤/纠正/预算限制的短参数修复；不能执行截断 JSON。
3. **纯正文使用标准模型工作流。** 无已选功能、无外部交付或必需工具的任务走标准 model 节点，tools 为空，结果直接交付；模型不能借通用循环请求 Bash 或额外结尾总结。
4. **长材料完整覆盖与断点。** 整份分析明确使用完整覆盖模式，逐批处理所有段，区分完整原文、全段摘要、检索片段。每批及归并输出存私有、同任务、内容/目标/配置绑定的完成断点。失败后不重复购买已完成批次，不把摘要称为逐字原文。
5. **有限纯模型恢复。** 对已分类的暂时服务错误/无可用响应，最多再试一次；保留持久尝试次数和未知成本上界，重新核对 Key/取消/授权/预算。不自动重试授权错误、过滤、输出截断或外部操作。可读部分完整保留并标明部分成果。

## 使用边界

- 32,000 是单条提交的 JS 字符上限，不是对所有模型上下文容量的承诺；超限保留草稿，改用附件。
- 整份材料模式最多覆盖 720,000 个已解析字符；较长输入可通过所有分段的摘要进入最终模型，不称为最终模型逐字持有全文。扫描文字、内嵌图片与版式仍取决于附件解析能力。
- 自动重试最多一次，仅适用于受原预算限制的纯模型或摘要暂时错误。授权错误、过滤、截断、未知外部结果与写入操作不自动重放。

## 真实模型验收发现的入口差异与补修

首版 `5bef581` 已通过 CI 并上线。新合成隔离服务验收中，一万字原文的首、中、尾核对码全部正确；随后在同一任务内提交 1,666 字替换材料，模型完成了回复，但新核对码未通过，不能计为验收成功。

只读核对合成入参发现：最新原文确实进入了 goal，旧一万字却又以 `selected_material`、`complete=true` 进入参考区。主对话已有调度选择材料范围，任务内 direct 入口仍跳过这项决策、继承旧材料。两条入口的语义不一致，且原合成模型只检查新码存在，未检查旧正文消失，掩盖了这个边界。

补修采用同一套调度决策：已有当前材料的云端任务收到新材料时，任务内入口也先做材料范围选择，再进入统一绑定器；字数与材料块仅触发需要决策，不自动判定替换。普通简短追问保留直接执行的快路径。状态询问、固定恢复、本机及未知写入保护继续优先处理；同提交重放不得切换为另一种 payload。父调度与子执行的回执必须通过准确提交编号关联，不能按编号前缀猜测。

补修验收增加：实际模型输入的新首、中、尾各出现一次，旧正文、旧附件、旧摘要和旧助手正文不得回流；短追问仍能引用已选材料；追加与替换由同一语义决策区分。隔离验收的路由及 Key 为合成 fixture，真实调用仅证明模型及服务工作流链，不冒充客户浏览器或真机验收。测试不会写入生产客户记录或改变余额。

补修离线检查：全量 2,926 项，其中 2,925 通过、0 失败、1 项既有跳过；任务服务 335 项、材料决策/追加/简短追问 10 项、前端回执相关 32 项均通过。新增路由和 worker 合计沿用原预算，回执超时会先只读核对准确提交编号，仍未知时保留原编号及草稿，不重复 POST。
